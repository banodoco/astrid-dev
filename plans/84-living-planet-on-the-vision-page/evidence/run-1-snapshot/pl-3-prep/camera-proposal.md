## Gesture and cleanup

Canvas remains the actual hit target in exposed world areas, with `touch-action: pan-y`; the sticky nav, copy, section links and all controls remain above it. Do not use a full-page overlay that swallows links, or `touch-action:none`. Vertical touch must be allowed to become browser scrolling, not translated into pitch; decide axis after a small movement threshold (e.g. 8 CSS px) with horizontal dominance, and apply yaw only after horizontal intent. For mouse retain useful drag/tap behavior. Avoid tap on any movement classified as scroll or drag. Compare start/end scrollY on both phone orientations using real touch input, not synthetic wheel.

Track each active pointer and captured pointer explicitly. On second touch, cancel the active gesture, release any capture, clear inertia and suppress tap until all touches end. `pointercancel`, `lostpointercapture`, visibility/unmount and context loss must all clear the primary pointer, drag state, pending tap and captures, never call `handleWorldTap`. `pointerup` is the only normal tap path when the same primary pointer ended without cancellation/multitouch and under the threshold. Handle a release exception if capture was already lost. Remove added listeners and disconnect observer at dispose. Existing donor behavior has `pointercancel` routed through `onPointerUp`, so a canceled short touch can currently fire a tap, and a second touch clears the primary before releasing its capture.

PL-10 needs actual rotation/time to remain one owner. Do not implement sky/session wiring or introduce another time clock here. If PL-10 needs a new callback, expose only an explicit user-driven horizontal rotation delta (including consistent sign/units) and do not emit it for programmatic orientation changes; coordinate with PL-10 after its prep, rather than guessing an unreviewed time mapping.
