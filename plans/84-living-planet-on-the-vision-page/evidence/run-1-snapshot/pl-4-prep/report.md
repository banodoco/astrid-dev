## Current seams

- `src/pages/Home/planet/PublicAstridPlanet.tsx:12-45` imports `planet-still.png`, lazy-loads `planetEngine`, and renders either a canvas (`live`) or an image (still). In live mode there is no poster layer while the import/renderer/first draw is pending. The engine `onReady` callback is currently a no-op. A rejected import logs to console and leaves a blank canvas; an `initPlanetEngine` return of `null` is not handled and also leaves the canvas blank.
- `src/pages/Home/PublicAstridVision.tsx:531` passes `live={visible && !reducedMotion}`. Reduced motion already selects the still image without importing the engine. The site updates reduced-motion state when the media preference changes; preserve that behavior and ensure toggling to reduced motion disposes live work promptly.
- `src/pages/Home/planet/planetEngine.ts:6726-6736` catches WebGL renderer construction failure and returns `null`. At `8429-8446`, `webglcontextlost` stops RAF/timers and releases sync handles; the engine has no callback to notify React, so the component cannot reveal the poster. Restoration restarts rendering, but does not signal a new ready frame: the one-shot `onReady` fired at `8933-8936`. The engine API has `setPaused` (`9043-9045`) and `dispose` (`9057+`), but no poster/context lifecycle API. A narrow callback pair for loss and a successfully redrawn restoration (or equivalent explicit engine status) gives the wrapper a reliable switch. Keep the lost-context listener alive while showing the poster if restoration should be recoverable.
- The card requires the poster during initial live loading. That overrides the concept note's initial suggestion to leave only sky visible until the live planet appears. Render the poster from the initial stage state and keep it visible until the engine has drawn its first frame; on engine/import/WebGL failure, retain it. Since the image itself is an asset request, ensure it is eager/preloaded and prove it on a throttled cold page so “poster before ready” cannot become “blank until the PNG arrives.”
- The existing asset `src/pages/Home/planet/planet-still.png` is RGBA 520×800 (aspect 0.65), captured at 2× a 260×400 stage. Current `.astrid-vision-juggler` at `PublicAstridVision.css:66-76` is 65×100 art pixels, same aspect; image and canvas fill that shared box. The generic `.astrid-vision-juggler img` rule at line 78 applies `image-rendering: pixelated` to the poster. Give the poster a dedicated rendering rule so scaling does not inherit the old pixel-art interpolation. Preserve the stage box while swapping layers; positioning and opacity changes must not affect layout or the hero's measured geometry.
- PL-2/PL-3 will change the stage's location, dimensions and camera framing. Keep one poster source, aligned by the same stage box, with non-distorting sizing and an intentional responsive crop/position if needed. Do not independently position the poster or rely on the current PL-1 camera: regenerate the fixed-pose poster after PL-3, PL-10 and PL-6 establish the resting pose. One neutral-light poster cannot claim to display the sky's exact hour; the manager's current ruling is neutral lighting. Assess softness at wide sizes too: the current 520×800 raster is 2× only for its capture size.
- The existing stage has `aria-hidden="true"` at component line 42, so both canvas and poster are decorative for assistive technology. Keep it hidden and provide a concise textual description elsewhere in page reading order, as the PL-4 card requires. Place controls outside that hidden wrapper.

## Fallback behavior map

| Case | Current behavior | PL-4 target seam |
| --- | --- | --- |
| Initial live load / before first drawn frame | Canvas only; can appear blank while dynamic import and engine setup run. | Show the eager poster in the reserved stage immediately; reveal live output only after the readiness signal/entrance begins. No stage resize. |
| Reduced motion | `live=false`, poster image only, no engine import. | Preserve: still image, no live engine or entrance. Check preference changes while mounted. |
| WebGL unavailable / renderer construction throws | Engine returns `null`; component ignores it, canvas remains blank. | Treat `null` as unavailable and retain/show poster; no unhandled error or repeated load loop. |
| Engine chunk import rejects | Catch logs error; blank canvas remains. | Keep/show poster, optionally retain a diagnostic log, no user-facing failure alert for a decorative feature. |
| WebGL context lost | Renderer loop and pending work stop; canvas may clear; React is not notified. | Signal loss so poster covers the canvas immediately. If restoration succeeds, signal after an actual restored draw before fading poster away; if it does not restore, poster remains. |

## Controls and keyboard/accessibility

- Existing engine `setPaused(boolean)` is a direct route for a Pause/Resume control. It stops scene time updates while retaining the current live frame; note it does not stop the renderer scheduling, so it is a motion control rather than a quality/performance stop.
- “Still” could instead switch to the poster, but the current component unmounts/disposes a live engine when `live` becomes false; returning live rebuilds the scene. Preserve that cost and behavior in the manager's controls decision. The manager has ruled out adding “Inspect World” in this early work and will decide the final minimal controls after layout.
- Use native buttons in a labeled controls group, outside the `aria-hidden` stage. They should be reachable by Tab, activate with Enter/Space, expose current/action state (for a toggle, consistent accessible label plus `aria-pressed`), and have a visible focus treatment. Keep controls out of the canvas hit area or ensure their pointer actions do not start a planet drag. Avoid a global keyboard shortcut; it could intercept page navigation and modal/card controls.
- When controls are not present in reduced-motion or fallback states, keep the stage's description available. Do not use live-region chatter for each animation frame; only announce explicit control state changes if the button name/state alone is insufficient.
