## Cause and repair

Two previously failing PL-2 verification traces show (a) populated Vision content while the page-transition marker remained for a five-second overflow poll, and (b) a cold Vision title missing at the five-second assertion but present in a later snapshot. Both feed requests returned 200; neither trace alone proves cause (`initial-analysis.md`).

An isolated candidate dev-server comparison with the same pinned feed and browser viewport found warm direct entry with the engine response disabled reached the title in 1.39 s, while live entry reached it in 6.45 s. The live engine constructor occupied 215 ms; the immediately following main-thread long task lasted 5.21 s and the first-frame callback occurred inside it. With navigation, a representative live run had 268 ms constructor work followed by a 4.41 s long task. Disabled navigation finished its transition in about 1.28 s. These results establish a first-frame software-rendering stall that can race content/transition readiness, not a native-device performance measurement. `probe-frame-rerun.log`, `probe-isolated.log`, `probe-frame-*.json`, and `probe-*-navigation.json` are raw evidence; scripts are alongside them.

Vision now passes content/error readiness to the planet. Page navigation exposes an explicit completion signal that releases on finish, rejection, invalidation, unmount, no API, or synchronous error, and follows replacement transitions. The component waits for readiness, settled navigation and cancelable paint opportunities before loading/initializing. It displays the still image until the first live frame and cancels pending waits, animation frames and imports or disposes an initialized engine on cleanup. No fixed time delay, changed assertion, new dependency or layout edit was made. Existing component test is unchanged; a separate test covers readiness, transition wait/replacement, frame/import/unmount cancellation, poster, cleanup and error cases. First-frame rendering still has a multi-second software-GL cost; PL-5 owns its mitigation. The complete fallback/entrance and controls remain PL-4.
