**Approach:** Extend the existing pack; no new pack and no new command. Three kinds of answer, chosen per need: a skill where the need is a choice; the smallest code where it is mechanics (the pack prepares its own source; the request takes handles; the missing-dependency message); deletion where it is neither. Considered and not chosen: a wrapper command that turns "this clip, this line" into a request (the request with a handle and a range is already that short; revisit only if the fresh-agent step stumbles on it); keeping LanPaint for sound regeneration (unvalidated, unreachable, and built on nodes the pack moved away from); rewriting everything onto request version 2 (larger, and version 1 is what the skill, the plain inputs and the dialogue handling use).

General Astrid capabilities this plan uses but does not own, with a recommendation for each:

## Owner decisions

- **D1 — Remove LanPaint.** Options: remove the helper, the packaged workflow and its tests; or keep it as a dormant candidate. Recommend remove. Cost stated plainly: it was the only graph that could regenerate sound inside existing footage, it never ran on a GPU, and nothing replaces that; new dialogue goes through continuation.
- **D2 — One request shape, and the working version 2 branches.** Settled by the critique's finding and recommended here: version 1 is the one documented shape for continue, change a region and generate; the character swap stays as a separately documented experimental version 2 request. Still to decide: the other version 2 branches work today and duplicate version 1. Options: (a) retire them in RH-3, so a version 2 request without the character swap is refused with its replacement named: version 2 image-reference generation becomes `operation: generate` with `references`; version 2 continuation becomes `operation: continue`; version 2 masked edit becomes `operation: edit` with a mask; (b) leave them working and undocumented, with an issue to retire them later. Recommend (a), after RH-1 gives version 1 the one thing version 2 did better (a source range anywhere in the file). It is an intended change to an experimental interface; no search can show that nobody outside sends version 2 requests.
- **D3 — Remove the `astrid h3` command.** Options: remove it so `astrid generate video --entry h3` is the one way in; or keep it and fix its hard-coded local placement. Recommend remove, with a short migration note: `--dry-run` replaces `plan`, a request file replaces `edit`.
- **D4 — Footage that is not 16:9.** When H3 prepares a source whose shape differs from 1024×576, options: fill the frame and crop the excess, or fit inside with bars. Recommend fill as the default, always stated in the request's dry-run output and overridable per request, and never a stretch. Fill matches the no-black-bars direction for the Matrix shots.
- **D5 — Where transcription and masks live.** Recommend as written under Approach: both are general Astrid capabilities provided under Plan 59 when its tasks reach them, with how they are built left to those tasks; the single transcript structure is its own later plan; none of them is inside the H3_AV pack or a dependency of this plan.
- **D6 — Release and review.** Recommend including this plan in Release 14 beside Plan 59, on `release/14/plan-60` branches, with one review stop after RH-1 and one review round at the end.
- **D7 — How a take is put on the timeline for review.** Options: (a) a stored alternate: the take added as its own clip above the shot with the existing add and trim commands, showing only its generated part at normal speed with the shot's temporary voiceover silent over it, the original untouched beneath, at a pinned revision; (b) a detached review draft using `--swap-asset`, which changes only the local copy until it is committed and is stated as such. Recommend (a); if an existing stored command cannot do one of those steps, that is a finding for Plan 59's blocker log and (b) is the fallback for that take.

Open until the GPU pilot, not yet a decision: whether 1.6 seconds of voice context is enough, and whether the long target line fits its 6.75 seconds. The graph's context is fixed at 39 frames today; a longer window would be a change to the graph, considered only after a measured failure.

Recorded as not supported, for a follow-up issue and not this plan: changing the words while keeping the exact picture. Continuation regenerates the picture after the cut point, the masked edit keeps the original sound, and removing LanPaint removes no working route for it.
