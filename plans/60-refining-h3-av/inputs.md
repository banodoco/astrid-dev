**Prior art:** Read at astrid-agent `ab95803ce` and VibeComfy `aee8bd825` (Release 14 heads); paths are in astrid-agent unless named.

- *Inputs are local files.* The request's assets resolve through an asset map of names to local paths (`shared/prepare.py:71-92`; file maps are staged as regular files in `astrid/core/generation/job_inputs.py:22-57`). Every other file input in Astrid accepts a media handle (`astrid/sdk/media_handles.py:1-22`): a digest, a reference, or an output of an earlier run.
- *LanPaint is unreachable.* `_compile_lanpaint` and its helpers remain (`shared/compile.py:27,183-243,382-433`) with a packaged workflow and two masks (`pack.yaml:82-91`), but nothing dispatches to them. Commit `772e57075` (28 October 2026) moved masked edits to H3's own nodes; the skill says LanPaint "is not on the active edit dispatch" (`docs/SKILL.md:219-223`); tests fail if a masked edit contains LanPaint nodes (`tests/helpers/h3_cpu_runtime.py:626-627`, `tests/packs/h3_av/test_native_masked_edit.py:64`). The native route changes picture only: sound is bound at zero regeneration (`shared/generation.py:349-418`). LanPaint was never run on a GPU (`guides/replacing-speech-in-existing-video.md`).
- *Declared but not there.* Version 2's `audio_only` branch always raises (`shared/compile.py:911-916`); `reference_audio_default` in `profiles/native-v2.yaml` is read by no code; version 2 accepts audio and video references that continuation then rejects (`shared/compile.py:930-939`); the skill links five stage pages under `actions/` that do not exist (`docs/SKILL.md:13-16`).
- *Two of the same thing.* Request version 1 and version 2 compile to the same graphs for continuation, masked edit and generation; only the character swap exists in version 2 alone. `astrid h3 plan|run|compose|edit` (`cli.py`) wraps the same entry and hard-codes local placement although H3 runs only on RunPod. `guides/` describes a "Seitanism extension workflow" as separate; it is the packaged continuation graph.
- *Continuation and voice.* One operation. The graph gives the model 39 frames (1.625 s) of picture and sound before the cut point (`workflows/native_h3_continuation/workflow.py:450-473`; `shared/timing.py:21`); version 1 appends the requested dialogue to the prompt (`shared/compile.py:163-173`), version 2 does not. No voice or video reference reaches continuation. The pinned graph needs at least 39 usable source frames and its context is fixed at 39; the timing code admits 90 or 141 (`shared/timing.py:45-53,99-110`), but changing timing alone would not change the graph, and nothing longer is built before a measured failure.
- *The entry can vanish.* When VibeComfy is not importable, contributed entries are silently dropped and the caller sees "unknown generation entry 'h3'" (`astrid/core/generation/entries.py:26-31`).
- *Sound inside existing footage is already possible with the pinned nodes.* H3's picture and sound are two streams with two masks, applied separately by the stock sampler (ComfyUI v0.36.0 `comfy/samplers.py:1297-1314`, `comfy/model_base.py:2234-2250`). The pinned node pack (ComfyUI-H3-Motion-Context-MultiRef `361624fb`) sets a separate sound mask over time (`MiniMaxH3SetAVNoiseMask`, `existing_video_extension.py:1131-1245`) and documents regenerating sound with the picture protected (`KEYFRAMES_AND_INSERTS.md:117`). The pack's masked edit uses that pack's node with `audio_strength=0` (`shared/generation.py:416`). LanPaint's own contribution is an edge-refining sampler and a blending decode (LanPaint `src/LanPaint/nodes.py:890-995,1139-1226` at `32cf848e`). No newer upstream version adds a ready-made node for this.
- *Sizes.* The model's own nodes take any width and height in steps of 32, default 1344×768, with no list of shapes, and fix 24 fps and frame counts of 5 + 17k (ComfyUI v0.36.0 `comfy_extras/nodes_minimax_h3.py:29-50,93-134`). 1024×576 is this pack's choice (`shared/prepare.py:241`, `shared/generation.py:346,392`, `shared/compile.py:507-530`, `profiles/`, the continuation workflow's loader). Nothing states which sizes the model handles well.
- *Transcription.* The one Whisper node in a pinned pack (`AILab_Qwen3TTSWhisperSTT`) returns plain text, not word times; the other registered Whisper nodes have no pin or schema; the worker's model lock has no Whisper model. `astrid timelines transcripts` only syncs narration. The transcript document and its SDK exist (`astrid/sdk/media_transcript.py:48-134`).
- *Hivemind.* Astrid's searchable record of Banodoco community practice (Discord messages, shared workflows, curated answers), read anonymously with `astrid hivemind search QUERY --limit N --json`; login is only for contributing. The creative-work skill already tells agents to search it before unfamiliar workflow choices (`astrid/packs/_core/docs/creative-work/SKILL.md:117-124`). Searched on 16 November 2026 for this plan: no report of word-level transcription in ComfyUI; a shared H3 workflow using LanPaint for local picture and sound repair and two shared H3 latent-mask workflows, none reporting clean speech replacement; mixed reports on reference sound (one of voice timbre carrying over, one of the reference being copied word for word); for masks, SAM2 with Florence, SAM3 with point tracking, and a person-mask generator, each a single user's report; no tested advice on crop versus pad or on which sizes H3 handles best. These are leads, not proof.
- *Skills.* Cross-pack procedures belong beside `creative-work` in `astrid/packs/_core/docs/`; a pack has one main skill plus declared extras and linked references (`astrid/packs/_core/docs/pack-builder/references/writing-skills.md`; `astrid/packs/timeline/pack.yaml:5-16`). `guides/` is not shipped to agents. `tests/packs/h3_av/test_skill_examples_admitted.py` already dry-runs the skill's examples.
- *Already there for the rest of the journey.* Placing a take: stored paths are media add through a timeline commit and literal move and trim; `astrid timelines edit --swap-asset KEY=HANDLE` changes a detached draft until it is committed (`astrid/packs/timeline/docs/references/editing.md:85-89`). Words: a transcript document attached to media in source time, which the App already projects onto clips. Renting: the RunPod pack.

**Approach:** The unit of work is a task skill proven by an agent doing the task: one skill document per kind of editing task the Minkhole edit needs, taking a fresh agent from "this clip, this intended result" to a reviewed take on the timeline, with a rented GPU, end to end. Tool work is pulled by the skills: each tool step in [tasks](tasks.md) names the task skill that needs it, and a fix nothing needs is dropped or filed. Extend the existing pack; no new pack and no new command. Three kinds of answer, chosen per need: a line in a skill where the need is a choice; the smallest code where it is mechanics; deletion where it is neither. Considered and not chosen: a wrapper command that turns "this clip, this line" into a request; reviving LanPaint as the route for sound inside footage (the pinned nodes already do the masking; LanPaint stays only as the reference for edge handling until the GPU result); rewriting everything onto request version 2.

General Astrid capabilities this plan uses but does not own, with a recommendation for each:
- *Transcription* (decided, D5): a skill reference, optionally backed by one small included workflow. The reference page is written with RH-2. Checking that a take said its line needs only text, which the pinned Whisper node can give if it runs on the worker. Word times, for cut points, need a node nobody has pinned and Hivemind has no report of; that part stays in Plan 59's log, and when it exists it writes the existing `media.transcript/v1`. This plan does not depend on it: words are checked by listening against the written line.
- *One transcript structure across video, clip and render* (the timeline's word commands and the visualizer reading the media transcript through one projection, narration words no longer a second store): a plan of its own, later; until then an astrid-dev issue. The Morpheus shot does not need it.
- *Masks from a description:* Plan 59's blocker log, when its first picture change needs one. VibeComfy registers SAM2 and Florence nodes; no standalone mask workflow exists. Until then masks are supplied by the caller. This plan only makes H3 take a mask by handle and refuse one that does not match the prepared clip.
- *Placing and comparing takes at generation time:* paused Plan 37; today's timeline commands plus the skill are enough here.

## Owner decisions

- **D1 — LanPaint.** Redirected 16 November 2026: the owner wants sound regenerated inside existing footage ("I think we need that functionality ultimately") and asked whether the node packs already allow it. They do: the pinned nodes mask picture and sound separately, so the route is the pack's own masked edit with a sound mask (RH-6), with no LanPaint and no upstream change. Options now: (a) remove the unreachable LanPaint helper and graph once RH-5's takes show the native route is usable; (b) remove it now; (c) keep it. Recommend (a): it costs nothing to keep for a few days, it is the only worked example of blending the edges of a regenerated span, and if RH-5 shows the edges are the problem, the next question is whether to adopt LanPaint's sampler as a pinned dependency, which is then decided on evidence.
- **D2 — One request shape, and the working version 2 branches.** Open. Version 1 is the one documented shape for continue, change a region and generate; the character swap stays as a separately documented experimental version 2 request. The other version 2 branches work today and duplicate version 1. Options: (a) retire them in RH-3, so a version 2 request without the character swap is refused with its replacement named: version 2 image-reference generation becomes `operation: generate` with `references`; version 2 continuation becomes `operation: continue`; version 2 masked edit becomes `operation: edit` with a mask; (b) leave them working and undocumented, with an issue to retire them later. Recommend (a), after RH-1 gives version 1 the one thing version 2 did better (a source range anywhere in the file). It is an intended change to an experimental interface; no search can show that nobody outside sends version 2 requests.
- **D3 — The `astrid h3` command.** Decided 16 November 2026: it goes ("It should just be part of the generate thing"). `astrid generate video --entry h3` is the one way in; a short migration note says `--dry-run` replaces `plan` and a request file replaces `edit`.
- **D4 — Footage and canvas of any size.** Decided 16 November 2026: Fill by default, never a stretch, and H3 through generate "should work on flexible crop sizes. So any dimensions". As built in RH-1: any input size and shape is accepted and conformed; the output canvas follows the request (the source's own shape, or a stated shape or size) on multiples of 32 within the pack's pixel budget; 24 frames a second and the model's frame grid stay fixed because the model's nodes fix them. Quality on shapes other than 16:9 is unknown until a GPU run.
- **D5 — Transcription and masks.** Decided 16 November 2026 for transcription: "just a skill reference here ... or it could even be a workflow that this includes". It is a reference page in RH-2 plus one included text-transcription workflow if the pinned Whisper node runs on the worker; not a separate plan and not a dependency. Word times remain in Plan 59's log. Masks from a description stay with Plan 59 until task skill RH-7 needs one.
- **D6 — Release and review.** Open. Recommend including this plan in Release 14 beside Plan 59, on `release/14/plan-60` branches, with one review stop after RH-1 and one review round at the end.
- **D7 — How a take is put on the timeline for review.** Open. Options: (a) a stored alternate: the take added as its own clip above the shot with the existing add and trim commands, showing only its generated part at normal speed with the shot's temporary voiceover silent over it, the original untouched beneath, at a pinned revision; (b) a detached review draft using `--swap-asset`, which changes only the local copy until it is committed and is stated as such. Recommend (a); if an existing stored command cannot do one of those steps, that is a finding for Plan 59's blocker log and (b) is the fallback for that take.
- **D8 — Money for the trials.** Open. Every trial rents a GPU. Nothing has been spent. Proposal inside the owner's $25, replacing the earlier split: at most $2 an hour; the pilot run already in flight under Plan 59 keeps its $3; each agent trial has a ceiling of $1.50 (about 65 minutes of the 5090 that quotes $1.39 an hour); $18 for trials buys 12 at the ceiling (about six for RH-2's three clips, three for RH-5, and three between RH-7 and RH-8); $4 stays in reserve. These are ceilings, not estimates: the unknown is how long a fresh machine takes to fetch the 53.5 GB of models, so the per-trial ceiling is reset once the first run reports what a trial really costs.
- **D9 — The stills.** Open. Six of the nine shots are stills that the guide wants moving, and three of those (00, 03, 05) need motion from one picture to another, which no H3 request expresses today. Options: (a) add that to H3 (the pinned node pack has keyframe nodes the pack does not use), as a tool row under RH-8; (b) use H3 only where one still is enough (02b, 02d, the creature in 04) and leave the rest as stills or to another video entry; (c) leave all stills as they are in this edit. Recommend (b) first and decide (a) after RH-8's first trial shows what one still gives. RH-7 and RH-8 stay in this plan as outlined rows, run when the edit reaches them.

Open until a GPU run, not yet a decision: whether 1.6 seconds of voice context is enough, and whether the long target line fits its 6.75 seconds. The graph's context is fixed at 39 frames today; a longer window would be a change to the graph, considered only after a measured failure.
