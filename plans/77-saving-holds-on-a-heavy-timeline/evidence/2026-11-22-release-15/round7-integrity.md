# What Round 7 checks before the editor opens

A cold Runtime authorizes the actor and checks the exact revision and publication that are current for this timeline. It checks the receipt and event chain, checks the latest catalog for untracked writes, and verifies the current film, pinned shots, internal timelines and retained dependencies, including document inputs and media bytes. Live shot and text checks run when the catalog is available. For a recorded commit, the reconstructed film must match the accepted receipt digest. Runtime replays the actions and verifies their recorded order where required, following earlier publications the proof depends on. Bootstrap publications use their own current-revision and dependency proof. They skip recorded-commit replay and the receipt digest comparison. [Head and closure](https://github.com/banodoco/astrid-runtime/blob/8dfa96aca3bbe08ffc9824cdf799354d028acbff/runtime_protocol/timeline_commit_store.py#L1314) · [Replay and earlier rows](https://github.com/banodoco/astrid-runtime/blob/8dfa96aca3bbe08ffc9824cdf799354d028acbff/runtime_protocol/timeline_commit_store.py#L1051)

The old editor verified every history page and the links between its rows before editing. For applicable recorded rows that includes each receipt, referenced revisions, actions and required sequential capture. The new open still hashes earlier history and ledger rows when making a replay key. It skips replaying unrelated old rows and drops the clients' independent closure checks. The old App checked separate immutable endpoints when a receipt lacked a canonical film, and the old SDK compared its reconstructed closure with the receipt. Damage exclusive to an unused old publication can surface later. The editor may reach submission in a case where stock stopped at open. Runtime still authorizes the write and verifies its current head, base, dependencies and change. [History pages](https://github.com/banodoco/astrid-runtime/blob/8dfa96aca3bbe08ffc9824cdf799354d028acbff/runtime_protocol/timeline_commit_store.py#L1430) · [Old App reads](https://github.com/banodoco/astrid-app/blob/f98073ec1b78f06e37d4261dfcc46373e00b6504/src/integrations/runtime/dataProvider.ts#L961) · [Old SDK comparison](https://github.com/banodoco/astrid-agent/blob/b7f0e96a4934ddb4c123eab791a6e18efb8f79ac/astrid/sdk/_remote_timeline.py#L252)

History and Undo/Redo load verified pages on demand. Restore and writes check the exact old publications and revisions they use. Doctor still walks the entire stored history. The HTTP read verifies a committed read-only snapshot outside the live writer lock. The lock still covers copying retained indexes and the final recheck of authority, store, head and file identity, with no fixed time bound. Warm reads can reuse proofs that still match. Store movement can retry once. A final retained-file mismatch can immediately return busy. The handshake advertises the optional route using the unchanged core contract and generated clients. The SDK uses the existing client's private HTTP helpers. ## Reopening a selected local workspace

The new selection read applies to the trusted local proxy. A fresh editor browser reads the authenticated workspace selection. It skips the write only when the result proves the expected actor, realm, scope and project. A missing or different selection still sends the keyed PUT. Paired relay and hosted editors still use their existing PUT. [App selection and document-lifetime ordering](https://github.com/banodoco/astrid-app/blob/846ce8cafdf8ca2e58a101a18242c9e50358f89c/src/tools/video-editor/pages/VideoEditorPage.tsx#L383)

The selection row is keyed by actor and scope in each realm database. In the signed sandbox, the actor's first workspace selection completed after the cold head proof and moved the Runtime's SQLite change counter from 2 to 5. The first reopen then took 17.146 s and replayed the selected record once. The stock three-pair median was 14.115 s. Two subsequent reopens of the same realm with the persisted selection took 4.074 and 4.506 s. Each retained the proof, recorded zero replay and kept its live SQLite change count at 2. The exception is the first previously unset workspace selection for that actor in this realm. Choosing a different project can write again. Any write that moves the store version can require the next verified read to replay even if the timeline document is identical. The first cut keeps that guard. The second cut's design keys reusable verification by stored content and keeps the structural walk. Someone who can already edit the realm’s files can forge or roll back a future sidecar. That person can also change the live database. Doctor will independently verify the history.
