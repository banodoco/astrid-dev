## Successful read, refusal and closed client

A stores verified replay keys at `timeline_commit_store.py:905–918`; B does so at `:955–974`, also recording retained SQL inputs. Successful service exit drops request-local scope, not the shared replay generation (B `:741–757`). Next request can take the stored exact head/entry path (B `:1246–1257`) after the next snapshot's version guard. Starting a fresh browser does not itself reset the Runtime process.

At the next no-cursor read, B synchronizes before assigning the pin (`:528–531`), applying raw tuple equality (`:683–695`). B samples DB/WAL mtime and ctime in its version (`:400–410`). A uses `_same_store_version` (`:68–91,481–484,621–646`) and ignores timestamp-only movement with the other custody/counter/size facts equal. This is the most direct B-specific second-read replay candidate. B also runs retained SQL witness comparisons on a service-owned write (`:357–398`), which costs SQL even when the comparison retains proof. The A landed history contains `05d1ad88`, which reverted an earlier own-write retention implementation for import overhead. The two versions need a measured comparison before proposing retention again.

A and B each clear proof on failed verification or refused snapshots. A's one bounded post-read movement re-evaluation is in `:222–244,503–525`; B's is `:223–242,550–575`. B classifies a narrower counters-only compatible case for retry. In either tree a genuine refusal may clear through the service decorator (`service.py:507–515`). Browser evidence alone cannot tell whether an underlying verification was still running, succeeded and retained state, refused and cleared, or was followed by a separate invalidation.

The proxy socket inactivity window is 60 s (App `config/vite/runtimeProxy.ts:6–7,25–34`). A and B have identical Runtime HTTP and service files. `server.py:967` evaluates the service history call before queuing the response. The handler releases the global store mutex before JSON encoding and socket writes (`:1638–1651,518–538`). ConnectionError or TimeoutError closes that socket (`:1660–1665`). There is no cancellation callback into store verification on an ordinary client disconnect; the abort does not directly drop memo. An earlier request can still be verifying while a retry waits. A later socket write can fail after that request already published reusable proofs. A server-side verification failure can drop proof independently and need not reach an already closed client.

## Decision

B's first cold was 176.179 s. Its repeat cold was 162.362 s and proved the original v30. Its same-Runtime repeat warm did not reach writable within 600.048 s, consumed 320.75 Runtime CPU s, and had no completed history response. A qualified warm in 13.744 s and C in 170.095 s. All these observations precede any edit. B does not establish reliable warm reuse. The browser results do not identify the internal invalidation branch or establish individual blame. The nine are dropped from the Round 7 cut and from any ahead-of-Round-7 landing proposal. Any later reuse needs a separate measured slice against stock with import and warm-read guards.
