# Plan 77 startup deadline feasibility

The change that guarantees a healthy long scan can finish through both supported startup routes spans Runtime and Agent. The local launcher can wait for the longer command. The hosted editor also needs to distinguish an authenticated startup in progress from an absent Runtime. Keep the complete change in the second cut. A higher Runtime-only number could admit the measured direct fixture and allow a longer internal workspace inspection. The normal managed callers have independent clocks, and a larger fixed number still refuses a sufficiently slow healthy realm.

This is source-only work at Runtime `77c38d037f98f744bd8f41c15d95429c124a8003`, Agent `b7f0e96a4934ddb4c123eab791a6e18efb8f79ac` and App `846ce8cafdf8ca2e58a101a18242c9e50358f89c`. No startup, timer, attestation or test code changed. The source-only review ran while the stock timing operator used its own stack.

The two installed direct 300-clip default-budget commands refused at 121.481 and 124.248 seconds before health. Separate 600 s trials took 159.499 s and 157.009 s from native birth to health. The Lead's separate 432-clip managed Round 5 command recorded an active workspace-inspection doctor and exited at 123.485 s before discovery. These measurements cover different installed routes. They do not establish a managed 600 s result or the final memo's timing.

Keep explicit failure and cancellation for real problems and retain the existing complete doctor proof. A cross-layer change must let a healthy, still-owned scan finish without calling that pending state healthy, and communicate that state to the caller. Any eventual ready claim still requires verified realm identity, process custody and a successful admission result.

## Release 15 Lead ruling

The Lead put startup deadline ownership in the second cut on 23 November 2026. One layer will own the admission deadline. Callers will read an authenticated state that reports a check still in progress. The existing doctor and verified readiness proofs remain requirements. A clean-marker attestation could avoid the full scan when it proves eligibility. The first start after an upgrade, an unclean stop and any mismatch still need a path that lets a healthy scan finish. The first cut keeps the current admission budget. [Startup issue #1521](https://github.com/banodoco/astrid-dev/issues/1521)
