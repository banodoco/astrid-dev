## Receipts added after independent review

- **Boundary receipt.** Before launch and again after everything is stopped, the script records a stat inventory (type, path, size, mtime, mode, owner, inode) of the whole signed backup directory. It records one-level listings of the owner directory, the owner's `.locks` directory without `one-root.lock`, the stack root and the data root. Those one-level listings carry no size or time for directories, so they detect added, removed or changed entries but not writes inside a subdirectory. These are stat inventories, not content hashes, so a rewrite that preserves size and mtime would not show. Any difference fails the run, keeps a `boundary-*.diff` and is recorded in `boundary.json`.
- **Lock write.** `exec 9>"$owner/.locks/one-root.lock"` opens that lock file for writing and creates or truncates it, so it is a write inside the owner boundary. `boundary.json` records its size and mtime before and after.
- **Preview check (revised after the first attempt).** The preview is not proven by process group. The first attempt stopped at the old process-group proof because the port 2400 listener is the `vite preview` child, started detached in its own group. The script now relies on the health answer through port 2400 (status ok, `workspace.v1`, the exact runtime instance id). After the stop, `preview-after.json` records the live members of the preview group and the listeners on ports 2400 and 17500, and a listener on either port fails the run. There is no `preview-before.json`.
- **Stops.** A group stop sends TERM to the preview launcher group, waits up to 10 seconds, sends KILL and waits up to 5 more seconds. The launcher stops its own detached children on TERM. As a plain fallback the script then sends TERM and, if needed, KILL to whatever still listens on ports 2400 and 17500. Nothing else is signalled. After the browser stops, a check for any process whose command line holds the disposable Chrome profile fails the run and kills what it finds.
- **Owner exit.** The exact-owner-PID-exited check now runs whenever `candidate-daemon-module.json` exists, including a launch that failed before the Runtime was published.
- **Privacy scan.** Cleanup writes `privacy-scan.tsv` with one line per pattern and file for emails, token-shaped strings, bearer text, secret-like fields, `key_id`, `manifest_hmac`, `.codex` paths and private-key headers. It skips the archived source and the launcher directory and records only the pattern name and file. It does not fail the run. A file listed there must be read before the evidence is shared.
