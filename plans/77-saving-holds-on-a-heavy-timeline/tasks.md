# Tasks — Saving holds on a heavy timeline

[Plan](plan.md) · [Inputs](inputs.md) · [Handover](handover.md) · [Rounds](rounds.md)

A [loop plan](../../skills/roles/astrid-dev-manage/workstreams/live-loop.md): four setup cards, then one standing loop card, then the review. **Routes** follow the [run contract](../../skills/shared/run-contract.md#routing-and-bindings): `N` and `X` run on Codex each bound in the run's `run.yaml` ([handover](handover.md#runyaml)). The advisor and the reviewer are roles with their own bindings, not routes: the advisor gives the strategy each round, the reviewer runs R. The loop card is run by the coordinator, who keeps the judgment and dispatches the fixes as N or X.

**Task ids:** `SL-0` to `SL-5` and `R`. **Critical path:** SL-1 → SL-0 → SL-2 → SL-4 → R. SL-3 runs beside them and does not block round 1; SL-5 is done. **Test inventory:** astrid-app `src/tools/video-editor/hooks/timelineLocalSaveHandoff.test.ts`, `src/tools/video-editor/data/external-drop-utils*` tests; astrid-agent `tests/editing_conformance/`; astrid-runtime `tests/test_v33_protected_acceptance.py`; the new `scripts/save-loop/` scripts, run live.

**How an X task runs:** it writes its `N` split first, launches the independent helpers at once, checks what they return against the code, and keeps the decisions and the final edit. Every task adds commits only. **Machine rules for every task:** a fresh headless-browser profile per run, deleted after; free disk checked before each run and the run stopped below 15 GB; never touch the owner's timelines.
