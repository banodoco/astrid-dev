## What to build

- `otto/config.py`: `load_workspace(root) -> Workspace` reading `otto.toml` with `tomllib` (closed schema: an unknown key anywhere is an error), validating every field the contract's section 3 defines, resolving paths against the workspace root (a path that escapes it fails), checking record-kind declarations (duplicate kind, missing readers, unknown ID preset), adapter module registration and the check and view registrations. Diagnostics are `file:line: message`, with the messages exactly as section 11 gives them.
- `otto/records.py`: generic readers built on `otto.markdown` (frontmatter, bold header fields, headings, tables) and adapter registration for kinds a workspace reads itself. No Dev kinds. (Note: the existing `otto/records` name must not collide with an existing module; if it does, post BLOCKED.)
- `otto/ids.py`: the ID resolver with presets `NN-slug`, `XX-NNN`, `slug`, or a regular expression; for each kind an ID policy separate from locator extraction (contract section 3, "Identity policies"); every preset resolves ID to path and back, preserving leading zeroes and qualified identities as the contract states.
- Tests for every failure the contract lists for configuration and identity (wrong root, unknown key, path escaping the root, duplicate kind, ID breaking its kind's policy, missing adapter, and the overlap rule of section 13 item 1 that applies only to `paths.agent` and `paths.skills_output`).
