## What was found

P95-19b compared Dev's `scripts/skill_builder.py` and `scripts/skill_installer.py` with Otto's versions line by line. Otto's lift agrees except in three places that change Dev's observable output:

1. **Generated header.** Dev's `render_skill` writes a "GENERATED from `<source>` … Do not edit this file: edit the source and rebuild." comment after the frontmatter; Otto writes none. Every generated `SKILL.md` therefore differs.
2. **Lock and scratch names.** Dev uses `.skills-build.lock`, `.skills-lock-…`, `.skills-probe-…`, `.skills-build-…`; Otto derives `.<namespace>skills-build.lock` and so on from the namespace. Dev's tests plant files at the old names and expect the old contention and recovery behaviour.
3. **Link ownership and legacy names in the installer.** Dev treats a symlink as owned when its target resolves anywhere under `<root>/.generated/skills` or `<root>/skills` (the retired layout), and also considers the unprefixed names `astrid-dev` and `shared` when retiring. Otto requires a namespace-qualified link name, a package directory directly under the output directory carrying a valid marker (or the exact former target of a retired package), and ignores the unprefixed names.

Neither side is wrong: Otto's defaults are the safer, generic ones. The fix is explicit, opt-in configuration.

## What to build

All new `SkillConfig` fields are optional, keyword-only, with defaults that leave current Otto behaviour exactly as it is; a default `SkillConfig` passes every existing test with no edit. Validate each new field the way existing fields are validated (checkout-relative paths, names with no separators, no control characters), with clear `ValueError` messages.

- **Seam 1: generated header.** An optional template string (for example `generated_header`) with a `{source}` placeholder, rendered by `render_skill` after the frontmatter exactly where Dev places it, followed by one blank line; `None` (the default) writes nothing, as today. The `{source}` value is the config's source root joined with the document's relative path, in POSIX form, as Dev builds it. Dev supplies its exact sentence; Otto never contains it.
- **Seam 2: lock and scratch names.** Optional overrides for the four names the config currently derives (lock file name, lock stage prefix, probe stage prefix, build stage prefix). When set, they replace the derived value everywhere it is used; when unset, nothing changes. Lock content stays as it is (it already matches Dev).
- **Seam 3: legacy install ownership.** Optional fields that let a workspace say (a) which additional checkout-relative directories count as owned link targets (Dev: `skills`), (b) which extra unprefixed names the installer considers when retiring owned links (Dev: `astrid-dev`, `shared`), and (c) that ownership is decided by "target resolves under the output directory or an owned legacy directory" as Dev does, rather than by the stricter marker rule. Keep one code path: the strict rule is the default and the Dev rule is the configured alternative; do not copy `install_packages`. Preserve everything else: the all-destination preflight, publish-before-retire order, dry-run, partial-failure reporting, identity rechecks, and the committed-cleanup error.
- **Tests (new module):** a Dev-shaped config (`namespace="demo-"`, source `agent`, output `.generated/skills`, header text with a `{source}` placeholder, the four old-style names, legacy dirs and names set) over a temporary tree. For each seam: the default config is unchanged; the Dev-shaped config reproduces the Dev behaviour. For seam 3 reproduce, with invented names, each of these Dev scenarios: a legacy link into `skills/` is retargeted to the new package; a legacy unprefixed link is retired; an unowned foreign link is never replaced; a partial failure reports what was done and leaves the rest. Read astrid-dev's `scripts/test_generated_skill_installer.py` and `scripts/test_skill_builder.py` at the DECISION's SHA for the exact scenarios and failure injections; write Otto-native equivalents, not copies of Dev test files.
