## What to write

Rewrite the file for a person who has never seen Otto, who will have an agent do most of the typing, and who must be able to say after each step whether it worked.

- **Order.** Keep the order the checklist already fixes: the reviewed contract, config, the strategy document, record kinds, pipelines, project templates, roles and authority, boards, first project. Each step is one action in one short imperative sentence, followed by one sentence naming what now exists and how to check it (an `otto` command and what it prints, or a file that must now be present). Where no command can check a step, say so in one sentence rather than implying one can.
- **Plain words.** No unexplained term: a first-use term links to the glossary or is defined in half a sentence. No metaphors, no "just" or "simply", no sentence over 30 words, no paragraph over five lines.
- **No over-claiming.** Otto checks Markdown structure, links, relationships, pipelines, skill packages and generated views. It does not judge whether instructions are correct, grant permissions, install anything unasked, or run an organisation. Keep the rule text that says so, in plain words, where it is relevant.
- **Remove the placeholders.** Delete each "No generic rule yet." line; where a heading then has only a checklist action, the action stands alone. Do not add a rule, permission, step or claim that no OT-16 row carries.
- **Always a next step.** Every section ends with "Next:" and one link; the last section ends with what to do after the first project is done.
- **Keep it a skill.** The frontmatter stays (`skill: true`, one description line within the limit); the title and every heading that another document links to keeps its anchor, or the PR lists each changed anchor and the link that follows it.
