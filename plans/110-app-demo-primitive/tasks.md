### Load-bearing scope notes

**APD-1.** Add `setChat(snapshot | null)` and `applyPatch(id, patch)` to the existing `DemoController`; do not rename or replace its other methods. `setChat` renders through the native composer, model line, message and action-group components that `TourChatPanel` already uses, with no timers of its own: the snapshot is the whole truth for that frame. Pair calls and results by ID (as `buildRenderedTurns` does), not by adjacency. `applyPatch` validates with the public patch contract, applies through the store's `ops.apply`, records the id, makes a repeat of the same id a no-op and throws on a reused id with a different patch. Reset stays dispose and remount. `host.test.tsx` covers: two calls whose results arrive out of order, a failed action shown as failed, typing and streaming text taken from the snapshot, valid, repeated, conflicting and invalid patches, no `fetch` to `/api/` or `/v1/` during mount and edits, and dispose leaving no portal or spotlight. Homepage, onboarding and live chat behaviour unchanged.

**APD-2.** Extend the spec with `conversation` (optional model, messages with `at` and an optional typing or streaming duration, actions with `start`, `end` and `status: done | failed`) and `patches` (id, `at`, patch body). Sampling frame _f_ returns, besides the existing view, focus and actions, the conversation snapshot as of _f_ and the ordered patch ids due at or before _f_. It is a pure function of the spec and frame, so the same frame always gives the same snapshot. `captureBrowserDemo` passes both to `host.apply`. The schema validates every field; compile rejects unknown keys, an action ending before it starts, a result for an unknown action, duplicate ids and events beyond the last frame. A beats-only spec, such as Passing Shapes, compiles unchanged. Tests: deterministic typing progress at fixed frames, overlap ending out of order, failure status, each patch due exactly once across sequential capture, repeated sampling of one frame giving identical output, and each rejection above.

**APD-3.** Port the donor rather than rewrite it. Changes from the donor: the pack under test is the checkout the command runs from, not a pinned older pack, and the receipt records its commit; demos resolve from `tests/packs/astrid_video/preview/examples/app-demo/<id>/` with `definition.json` plus optional `effects.tsx` and `capture.mjs`; the entry page wires `plan.chat` and `plan.patches` to the APD-1 controller; `encode.py` draws the header band only when a beat has a `title` and otherwise scales the capture to the full output frame; the receipt adds the spec SHA-256, App commit, asset hashes, blocked-request log and `nativeExport: false`. Keep the donor's staging of the entry page into `$APP/examples/` and its removal on exit, its Runtime and off-origin request guard, its decoded-frame wait and identity check, and `serve` and `smoke` modes. Negative fixtures under `preview/examples/app-demo/invalid/` each exit nonzero with no MP4: a spec with an unknown event type, a reused patch id, an asset outside the workspace registry, and an effect that requests `/api/runtime/packs`. `render_project.py` gains engine `app-demo` (row fields: `demo`, plus `ASTRID_APP_CHECKOUT` in the environment); it reuses an existing output whose receipt matches the spec SHA, App commit and pack commit. Prove the runner with a two-scene manifest (`app-demo` Passing Shapes, then an `agent-at-work` scene) under `preview/examples/app-demo/project/`: the first run renders both, and a second run after editing only the agent-at-work spec reuses the capture.
