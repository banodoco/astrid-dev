## Goal

Provide one consistent end-to-end path for supported generation, with shared defaults and predictable setup, execution, and results. This plan integrates and publishes the completed generation work after installer consent; managed model execution, training, and GPU support remain unproven or deferred.

## Composition rules

At start, record the actual rolling `pre-main` head in each touched repository and use it as the frozen merge base. Earlier bases (for example Agent `01eceda02e58a1940ada4a261f4789539d6f0a56`) are historical observations, not current dependencies. Where VibeComfy/lifecycle has no `pre-main`, record that absence and use observed `main` as the merge base; create only the final candidate lane, with `pre-main` promotion after review. Merge producers first (VibeComfy, lifecycle, then any required Runtime stop), then Agent, then App pin/lock refresh. Preserve valid ancestry and installer protections. Resolve conflicts only in already changed files with the focused behavior check; no extraction/cherry-pick salvage work.

Use a unique immutable create-only increment lane per touched repository, such as `lane/M-GPU/increment-02-generation-<run-id>`. Do not depend on or overwrite the fixed historical `lane/M-GPU/integrated`. Promotion to rolling `pre-main` remains the existing release procedure after scoped review; if a frozen base is stale at execution time, recapture it and redo only the affected composition/checks. No new approval stage is introduced.

Keep concurrent editing, Packs, unrelated small-fixes folds, and unproven full model execution outside this increment.
