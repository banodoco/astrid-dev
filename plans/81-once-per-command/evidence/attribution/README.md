# CPU attribution

**`run.sh` and its retained runs are diagnostics, not the required baseline.** They use a prepared connection, bypass the normal Runtime launcher, timestamp internal task creation rather than the HTTP admission response, and invoke `console.main` through `python -c` instead of the console executable. The normal-launcher runner is `launcher.sh`.

`run.sh OUTPUT [--trials 5] [--modes plain timings importtime cprofile]` holds `/tmp/astrid-timing.lock` for setup, warmups, every trial, drain and teardown. OUTPUT must not exist. The wrapper uses the isolated interpreter at `/root/codex/plan-81m/attribution-evidence.env/bin/python`; `run.py` checks the three exact source revisions and refuses dirty checkouts. The environment must expose Agent, Runtime and VibeComfy to both the CLI and worker subprocesses. This is source-only, CPU-only evidence against the attached validating test target, not installed or GPU evidence.

For each route and mode the runner uses one warmup and five fresh CLI processes by default. The call is `astrid.console.main()` with `SystemExit`, `--no-wait --json`, seed 12345, and a unique trial prompt. W uses the pinned Qwen Python template, I the default image route, E the explicit Qwen image entry. Runtime task creation and successful target `/prompt` submission are observed in the fixture process using the same `monotonic_ns` clock as spawn and exit. Each returned task must be distinct and succeed; exactly one target acknowledgement containing the trial prompt must follow that trial, and the task is drained before the next command. Task success and this isolated association do not prove real ComfyUI/GPU operation. Timing instrumentation in the fixture may affect the measurements. Raw stdout, stderr, statuses, task and prompt IDs, acknowledgement graph, wall timestamps and provenance are retained; local endpoints and temporary paths are redacted from output. Keep raw captures private until reviewed for local material.

`python rank.py OUTPUT/manifest.json --output TABLES` deterministically renders saved inputs, excluding warmups. `python verify_rank.py` checks reproducibility and expected ordering on synthetic saved inputs; those inputs are not a benchmark. Self imports and cProfile results are measured in instrumented processes; cumulative profile rows overlap and are not scaled to plain wall. A missing mode has no table. The optional sampler, launcher child CPU/wall and wait spans are not captured by this runner and must be reported as missing. The current pin predates A-1–A-3: it cannot establish the later attributed baseline or its remainder target. An installed-machine run and matched post-fix comparison require separate work.

`launcher.sh OUTPUT --trials 5 --modes plain` uses the actual console executable, the normal launcher and a disposable workspace. It verifies the console imports the pinned Agent source and the managed host registration points to it. It holds the shared lock for the whole run. It records completion of the Runtime admission HTTP response write and the stand-in target response write on the host monotonic clock, matched to the task and unique prompt; these are server-side emission timestamps, not client receive timestamps. A hook in the Runtime daemon and a wrapper in the target server add measurement overhead. The hook is absent from measured CLI processes. The target remains alive through launcher teardown. Outputs include the target inventory, package versions, source revisions, command status, separate warmups and raw streams with loopback authorities redacted. The optional sampler and launcher subprocess CPU/wall are not collected. Timing, import and cProfile modes are supported but require their own completed evidence run; they are not implied by a plain run.
