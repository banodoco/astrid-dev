# A-2 CLI hashing and E YAML observations

`observed/` contains one measured instrumented CLI process plus warmup per W/I/E, using the same clean Agent `2ec9c24123a69916fe726023e2eede4c3386b1ce`, candidate `astrid.console:entrypoint`, pinned Runtime/VibeComfy and CPU target fixture as the urgent profile. All three tasks and target responses were matched and drained; teardown was 0. `hash-attribution.md` groups observed SHA-256 constructors/updates and `file_digest` calls by caller, safe path family, count, bytes and measured elapsed, with individual paths and repeat/metadata observations. `yaml-E/` is a second E run with reentrancy-guarded `yaml.safe_load` and direct `yaml.load` interception: 74 and 336 calls respectively, 410 total, zero unlinked paths, with 0.553286 s and 3.185216 s summed durations. These happen to match the count of 410 yaml.load calls in the separate E cProfile run; the runs are separate and timings are instrumented. Direct Loader construction, aliases bound before the hook and subprocess/daemon activity remain unobserved.

The SHA observer intercepts CLI `hashlib.sha256` and `hashlib.file_digest`; `file_digest` elapsed includes file reading and hashing. Direct native/OpenSSL hashes, aliases bound before installation, other processes and untracked file-read methods are outside scope. Path links for `Path.read_bytes/read_text` are made only through retained object identity, and file_digest links through the actual stream name. Unmatched paths are counted. Paths under disposable fixtures retain only basenames and are excluded from distinct/repeat claims. Before/after and across-repeat comparisons use device, inode, size, mtime and ctime as observed; equal metadata does not establish unchanged contents. Call durations may overlap across threads or copied hash objects and do not partition wall or imply a saving. No file contents are recorded.

Instrumentation imports YAML early, retains at most 8 MiB/96 objects temporarily, and writes event JSON at exit inside outer wall. Peak retained bytes W/I/E were 8,375,527/8,345,981/8,359,322; peak process RSS 184,640/192,888/195,724 KiB. Only some SHA wrapper bookkeeping self-time is measured; other observer overhead is unknown. `control/` is a separate matched A-2 uninstrumented fixture run: one measured sample and warmup per route, with timings enabled, same shim, receipts and teardown 0. Its W/I/E outer walls were 11.759/10.340/16.281 s, versus 18.575/16.374/20.353 s with the observer. Differences +6.817/+6.034/+4.073 s include ordinary variation between non-interleaved single samples; they are neither a precise overhead estimate nor a saving.

Raw event JSON files are compressed losslessly as deterministic gzip to reduce size. Other raw trial outputs, manifests, per-path report and separate caller reports are retained. Regenerate both reports byte for byte from this directory:

```sh
python3 tools/report.py observed
python3 yaml-E/report.py yaml-E
```

`tools/verify_probe.py` checks repeated reads, byte counts, original digest parity, YAML nesting, exception transparency, injected observer-append failure and that fixture content is not logged. Its first diagnostic assertion mistakenly expected 26 bytes for a 27-byte literal; the expectation was corrected to the literal length before the passing run. `yaml-E/verify_probe.py` adds direct yaml.load and nested safe_load count checks. The initial interrupted W-only attempt is retained under `diagnostic/` and is not included in the results. The complete raw uncompressed originals and the control logs remain in `/root/codex/plan-81m/run/`.

Targeted scans of the uncompressed staged files found no bearer authorization headers, loopback host:port authorities or quoted API-key/token assignments; the scanner did not print matched values. The scan is not proof of absence of arbitrary sensitive material. Exact source identities, CPU/load, source module and host identities, clocks, status and receipt IDs are recorded per manifest.
