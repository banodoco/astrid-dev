# Witness design reading

At pinned VibeComfy `799d90f6`, `porting/object_info/generation.py:85–110` returns device, inode, size, mtime, mode and a digest of regular-file bytes. Its explicit purpose includes detecting in-place replacements that preserve metadata. The operation uses lstat and a path-based read rather than an fd-bound read with a postcheck; this is not a claim that every concurrent race is excluded. Call sites are the reader in `porting/object_info/consume.py:201,219–224,269,497,500` and the provider in `schema/provider.py:601,616–624,791`; direct test calls are separate. Metadata-only memoization does not preserve the byte-witness guarantee.

Of 2,348 core object-info file witness calls in the captured W trial, 2,221 went through four repeated `_sync_reader` paths in `_load_index`/`_load_pack` and `_resolve_class_type` during emission; 119 came through provider sync, five through provider initial pack load, one through consumer pack load and two through batch-snapshot checks. The [caller note](witness-callers.md) records all witness calls, source identities, measurement limitations and the broader stack.

One candidate is to make `_resolve_class_type` consult the existing operation-scoped `class_entry_snapshot` and scope the two bundle emission entry points as the UI emitter does. This avoids a new persistent cache but needs explicit semantic proof: `get_classes` incorporates curated-only fallback entries (`consume.py:525–530`), whereas `_resolve_class_type` currently returns None for such classes; and identity-specific resolution fails in a class-only snapshot (`consume.py:560–564,635–639`). Emission may catch that exception and fall back to class-only output names (`emit_ready.py:3585–3599`), potentially changing output or warnings. All ready-template byte parity plus identity-bearing and curated-only cases are necessary evidence, alongside the unchanged same-metadata and race tests.

A provider-level byte snapshot is another possible boundary but would require authoritative mutation and lifetime semantics across both provider and consumer paths. A caller-supplied immutable schema snapshot would require changing VibeComfy emitter APIs and Astrid call sites, and proving that target data matches local object-info semantics. Astrid passes a captured target provider to compile, while pinned `emit_bundle` accepts no provider, so that seam alone does not eliminate the dominant emission checks. These are design alternatives and risks, not approved fixes or measured savings.
