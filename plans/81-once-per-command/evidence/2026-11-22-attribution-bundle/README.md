# Plan 81 pre-A1 attribution — staged evidence, 22 November 2026

This package holds CPU source measurements against a validating attached stand-in, not a GPU, an installed build, or an attributed A-1–A-3 baseline. The exact clean inputs are Agent `315b8b7a9336ec3147b399f6bf6f168011d09b27`, Runtime `182311f9d363712c0339254bd27e091d0e18318d`, VibeComfy `799d90f619a6723d0b376b7e77aef09c244a0821`. Each batch manifest records executable, console hash, source/host identity, Python packages, CPU, load, seed, redacted argv, return status, three monotonic timestamps, matched Runtime task and target prompt IDs, and teardown status. Input graph inventory is in each batch. The CLI observer is absent; daemon and target response-write hooks add overhead and record server emissions, not client receipt times. Tasks are drained between trials. No elapsed child CPU or launcher subprocess-specific span is reported.

`combined/` contains the plain baseline and nine separate timing, importtime, and cProfile route/mode batches. Each mode and route has one warmup and five measured processes, with one lock held for its whole fixture lifetime and released between batches. Raw per-process stdout, stderr, timing rows and profile binaries are in `combined/batch-*/`; the root manifest points to them and namespaces target prompt IDs by fixture. The pre-A1 collector does not provide inclusive times or ancestry; report cells say unknown. Plain/timings/importtime/cProfile median wall seconds (with ranges in the reports): W 12.082/12.085/11.876/18.885; I 11.567/12.124/11.382/18.418; E 15.425/15.930/15.753/34.393. These are separate measured process distributions. Import self costs and cProfile self/cumulative values are not scaled to plain wall, and cumulative parents overlap.

Reproduce the saved tables byte for byte from this directory:

```sh
python3 tools/rank_batches.py combined/manifest.json --output /tmp/a4-ranked-again
diff -qr combined/tables /tmp/a4-ranked-again
```

The staging ranker recognizes a fixture ID so separately started stand-ins may both issue `slot-1`; it still rejects repeated task IDs and repeated prompt IDs within a fixture. `tools/merge_batches.py` built the combined manifest from the ten independent saved manifests, copying rather than rewriting their raw records. `tools/launcher_runner.py`, `tools/profile_runner.py`, and wrappers preserve the distinct baseline and profiling procedures. Import profiling sets `PYTHONPROFILEIMPORTTIME=1` on the actual console executable; cProfile runs that console script through the same interpreter as a profiling wrapper. Reproducing a measurement requires an isolated prepared Python environment and the pinned source checkouts; the per-trial argv and package inventory are recorded, rather than a claim that a different environment will yield identical values.

`samplers/{W,I,E}/` each contains one measured py-spy 0.4.4 sample and one warmup, matched receipts and teardown 0. Each used `record --subprocesses --format speedscope --rate 100`; idle threads were not requested and the already-running Runtime/host were not descendants of the CLI and were not observed. Raw process stderr/stdout and speedscopes are retained. Sampling cannot fully account for blocked or daemon work.

The old collector reported `Runtime GET /v1/health` twice in each measured W timing trial and once in each I and E timing trial. Median summed self times for those occurrences were 0.013706/0.007500/0.006519 s for W/I/E. These are only requests covered by that existing timing hook in the separately instrumented process, not a count of every launcher, daemon, or target request; no cross-process partition is implied.

`diagnostics/sampler-W-failed/` preserves the initial sampler attempt: py-spy attached and produced data, but its banner broke the strict JSON parser before drain and teardown returned 1. The two surviving owned processes were manually terminated and verified absent before the successful retry. `diagnostics/I-cprofile-contaminated/` is an otherwise completed batch that overlapped those processes and must not be used as clean measurement. The standalone failed install/profile logs are retained as diagnostics. Optional A-6 work and the A-2-aware console distinction are documented in `tools/console-provenance.md`.

Sanitation: local loopback authorities and disposable scratch paths in saved streams/argv were redacted by the runner. Four speedscope JSON files in this staged copy had loopback authorities replaced with `<local-redacted>`; their unsanitized source files remain outside this package. The 18 unmodified cProfile binary files contain temporary filesystem paths and are retained as requested; they contain no detected loopback authority. The diagnostic contaminated cProfile binaries likewise may contain temporary paths. A scan for bearer authorization headers, loopback host:port authorities and quoted API-key/token assignments found no remaining matches in this package; this is a targeted scan, not proof that arbitrary sensitive data is absent.
