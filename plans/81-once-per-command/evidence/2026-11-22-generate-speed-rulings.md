# Generate speed: rulings on the two specs after the independent review

22 November 2026. Made by the Orchestrator (hosting session) on the owner's request to specify, cross-check and farm out the work that attributes all of `generate`'s time and removes duplicate work inside one command. Binding for the workers: where this file and a spec disagree, this file wins; where the independent review (`2026-11-22-generate-spec-review.md`) found a spec claim wrong, the correction in the review applies unless this file says otherwise.

## What was checked

The planner's attribution spec (cards A-1 to A-6) and fixes spec (F-1 to F-5) were checked against astrid-agent `315b8b7a9` by an independent Codex Astra review at high effort. Verdicts: A-1 OK with changes, A-2 wrong, A-3 wrong, A-4 OK with changes, A-5 wrong, A-6 OK with changes; F-1 OK with changes, F-2 wrong, F-3 OK with changes, F-4 wrong, F-5 held. The review ran the real SDK facade with fakes and counted calls, hashed the two VibeComfy template pairs, and ran four unchanged focused tests (5 passed).

## What the work is and is not

- The target is the one-second `generate` of Plan 82. Plan 81 does not promise it. The review found no evidence that these cards reach one second, and none that the proposed stage list accounts for 90% of a fresh process until it is measured. No delivery date for one second is claimed.
- Generation only. Timeline, saving and loading are not part of this work.
- Plan 81's rules hold for every card: no wire, schema or store change; no refusal moves later than it is today; nothing is kept for a later command; a value worked out once is an argument or attribute of one command's objects, never module state; no existing test is edited, skipped or weakened. Measurements use VibeComfy at the pinned `799d90f6`, not `e65f494`.

## Rulings

1. **Measure first.** Start raw baseline and profile collection (A-4) at once, before any fix. It breaks the cycle between the profile and the instrumentation. Order: A-4 raw baseline; A-1; A-2; A-3; the attributed pre-fix baseline (A-6, first half); then fixes one at a time, each re-measured with the same fixture; then A-5's gate; then the post-fix baseline.
2. **Three timestamps, one clock.** The gate and the baseline record, per trial: spawn to successful Runtime admission response; spawn to the ComfyUI `POST /prompt` acknowledgement of the same attempt; spawn to CLI exit. A gate that ends at Runtime admission says so. Trials are drained outside the timed interval or use isolated endpoints; a server-wide request counter reset between trials can count the previous task's worker.
3. **Coverage is measured per process, not from medians.** On each successful process record wall W, the sum of named exclusive rows S, exactly one remainder R and the collector span C; check S+R against C; gate (W−S)/W per sample, with an explicit clock tolerance; report R and W−C separately. Required names and counts are checked on each of the five samples. A broad parent that collects a whole command does not count as explaining it: split a dominant unexplained parent before calling A-6 complete. Apply the 10% bound to generation (W, I and E); the timeline group keeps its existing gate.
4. **A-1:** keep the existing exclusive `seconds`; add raw occurrence rows with a command-local identity, a parent occurrence and an optional detail, opt-in and additive; repeated names (for example `pack discovery`) keep their separate parents. No Runtime payload or formal schema changes.
5. **A-2:** per-invocation start marks from both fresh entry points (the installed console and `python -m astrid`), a mark on the real gateway import interval, and an explicit provenance when the OS process start is unavailable. Use arguments or a resettable command context, never a new persistent stamp in the environment, so a long-lived tool server is not billed its lifetime.
6. **A-3:** use the review's corrected segment table (section 5 of the review): dispatch and the two parser constructions, the real connection open at the CLI (not the body of the client's `with`), the two snapshot entries (1544 and about 1969) timed inside the generator, candidate and approval per attempt, materialisation as successive scopes, the three admission preflights (`invocation.py`, `RemoteTasks.create/prepare_admission`, workspace prepare) distinguished, and an external tail (output, cleanup, exit) measured by the parent. Instrument operations that actually run and assert conditional route traces.
7. **A-4:** one pinned executable for the baseline and every profile (the console, as the gate runs it), pinned provenance, the real stand-in fixture driving W, I and E; plain `--no-wait --json` wall measured separately from `--timings`, importtime, cProfile and sampling; raw per-process wall, ancestry, stderr, seed, return status, revisions, load, warm-up and spread kept; importtime and cProfile figures are not summed into a partition of wall time; interleave before and after on a quiet host.
8. **A-5:** do not edit the existing gate, its samples or its ceilings. Add a sibling gate and a versioned baseline for the new groups, calibrated with the approved rule (highest of at least three medians, rounded up), and require expected positive work and receipts per trial so a deleted stage cannot pass. Delay tests inject at real operations, including one outside the collector, and use a controlled wall where 1.5 s can cross the 10% bound.
9. **A-6:** record the attributed source baseline after A-1 to A-3 and before the fixes, repeat it after each fix and after all, same fixture and endpoint. Source and installed results are separate runs; an installed result needs a real target with a witnessed endpoint. Plan 81's accepted installed criterion is at most 60% of the first baseline.
10. **F-1 (do first):** pass the command's own client to `attached_comfy_url` at `generation.py:1559`; do **not** pass `repo`; keep the caught exceptions and first refusal; omitted-client and ambient-store behaviour unchanged. Expected: handshake 2→1, health 2→1; settings reads unchanged (still 4 on W). Test with real fresh-CLI shape and an authored-UI case with conflicting stores.
11. **F-3 (do second):** carry an optional verified-equivalent default registry only on the command path that already holds it; keep the legacy load for absent, scoped, private (shipped-only) or substitute-backend cases; test the explicit `None`, a substitute accepting `**kwargs`, a keyword-only parameter and a non-inspectable callable, without retrying a backend `TypeError`. Compare the plan, role bindings, approval digest and missing-model alternatives with and without the registry; count the real loader.
12. **F-2 (after the profile ranks it):** repeated pack discovery and tree hashing per candidate is real, but the specified edit is wrong. Supply a lazy, command-owned policy reader at the points where the existing path already asks for policy (`entries.py` description near 612, `preflight.py` near 337, `availability.py`), never an eager call before the loop; keep every guard and its order; keep the standalone no-argument APIs. The reader snapshots at first use, the same per-command snapshot Plan 81's US-4 already takes for entries and registries; if any existing test pins a different behaviour within a command, stop and write the test ID to the mailbox. Proof compares exact refusal code, message, remedy, candidate order and absence of target/admission, and covers empty candidate list, invalid input plus a broken declaration, authored and bundled paths, scoped roots, and two interleaved commands in one process. Existing tests wrap `model_availability` as `lambda name, *args`: do not break those seams.
13. **F-4: cut.** Reusing a validated placement can skip a live refusal (an ended lease, a stopped endpoint, an edited settings document). Revisit only if the attributed baseline shows real cost and a safe invariant is demonstrated.
14. **F-5: held**, unchanged; revisit only if the second snapshot's setup is measured at 0.2 s or more.
15. **Timing runs are serialised.** Two managers share four vCPUs. Every timing, calibration, profile or gate run takes `flock /tmp/astrid-timing.lock` for its whole duration, so the two managers' measurements do not pollute each other. Record the load average with each run.
16. **Sizing.** The planner's 44 hours (47 with F-5) is plausible for a first source implementation and optimistic for refusal-equivalence proofs, non-vacuous gating and comparative profiling. A week can produce a trustworthy attributed baseline and the safe fixes; it supports no date for one second.
