# Frozen-head installed version and pin preflight, 23 November 2026

The existing fresh published before install was retained. New after and vc48 installations were staged under separate roots in `/root/codex/plan-81m/run/fresh-stage` using the committed candidate manifests; their installers reported success for builds `705298cd` and `b5c30e61`. The first new vc48 install could not start its Runtime because a process from our earlier deleted vc48 staging still held port 17342. Its executable and working directory were both under that deleted staging root; the manager signaled that one verified process via pidfd, removed only the failed vc48 staging root, and reinstalled it. The earlier installer diagnostic log remains in the run folder.

For each arm, the manager ran the wrapper's `runtime_attestation.py --selected` helper on its `program/current` pointer, compared Agent, Runtime, VibeComfy and lifecycle pins from the selected installed manifest with the requested manifest, and ran the launcher with `--version` in that arm's isolated home and door-port environment. All comparisons were true and all three version commands exited zero. The accompanying JSON records show pins, selected versions, and manifest hashes. These are the version and pin preflight steps performed directly, not a full wrapper run. No generation, timeline or timing sample was run.

The preflight records use attestation off: selected manifest pins and launcher version were checked, but Runtime source bytes and the connection used by a command were not attested. Before an installed measurement, the reviewer must independently read each selected current pointer and manifest. Existing timing tables elsewhere are historical and do not measure these frozen heads.
