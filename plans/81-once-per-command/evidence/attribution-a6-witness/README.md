The helper copies the fixed environment twice, preserving symlinks, and replaces the Agent source line in both copies with the approved A6 Agent and the Vibe source line with the respective arm in `attribution-source.pth`. It compares tree entry types, modes, file bytes and symlink targets except that `.pth`, checks interpreter binary hashes against the original, and compares distribution names and versions using Python `-S`. It also compares system `pip freeze --all --path` output, recording the commands and pip version. These metadata checks do not execute arm `.pth` files or import candidate code. `environment-identity.json` records the full tree, metadata, interpreter hashes and source paths. Copies retain absolute paths in existing package metadata and scripts; matching inventories cannot establish that external dependencies or mutable source files remain unchanged. The driver rechecks environment identity and pinned sources before each run.

The schedule takes three plain W pairs in strict before, after, before, after, before, after order, followed by one separately observed W process per arm. Each of the six wall samples has its own same-arm untimed host import attestation immediately before and immediately after it, for twelve separate attestations. Each attestation and each sample is an independent runner invocation with its own timing-lock hold; the lock is released between them. For each attestation the driver temporarily creates the `sitecustomize` and attestation hook files in that arm environment under the lock, with a hard-coded log path, and removes them before the timed environment check. Attestation activates a Python profiling hook and has overhead, so its timings are not wall samples. A SIGKILL can leave a hook behind; environment validation then fails closed and the leftover requires manual cleanup. Hook propagation remains unverified. The hook records the first targeted `consume.py` execution in the host or a descendant, which can occur at startup and does not establish that the task called the witness. An AST marker alone does not prove snapshot-first behavior; inspect retained function source. This evidence covers that instrumented execution, not every import or a proof that later uninstrumented processes behaved identically. Missing or inconsistent attestation fails closed; examine retained evidence.

Each complete runner invocation holds `/tmp/astrid-timing.lock`; the driver releases it between invocations. Target startup through readiness and target teardown take separate short lock holds. Before every run the driver waits up to ten minutes for the lock and load1 below 1 while holding it; a timeout fails closed without taking that sample. It records load before and after each run. The lock coordinates cooperating processes only and does not guarantee a quiet host throughout a run. Each isolated Runtime gets an unobserved warmup and drains tasks before its measured trial and teardown. The target uses append-only receipt offsets; neither counters nor receipts are reset. Failed runs stop rather than replacing or omitting samples. Preserve stdout, stderr, manifest, monotonic spawn, Runtime admission emission, target acknowledgment emission, exit, identities, load, target request and raw observer logs. Inspect outputs for sensitive material before sharing; path filtering is targeted, not a universal sanitizer. No credentials should be read.

The observed CLI injects the copied A-2 hash observer before the console starts; the plain wall samples have no hash observer. The observer wraps Python `hashlib.sha256`, `hashlib.file_digest`, selected `Path` reads, and YAML `safe_load`; it preserves raw per-call known and unknown bytes, callers and durations. It does not instrument Runtime or host processes, native/direct constructors, every file-read API or every API alias. The bounded object-identity association can miss a path, including copied or evicted values; metadata equality is not content equality. `file_digest` durations include reads and hashing. Wrapper and logging overhead can materially change execution; reported observer bookkeeping is partial, not a complete overhead correction. Call durations can overlap or be copied and must not be summed into a wall partition or interpreted as saved time. Record unknowns, errors and failure poisoning. The log cannot count host or Runtime `cache_file_witness` calls or establish exact call counts or bytes. Calls through aliases captured before installation, other hash APIs, unsuccessful file reads, and hash objects never finalized can be missed; event recording and final log writing also suppress errors. A present log does not establish complete observation. A missing log, failed command, missing receipt or differing fixture invalidates that run. Three pairs are observations, not statistical proof, and neither old baseline values nor inferred savings are inserted here.

`summarize.py` can summarize the retained observer event files after a run; keep the raw logs as primary evidence. Confirm module/source identity, the shared endpoint, event counts and intended capture behavior before relying on results.
