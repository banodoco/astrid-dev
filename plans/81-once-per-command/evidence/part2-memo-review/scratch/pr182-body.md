### Earlier candidate evidence

Bundle emission repeatedly witnesses the same object-info packs for scalar class lookups. This change keeps a per-class memo for the bounded emit, then re-witnesses the observed cache evidence before publishing the final bundle pair. The memo is revoked and cleared when the outermost scope exits, including for copied contexts.

The approved contract is: “within one emit the object-info evidence is read as of first lookup and witnessed once more at the end, before any output file is written; a change during the emit refuses with the base's error; where the base would have used a new value mid-emit, this refuses instead”. The output boundary here means the final destination pair: private canonicalization staging may occur earlier and is cleaned on refusal. Invalid cache changes exercised by the regressions raise the base error; a valid changed value instead produces a cache-changed refusal, whereas the base may consume the new value. Provider content is witnessed before and after its first JSON read; a mismatch is refused without caching. A failing-first test covers same-size replacement with restored mtime in that gap. These path-based checks cannot detect an ABA change restored between observations or prove atomicity against all concurrent modifications.

### Limits

A provider pack may change after the parser's verified read and before the caller saves the parsed value and separately sampled witness; the base scalar reader can also return the stale value on the next read. This inherited race is not fixed here.
