## Rule and ownership

Each outermost bundle owner owns a mutable read set in its ContextVar-held, revocable scope. Nested live bundle scopes share it; outer exit clears and expires it, and re-entry via a copied expired context creates a fresh owner. Track, for each observed configured path and resolved active root/generation, its resolved path plus device/inode and relevant type/existence; for each actual object-info dependency, retain a stable logical key, resolved root/path, witness of absence or regular-file type and byte digest, and the first authenticated observation. Record every file and directory consulted, including warm pack signatures, CURRENT, generation manifest, every artifact consulted during generation validation, index, provenance and provider packs, even if no requested class came from the file. Record observations dynamically at the lowest common read/witness boundary, including paths checked for absence and failures, never a manually maintained filename list. A changed observation must poison the owner or immediately follow the original scalar path; it cannot replace an earlier witness silently. Do not cache an exception. Preserve original validation and error order when invoking the scalar reader.

Every read that can affect a memoized class result or its refusals must go through the tracked reader or disable/forbid that memo for the scope before a hit. Route file reads performed indirectly by generation validation through the same tracked boundary, or disable memo for that case. Reads of workflow input, sidecars, publication journal and output staging are outside the object-info reader: inventory and instrument them separately, and decide whether they can influence object-info results; an untracked dependency capable of doing so forbids memo use. If the Lead's rule is intended to cover *every* filesystem read regardless of dependency, the alternative is to track those too or disable the memo: do not silently exclude them. This interpretation requires approval before implementation if it changes scope.

On each memo hit, validate the **entire current read set** including resolving the configured root again, checking root/generation identities and re-witnessing byte contents, before using the cached result. At end of emit validate the entire set again before any final output is published, using either of the two end-check options below. The Lead's later ruling permits stat/identity for the end check only; it does not authorize weakening the per-hit byte check specified above. On mismatch re-enter the base scalar reader under its lock to reproduce the applicable corruption refusal; if it succeeds on changed but valid evidence, reject the emit as the owner-approved Option A semantics require. Do not replace the original witness with a new one and then return stale data. This is stronger and more expensive than merely validating at the end; a final check alone cannot make a hit valid at hit time. Ensure that final validation and publication boundary preserve the existing staging-cleanup contract. Detection cannot eliminate arbitrary concurrent mutation after a check without an enforceable atomic publication/locking contract: state this residual explicitly.

### Authenticating parsed data (#1531)

A pre/post path hash alone does not prove which bytes a parser consumed, and the current separate `_reader_state` witness can authenticate new bytes while its cached parsed object represents old bytes. Read the bytes through an opened, validated descriptor; compute the digest from the **same byte buffer passed to JSON parsing**, verify descriptor and path identity before/after as appropriate, and return `(parsed value, authenticated witness)` together. Install the parsed value and its matching witness as one locked transaction; if the descriptor/path or generation changes, retry using the base bounded policy or refuse. A later separately sampled witness must never be attached to an earlier parsed value. The byte buffer binds parse to witness; before/after identity and content validation address replacement during the read, not arbitrary ABA or modifications after final check. If existing base error ordering cannot be retained, stop and escalate rather than improvise.

## End-of-emit options and contract wording (Lead ruling 03:50)

The memo must be confined to a single command invocation and revoked/cleared at its outer boundary. **Option 1: full byte re-hash.** Re-resolve the configured path/root and generation, and hash the bytes of every regular-file member of the complete read set before publication; also check type and absence. A stable persistent same-size/restored-mtime replacement is detected, subject to the previously stated race/ABA limits. Expected end-check hash calls: one per present regular-file entry in the read set, with bytes equal to their summed sizes; directories, missing paths and root identities require non-hash checks. Some validation paths may hash additional artifacts: count those separately. This is an estimate, not a measured number.

**Option 2: separate bundle-end stat/identity check.** Re-resolve each configured path and link chain and compare resolved path, file type, device/inode, size and nanosecond mtime, including root/generation and recorded absences; re-hash or exclude from memo any class of read whose identity cannot be followed and verified soundly, such as a repointable link whose full resolution cannot be authenticated. Expected end-check hash calls: zero for eligible stat/identity entries, plus one per present regular-file entry in the unsound/re-hashed subset and any additional hashes required by validation. Count bytes of that subset. These calls are incremental to the same first-read and per-hit hashes required above, not total calls for an emit. A root symlink flip is addressed by re-resolving its path and root identity; if the full route cannot be verified, re-hashing an old target alone is insufficient, so exclude it or perform a sound re-resolution. Even eligible files have the explicitly accepted limitation: **an in-place rewrite preserving size and nanosecond mtime during the one command is not seen by the stat-only end check**. A content hash on an earlier hit does not turn the later stat-only check into a byte check; a change after the last hit can escape. Also state ABA and check-to-publication races. Do not claim equivalence to the base for that interval.

`cache_file_witness` remains byte-for-byte unchanged, including byte hashing and all three existing same-size/same-mtime baseline tests, which must pass unchanged. The stat witness is a new, separate helper used **only by the bundle-scope end check**; it must not change ordinary scalar reader, witness, or per-hit behavior. Compare both options using instrumented real read sets; the number of regular entries and unsound subset is not established, so numeric total hash-count predictions would be invented. For a given run let B be unchanged first-read/per-hit work, R the full end set, U the subset that must be re-hashed and V extra validation: option 1 expects B + |R| + V calls and B-bytes + sum(size(R)) + validation bytes; option 2 expects B + |U| + V calls and B-bytes + sum(size(U)) + validation bytes. Compare against the measured baseline below, including its existing final-check hashes so additions and replacements are not double-counted.

**Docs and PR contract wording if option 2 is chosen:** “Within one command, bundle emission records the object-info dependencies it reads. Before a memoized lookup it validates the complete recorded set; before publishing the final output it checks the complete set again using resolved identity and stat, and re-hashes or excludes dependencies whose paths cannot be safely checked that way. A detected change refuses before final output is published. An in-place rewrite that preserves size and nanosecond mtime during that command may escape the final stat check; changes after a check and ABA changes may also escape. Ordinary `cache_file_witness` continues to hash bytes.” This replaces any blanket statement that every content change is detected or that every refusal exactly matches base. When a changed valid value would have been consumed by base, retain the explicitly approved refusal behavior. Update wording only upon implementation/authorization; this note changes neither docs nor PR.

## Cost and measurement

Existing W-proxy evidence varies by exact head: `4e5c3cc9` is **238 calls / 200,880,474 bytes** (~201 MB), while `950023c8`/`06ad021f` is **240 / 203,538,906** (~204 MB); 53 emits are **37,391 / 13,850,200,412** (~13.85 GB). W has 13 distinct classes and 52 scalar syncs (four/class), versus baseline **7,608 / 5,424,491,784** bytes. Counts are witnesses, not seconds; W is a proxy, not the full Astrid command.

Total expected change is unknown: per-hit full-set hashes may increase work, while replacing current final hashes with stat checks can reduce end-check work. The increase can be large. If there are H memo hits and the growing set has N_i files/bytes at hit i, extra hit-validation work is approximately sum_i N_i hashes and sum_i bytes, plus full-set validation at end, authenticating bytes and any extra first-observation checks, minus work already done in current checks. Warm packs and manifest artifacts can increase N_i substantially. Per-hit whole-set hashing may approach or exceed the original reader's work; do not promise a 10x improvement. Measure actual calls and bytes on the exact candidate, separately by per-hit/final/first-read and cache path, against paired 950023c8 and release base with identical input manifests. Capture 53 per-template counts and aggregate and the same 13-class W proxy, then ask the attribution manager to measure the installed result under the timing lock when authorized. Part 2 acceptance is the measured installed number, whatever it is; no 5.7-second target is promised. No timing runs are part of this design task.
