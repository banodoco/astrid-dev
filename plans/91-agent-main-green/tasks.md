## How work is proved

CI on a pull request into `release/15/main` runs only fast checks, unit shard 1 and boundary (`ci.yml:9-13`). Pushes to a plan branch start nothing, and Lanes has no pull-request trigger. Proof therefore runs in three places:

1. **The worker's checkout** for code-only cards: `bash scripts/worker-env/agent-setup.sh` once, then `bash scripts/worker-env/agent-pytest.sh -q -rA <files>`, by literal path from the astrid-agent root ([shared worker environment](../../env/README.md)). It runs Python 3.13 and fetches at depth 1; CI uses 3.11.
2. **A hosted card run** for anything that depends on CI's inputs (Node, esbuild, Remotion, ComfyUI, Pinokio, historical git objects) and for every flaky trial. AG-1 adds `workflow_dispatch` inputs to both workflows: `tests` (the files or IDs to run), `repeat` (run them *n* times) and the ref. A card run takes minutes. Cards AG-A1 to AG-A3, AG-B13, AG-B18, AG-B20 and AG-B22 prove here.
3. **The batch run.** After merging up to five cards, the manager dispatches both full workflows on `release/15/plan-91` and compares the results with the ceiling by (job, id). This is the gate. The same comparison runs on every completed `release/15/main` run.

**The ceiling is a ratchet only the manager edits.** Cards never touch it. After a green batch comparison, the manager removes every ID that passed and commits the new ceiling. An ID leaves the ceiling only after passing in a batch run on hosted CI.

## Triage rules

Every Wave A, B and C card follows these, in order. They turn "fix the long tail" into steps a worker can't get wrong.

0. **Prune before fixing.** If any of the card's IDs is in [prune-candidates.md](evidence/release-15-b324d7c1/prune-candidates.md), use the prune pass's verdict for it: a retired or redundant ID is deleted by AG-P1 or AG-P2, not fixed. Only a kept ID is the card's to fix. A card that meets a test of retired behaviour the prune pass missed retires it under the same rule, with its citation.
1. **Reproduce first.** Run the card's IDs on the plan branch head. An ID that passes is reported, and it leaves the card only when it passes in a hosted run (proof 2 or 3). An ID that fails differently gets its new first-failure boundary recorded before anything changes.
2. **Name the kind, with evidence.** Exactly one per cause:
   - **env:** CI or the test setup doesn't provide an input the test asks for;
   - **stale-test:** the behaviour changed on purpose and the test wasn't updated;
   - **retired:** the test exercises something deliberately removed;
   - **redundant:** another passing test already covers the same behaviour;
   - **product-bug:** the product is wrong;
   - **flaky:** the outcome depends on timing or load;
   - **unknown:** none of the above, yet.
3. **Fix by kind:**

   | Kind | Allowed fix | Required proof |
   | --- | --- | --- |
   | env | Provide the real input in CI or the test setup: the pinned tool, the real checkout, the real object. Never a stub path, a default inside the test, or a skip when it's missing. | Hosted run: the IDs pass; with the input removed, the test still refuses with its own message. |
   | stale-test | Update the expectation. The card quotes a source that **states the new behaviour and postdates the test's last change**: a PR, a plan task, a release-brief line, or the contract file and its rule. A squash-merge commit alone doesn't count (`fb730f78`, `998ca937` and `6564b580` each touch about 4,000 files). With no such source, the kind is unknown. | The IDs pass; the card quotes the source. |
   | retired | Under [D5](inputs.md#owner-decisions): delete the test, citing the retiring change (a commit, PR, plan task, brief line, or a record such as `config/astrid-beta-capabilities.json`) or D5's support line. Only current behaviour, and updating from the previous published release, is supported: older formats, older install boundaries, historical commits and moved packs are retired. Where a user could still reach the old path today (an API route, a command, a file the App opens), a test must assert that it refuses, as with `410 retired_route`. | The deleted IDs are listed with their citation; any refusal test passes; an `X` reviewer has read the list. |
   | redundant | Under D5: delete the test, naming the passing test ID that covers the same behaviour, and say what both assert. | The deleted IDs are listed with their covering IDs; the covering tests pass; an `X` reviewer has read the list. |
   | product-bug | Fix the product if it takes a day or less, with the failing test as proof. Otherwise, under [D6](inputs.md#owner-decisions), an `X` check confirms the test shows a real defect. The card then files an issue, the owner accepts the ceiling entry when it is filed, and the IDs stay visibly red. | The IDs pass, or the issue link and the owner's acceptance are on the ceiling entry. |
   | flaky | 20 paired trials before and after, through the hosted `repeat` input. Never widen a deadline, add a retry or raise a timeout in product code to pass; a change to a product deadline is [D14](inputs.md#owner-decisions). | 20/20 after; the base's rate is recorded. |
   | unknown | Two hours of diagnosis at most. Then treat it as a suspected product bug, and re-route an `N` card to `X`. | The diagnosis notes, then the rule for the kind it becomes. |

4. **No other change.** A card changes only its scope. Nothing is added to a skip list, a deselect list or a baseline that only grows. Cards don't edit the ceiling.
5. **Prove by ID.** The card's IDs flip from red to green. `env/baseline-diff.py` on base and head shows no new failure in the card's files or in any file that imports the changed code ([Release 14 ruling 13](../../releases/14/run.md)).
6. **Stop at twice the size.** A card that has taken twice its size stops and reports. The manager splits or re-routes it: `N` to `X` for coupled reasoning, and `X` to `S`, or to the owner, for a contract decision.
