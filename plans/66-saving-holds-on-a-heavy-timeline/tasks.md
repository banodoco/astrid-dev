# Tasks — Saving holds on a heavy timeline

[Plan](plan.md) · [Inputs](inputs.md) · [Handover](handover.md) · [Rounds](rounds.md)

A [loop plan](../../skills/roles/astrid-dev-manage/workstreams/live-loop.md): four setup cards, then one standing loop card, then the review. **Routes** follow the [run contract](../../skills/shared/run-contract.md#routing-and-bindings): `N` is Luna, `X` is Sol at xhigh, `S` is Astra (read-only). The loop card is run by the coordinator, who keeps the judgment and also dispatches the fixes as N or X.

**Task ids:** `SL-0` to `SL-4` and `R`. **Critical path:** SL-0, SL-1 → SL-2 → SL-4 → R. SL-3 runs beside them. **Test inventory:** astrid-app `src/tools/video-editor/hooks/timelineLocalSaveHandoff.test.ts`, `src/tools/video-editor/data/external-drop-utils*` tests; astrid-agent `tests/editing_conformance/`; astrid-runtime `tests/test_v33_protected_acceptance.py`; the new `scripts/save-loop/` scripts, run live.

**How an X task runs:** it writes its Luna split first, launches the independent helpers at once, checks what they return against the code, and keeps the decisions and the final edit. Every task adds commits only. **Machine rules for every task:** a fresh headless-browser profile per run, deleted after; free disk checked before each run and the run stopped below 15 GB; never touch the owner's timelines.
