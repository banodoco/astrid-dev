**Approach:** Provisional logical per-pack namespace scoped by Runtime, one typed mediated storage contract, ordinary SQLite relational support and reusable existing document primitives. Compare separate SQLite files, same-file protected tables and existing documents with real atomic edit, failure, isolation and export cases. Keep physical arrangement private. [SQLite ATTACH](https://www.sqlite.org/lang_attach.html) explicitly limits cross-file crash atomicity in WAL mode; [appropriate uses](https://www.sqlite.org/whentouse.html) explains server-mediated access and single-writer concurrency; [security guidance](https://www.sqlite.org/security.html) and [authorizer](https://www.sqlite.org/c3ref/set_authorizer.html) are inputs for an independently reviewed SQL boundary, not proof of isolation. Retain SQLite default unless measured concurrency/availability or actual transaction needs dictate another backend. Avoid a generic database platform, new migration manager per language or compulsory SQL for small tools.

## Gap boundary proposal

Current primary remains LS-003. Consider a distinct gap — **Packs cannot yet independently own and evolve durable creative data** — primarily under the Liquid Software aspiration [Packs are live, portable and extensible](../../vision/pillars/liquid-software.md#packs-are-live-portable-and-extensible). It is observable even with excellent UI/operation composition (LS-003), agent tool authoring (LS-005), reliable installation (F-004) and independent core/client contracts (LS-006). A pack may have all those properties but still lack a supported way to add relational state, migrate it, preserve it through upgrades/removal and transfer it between local/hosted workspaces. Existing JSON documents make a blanket "no pack storage" claim inaccurate; the distinct question is ownership, evolving structured data, isolation and portability without core changes. Closure evidence should be two real data-model journeys including the owner-selected default feature, schema evolution/recovery, denied foreign access and local/hosted portable custody. Have the advisor compare strengthening LS-003/F-004 instead of introducing a gap; only after boundary review and owner disposition create a new gap ID, change primary/backlinks and declare a closure route. Do not manufacture a new gap merely for this plan.
