## 2. Verdict and smallest coherent outcome

Keep the single release record, generated manifest delivery, exact pin/approval gates and user-facing version from P31. Move RL-3 **before** R16's first canonical publication; retain all of the security and compatibility contract, not a cosmetic 0.1 label. Absorb P58's already delivered parser, draft checks and strategy generator and the P29 publication rows it already moved. No additional roadmap document, visualization, parallel release log, version arithmetic in clients, or second manifest source. Continue integer release ordering internally.

Recommend the existing two-mode release qualification model: R16 mode A (complete, exact-head, no harm, no unexplained regressions, all actual required checks and journeys genuinely green), R17 mode B (eliminate inherited red and establish/maintain universally green mains). D22/full-green language must be reconciled explicitly by the owner/coordinator before scope approval; it cannot be silently superseded by this report. If a required check cannot pass without fixing a failure, that fix is an R16 prerequisite or the release is blocked. No bypass, no retesting until green, no changing assertions, no omission of a required job, no acceptance of harm. No universal-green claim before R17. A genuine approved, non-harm, individually evidenced known-issue ledger is a different proposition from absent proof or a failing required check. Prior release overrides do not transfer automatically.

The minimal successful R16 implementation is: one conservative schema + legacy import; one release contract + protected finalization; one generated-copy path and guard; one displayed semantic version; one explicit required-update decision and qualification/cutover receipt. All six must work together. It is possible in principle without a second numbered publication or full R17 programme, **conditional** on the blockers below, not demonstrated now.
