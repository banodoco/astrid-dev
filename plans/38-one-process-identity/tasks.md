Routes, per the [run contract](../../skills/astrid-dev-shared/run-contract.md):
- **N:** normal, the default.
- **X:** very hard.
- **S:** super hard, used here for security and custody.
- **T:** taste, used here for message wording.

X and S tasks delegate research, reading, mechanical edits and checks to N helpers, and keep the judgment and the final change. An N task that misses the same acceptance check twice re-routes to X.

**Where work lands.** Each task lands by PR on `int/38-one-process-identity`, in the Runtime (R) or the Agent (A), cut from each `main` after release 12 is published. Record each task's base SHA when it starts.

- *Local* runs in a worker session with only that task's repository attached. - *Hosted* is the named CI job on the task's PR, judged by its inner pytest step.

**Each task deletes the copies it replaces** ([duplicate inventory](inputs.md#duplicate-inventory)) in the same PR.

## Task details

### P1 provider API
- **Functions:**
  - `identity(pid)` and `birth_matches(a, b)`, which re-export `platform.process_identity` and `process_birth_matches`;
  - `token(pid)`, `peer_token(sock)`, `details(words)`, `signal(words, signum)`, `resume_once(words)` and `census()`;
  - `PRIMITIVE`, `ROTATES_ON_EXEC` and `supported()`.
- **Darwin.** `darwin_process_binding.py` takes the union of both brokers' Darwin code: the audit token; `LOCAL_PEERTOKEN`; the task-name-port token with its structured capture failure; `proc_signal_with_audittoken`; the one-shot resume; the suspended `posix_spawn`; and the `kinfo_proc` census ABI check.
- **Linux.** Use `SO_PEERPIDFD` where the kernel answers it. Otherwise keep today's `SO_PEERCRED` read before and after the `/proc` read.
- **Windows.** Pin on inherit: the peer's process handle is opened and identity-checked when the channel is adopted, and `signal` uses that handle, not a later pid lookup.
- **Import rule.** The modules use only the standard library, `ctypes` and `runtime_protocol.{platform,dirfd}`. The host can import them under the verified mapping (`verified_host_launch.py:756`), after `verify_installed_host_startup()`.

### P2r closure definition
- **The file** holds `components` (name → path) and `installed_pair`, which lists `runtime_protocol` and `astrid_runtime` and is measured when either is present beside `astrid/` (decision D2). It also holds `vectors`: inline trees and their expected `components` and `digest`.
- **Two measurers stay** (`verified_host_launch.source_checkout_closure` and the Agent's `source_identity`), because neither may import the other's code first. The file is their one definition, and the vectors pin their algorithm.

### E1 job
- **Shape:** `host-spawn` installs the Agent from `tests/astrid-agent.pin` non-editably, the same way today's `darwin-native` job does, on each OS.
- **Blocking:** it is not `continue-on-error`.
- **The diag workflow** `diag-darwin-custody.yml` and its branch stay unmerged.
