# Nekodificador’s H3 tools and their fit in Astrid

Research date: 2026-11-18. This is read-only research; no workflows were run. “Fact” means a source states or implements it. “Fit” means a proposed Astrid mapping, not an implemented feature or validated generation result. A node’s existence/interface does not establish output quality.

## 2. Nekodificador tools: mechanism, I/O, license, maturity

| Tool | What it does; H3 mechanism and I/O (facts) | License / maturity | Astrid fit (inference) |
|---|---|---|---|
| **NKD Event Curve** (Basic Tools) | Curve editor/generator makes a time-varying event signal (documented event classes include impacts, flow, motor, blast, uncanny and words). Curves can be authored or derived from audio loudness / video motion; output includes guide audio and a visual curve preview. H3 gets the generated signal through **MiniMaxH3AddGuide** as audio conditioning, placed at a frame (the example uses frame 0). This is temporal audio guidance, **not** timestamped text prompt conditioning. [Node docs](https://github.com/Nekodificador/ComfyUI-NKD-Basic-Tools/blob/master/docs/event-curve.md) · [announcement](https://cm.q258.de5.net/en/news/2026-11-15-nkd-event-curve) | GPL-3.0 in repo. [LICENSE](https://github.com/Nekodificador/ComfyUI-NKD-Basic-Tools/blob/master/LICENSE) | A timeline **control/audio guide** item with curve points, event class, generated waveform and strength, linked to its target interval. Keep the curve editable and provenance-linked; do not silently turn it into a prompt. |
| **MiniMax Guides** (Basic Tools) | Convenience lowering for image, image sequence, video and audio guides into H3 latent conditioning. Guides are placed by frame; `-1` means last frame; guide may include duration/`until`; same-frame sounds can be mixed per current docs. Uses native `MiniMaxH3AddGuide` semantics. Inputs: conditioning, target AV latent, guide media/position/type and VAE as relevant; output: modified conditioning. [Docs](https://github.com/Nekodificador/ComfyUI-NKD-Basic-Tools/blob/master/docs/minimax-guides.md) · [official node](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L165-L239) | GPL-3.0. [LICENSE](https://github.com/Nekodificador/ComfyUI-NKD-Basic-Tools/blob/master/LICENSE) | A placed **guide** timeline item: media, modality, frame/time, duration and guide policy. Keep delivery permissions separate: a soft guide does not promise exact pixels. |

Extend combines a prior sampled latent and a new latent with overlap, then reports overlap/trim information to extend a clip. These are latent construction/extension helpers, not new H3 model weights. [AV Latent](https://github.com/Nekodificador/ComfyUI-NKD-Basic-Tools/blob/master/docs/av-latent.md) · [Extend](https://github.com/Nekodificador/ComfyUI-NKD-Basic-Tools/blob/master/docs/av-latent-extend.md) | GPL-3.0; documented custom nodes. [Docs/source](https://github.com/Nekodificador/ComfyUI-NKD-Basic-Tools/blob/master/docs/temporal-crop-stitch.md) | GPL-3.0; custom-node workflow utility, maturity evidence is repository docs/examples. This is denoising/timestep control, not clip-time control. [Docs](https://github.com/Nekodificador/ComfyUI-NKD-Sigmas-Curve/blob/master/docs/h3-audio-shift-curve.md) | GPL-3.0; documented custom node, but no independent quality claim. **Clarification about “prompt conditioning at specific points in time.”** The evidence reviewed for Nekodificador supports temporally varying **audio guide** strength, guide placement and sampling-stage audio shift, not per-time textual conditioning rows. Separately, community **ComfyUI-MiniMaxDirector** turns timed picture/camera/audio segments into one structured H3 prompt and conditioning, and Draken’s nodes select conditioning by sampling window; those differ from proof that H3 natively masks text embeddings to exact video frames. [Director guide](https://github.com/imbutus/ComfyUI-MiniMaxDirector/blob/main/docs/GUIDE.md) · [Draken nodes](https://github.com/DrakenZA/Comfyui-H3-DrakenNodes)

## 3. Other H3 capabilities and what they would mean for Astrid

| **First/last keyframes:** stock `MiniMaxH3ImageToVideo` encodes optional first and last images into `minimax_keyframes` at frame 0 and final frame; prompt + dimensions + length produce positive conditioning and AV latent. [Pinned official source, lines 115–162](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L115-L162) | Boundary-placed guide items, same guide abstraction as interior anchors. |
| **Guide at arbitrary frame / audio-to-video:** official `MiniMaxH3AddGuide` inserts image, clip, audio or AV guide at a requested pixel frame into conditioning; multi-frame inputs are aligned to H3’s frame grid. Soft conditioning is not exact decoded-pixel preservation. [Pinned source, lines 165–239](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L165-L239) | Timeline guide item with modality, frame, duration, strength and target; permissions remain separate. |
| **Multimodal references / speaker material:** official ReferenceToVideo accepts images, videos, paired video audio and standalone audio, labels them `<Picture n>`, `<Video n>`, `<Audio n>`, then encodes them into positive conditioning/AV latent. Capacity is node-specific (up to 9 images, 3 videos, 3 paired and 3 standalone audio references). [Pinned source, lines 242–363](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L242-L363) | Typed reference objects; speaker is a named audio/video reference bound to dialogue prompt segments. Avoid implying independent multi-speaker binding without a route that implements it. |
| **Timed text / shot prompting:** community director workflows package timed shot/action clauses and references into one model prompt; window samplers can choose conditioning by denoising window. These are workflow strategies, not stock frame-isolated text rows. [Director](https://github.com/imbutus/ComfyUI-MiniMaxDirector) · [Draken](https://github.com/DrakenZA/Comfyui-H3-DrakenNodes) | A `prompt` timeline item with text and interval; compiler must state whether it generates segmented prompts, window-selected conditioning, or only one narrative prompt. |
| **Camera / motion control:** community workflows feed motion-reference video/AV latents, or encode camera/action schedules as per-latent text clauses. Mechanisms vary and are experimental; e.g. [H3 Motion Context MultiRef](https://github.com/seitanism/ComfyUI-H3-Motion-Context-MultiRef/tree/361624fb) and [H3-World camera workflow](https://github.com/NyckM/3d-Camera-control-H3-Minimax). | Motion-reference media or a camera/control track on timeline; permissions state which visual regions can change. Label backend support and maturity per control type. |
| **Context extension, inserts, loop-like chains:** Motion Context provides AV context/extension, overlap/insert and AV bridge workflows using latent context and masks; inserting context is not equivalent to exact source-frame preservation. [Keyframes and inserts](https://github.com/seitanism/ComfyUI-H3-Motion-Context-MultiRef/blob/361624fb/KEYFRAMES_AND_INSERTS.md) | Continuation segment anchored at source end, with overlap metadata; bridge has two protected source intervals; explicit composition policy establishes actual pixel/audio preservation. A loop is a composition constraint if the chosen graph supports it. |
| **Motion transfer / upscaling:** Motion Context examples transfer motion through source AV latent, fractional denoising and learned latent upscale/de-rope stages. This is a multi-stage workflow, not a native H3 node. [Example workflows](https://github.com/seitanism/ComfyUI-H3-Motion-Context-MultiRef/blob/361624fb/example_workflows/README.md) | Render/post-process stages in a skill recipe, with their model/settings recorded; not a new media primitive. |
| **H3 Fun ControlNet / denoising ranges:** official source exposes control video, mask, strength, and start/end denoising percentages through a patched model. The percentages schedule sampling, not clip time; mask convention distinguishes regenerated pixels. [Pinned source, lines 454–509 and 573–615](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L454-L509) | A control/mask layer tied to a generation pass and sampling range, with explicit permission semantics. Do not render denoising percentage as timeline time. |
| **Resolution / duration limits:** official node uses a 17k+5 frame grid at 24 fps; source documents typical trained range around 124–362 frames and calls longer lengths untested. [Pinned source, lines 93–105](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L93-L105) | Timeline duration can be user-authored, while compiler reports snapped effective length. Canvas size belongs to generation settings, not a guide. |

## 4. Astrid fit: current surface and design direction

**Facts about current Astrid.** The H3 pack defines request → prepare → compile → validate → run → compose → verify and maintains separate change permissions/masks. H3 skill (`astrid-agent` `astrid/packs/h3_av/docs/SKILL.md`) Its v2 request model already parses image/video/audio media as timeline or reference entries, frame placements, edit intervals, masks, guides and literal dialogue/text. request_v2.py:350–423 (`astrid-agent` `astrid/packs/h3_av/shared/request_v2.py:350`) That grammar is broader than every route the compiler can lower: for example, the LanPaint AV graph rejects references, and native continuation rejects audio references. compile.py:230–272 (`astrid-agent` `astrid/packs/h3_av/shared/compile.py:230`)

**Plans already on astrid-dev main (facts).** Plan 64 is queued and proposes typed image/video/audio speaker references for source-free and masked routes; it explicitly excludes multiple speakers, `MiniMaxH3AddGuide`, arbitrary-frame timeline images, and separate dialogue pieces. [Plan 64](../../64-h3-speaker-references/plan.md) Plan 65 is queued and proposes per-request output size, building on Plan 64’s generation inputs. [Plan 65](../../65-h3-dynamic-size/plan.md)

**Design recommendation (inference).** Treat the canvas as a typed, composable request: media occurrences; timeline placements; prompt/dialogue items; guide/control tracks; references; and independent video/audio permission masks. A skill should be a recipe over these primitives plus declared compiler capabilities. Distinguish a *soft latent guide* from a *hard output permission/preservation guarantee*: guide latents influence sampling, while only compose/verify can establish what pixels or samples were actually preserved. This lets Event Curve be represented as a curve plus linked audio guide; lets spoken words be speaker-bound prompt/dialogue items; and lets extension, masks and upscaling stay workflow stages instead of ad hoc node graphs.
