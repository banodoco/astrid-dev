## Finding that resolves the insert_frame-0 unknown

**Yes: the prefix continuation is `MiniMaxH3ExistingVideoMaskedContext` with `insert_frame=0`.** The API explicitly says zero is the original prefix behavior and returns `trim_frames=preserved_frames` for zero, versus zero trim for interior insert (`existing_video_extension.py:826–890, 908–915, 1082–1102`). It decodes/normalizes source frames and audio, chooses a shared AV context, VAE-encodes that source tail into the target latent and masks it to preserve. The matching output is `MiniMaxH3AssembleExtension`, which concatenates the original source with generated output after trimming the preserved prefix (`existing_video_extension.py:1762–1797`; schema `ComfyUI-H3-Motion-Context-MultiRef@cpu-runtime.json:1167–1284`).

The captured workflow's *active Existing Video* branch instead starts with `MiniMaxH3StartMaskedContext(start_mode="existing_video")`, passing decoded `source_frames`, `source_audio`, target latent, 39-frame context, and 8 audio feather ticks; that selector delegates to `MiniMaxH3ExistingVideoMaskedContext` with its default `insert_frame=0` (`workflows/native_h3_continuation/workflow.py:398–408,441–473`; `existing_video_extension.py:1690–1758`). Subsequent blocks use **different nodes**: six chained `MiniMaxH3GeneratedAVMaskedContext` nodes copy prior sampled AV latent into each fresh target latent (`workflow.py:513–520,556–562,602–608,648–654,694–700`; schema `...cpu-runtime.json:1497–1553`). Final output uses `MiniMaxH3StreamLiveExtensionAVToVHS`, not either insert assembler (`workflow.py:780–818`). The `MiniMaxH3StartMaskedContext` is a selector/wrapper, not a distinct prefix algorithm.

**One lowering covers all three only at the source-context insertion stage, not as one complete graph/output path.** Prefix and interior insert share `MiniMaxH3ExistingVideoMaskedContext`; zero versus nonzero insert position changes mask placement and trim output. Prefix output needs `MiniMaxH3AssembleExtension`; an interior insert needs `MiniMaxH3AssembleInterior` to splice exact source pixels and PCM back into decoded output (`existing_video_extension.py:1276–1335,1354–1447`). A two-sided bridge uses **another node family**: `MiniMaxH3MaskedAVBridge` conditions both ends and `MiniMaxH3AssembleBridgeAudio` handles audio (`h3_masked_bridge.py:243–451`; schema `...cpu-runtime.json:518–577,2225–2346`). Do not describe one lowering as covering prefix, insert, and bridge; share graph-building helpers only if their contracts remain explicit.

**Frame lattice.** The Existing Video node snaps `insert_frame` *down* to a multiple of 17 (latent phase grid); multiples of 51 also align the 24-fps frame position to the 40-Hz audio clock exactly. Other multiples of 17 are accepted by source but audio position is rounded to the nearest audio tick and logged with a nonzero timing error; the current CC-7 text proposes refusal, which is a deliberate stricter Astrid contract, not node behavior (`existing_video_extension.py:863–870,908–915,1011–1029`; schema `...cpu-runtime.json:1167–1284`). Prefix length/context must be a joint boundary **39 + 51k** (39, 90, 141, 192, …), chosen no larger than requested, usable source and target; under 39 usable frames errors (`existing_video_extension.py:312–348,946–949`; schema lines 1200–1260). Video-only valid runs 5+17k (5, 22, 39, 56, …) are not necessarily exact AV boundaries. Bridge preserved length also requires 39+51k; its target video latent is a valid 5+17k run and must leave a nonempty generated middle (`h3_masked_bridge.py:159–164,243–320`). An insert's preserved source segment uses the shared AV context boundary, and the full insert must fit target; assembly bounds-checks it (`existing_video_extension.py:923–929,978–1029,1361–1366`).

## CC-7 ambiguity inventory and exact replacement wording

1. **“Continuation” and request flag.** An implementer may preserve a second route or mistake the currently accepted flag for required intent. `request_v2.py` already represents placed media and preparation's uncovered tail; `research/continuation.md` records the old branch. Replace with: “A continuation is one video timeline item at frame 0 whose end precedes the requested canvas end. Do not add or retain a continuation route flag. CC-7d removes the legacy flag after caller/search and tests are migrated.”
2. **“Captured graph's active Existing Video path.”** Could port the `StartMaskedContext` wrapper and accidentally include T2V/I2V. The wrapper chooses between Existing Video and generated-starter latent (`existing_video_extension.py:1690–1758`). Replace with: “Port only `start_mode='existing_video'`: source frames/audio → ExistingVideoMaskedContext at insert 0 → prefix assembler. Do not port the generated-starter branch.”
3. **Prefix node identity.** The card leaves an answerable question open. Replace its “Before porting, check whether…” with: “Prefix is ExistingVideoMaskedContext with `insert_frame=0`; use the same context-node builder as inserts. Its output assembly differs: prefix uses AssembleExtension; interior uses AssembleInterior.”
4. **“One lowering for all three.”** Node schema shows a common context node only for prefix/insert; bridge has a distinct two-sided contract and output path. Replace with the three definitions in CC-7a/b/c above. Common helper reuse is optional; don't force a single graph branch abstraction.
5. **Offset lattice/refusal.** “Multiples of 17; 39+51k” conflates insert positions, context lengths and bridge preserved lengths. The node snaps off-17 input and permits 17-but-not-51 with audio rounding. Replace with: “Astrid rejects insert offsets unless divisible by 51 (thus also 17); no implicit snapping. Prefix context and bridge preserved intervals are 39+51k. Target H3 timeline length must separately satisfy its 5+17k video run.”
6. **Bridge wording and proof.** “Clip A, a 60-frame gap, clip B” is not a valid smallest bridge fixture when the gap means generated middle. The node requires the full target to be 5+17k, while each shared AV boundary context is 39+51k (`h3_masked_bridge.py:157–164,316–320,444–451`). Replace with: “Use two source clips, each contributing a 39-frame protected context, and a 63-frame generated middle: total target 141 frames. Verify the two exact source intervals, generated middle, bridge audio path and composition. Reject any timeline that cannot map both source contexts and the uncovered interval onto a valid H3 target.” The chosen intervals must be derived from actual placement ranges; don't silently enlarge or shrink the user's gap.
7. **Interior insert composition.** `ExistingVideoMaskedContext` alone does not produce pixel-exact interior source output; the pack marks `AssembleInterior` required because causal VAE decode differs (`existing_video_extension.py:1276–1335`). Replace with: “Every interior insert wires the node's snapped `insert_frame` and `preserved_frames` outputs into AssembleInterior, and uses the same crop/FPS/source mapping as context preparation. Deliver the original source pixels and PCM over the interval.”
8. **“One bounded, unchanged video prefix,” usable audio and grants.** “Unchanged” may be read as no adapter, no soft reference, or no generation anywhere. Separate source timeline permissions from model conditioning. Replace with: “The prefix's timeline video and audio are exact and have no grants that modify either stream. Soft image/video/audio conditioning may be present if independently admitted. Require source audio for this first port; a later audio-policy change is separate.” Existing adapter limitation currently says continuation unsupported (`shared/compile.py:858–862`), so don't infer admission from the abstract graph.
9. **“Effective references,” keyframe and size.** Could imply duplicate slots or hard-coded captured 0.5 MP behavior. Captured refs path binds one image into two slots or two separately (`research/continuation.md`, workflow refs); CC-7's intended graph has one effective reference while the captured duplicate is a known difference. Replace with: “Bind every declared reference once in declared order/tags; preserve speaker-video binding. Do not duplicate one image merely to fill two slots. Use the requested resolved canvas consistently for target latent, source decode/resize, assembler and mux. Record removed 0.5 MP selector as an intentional graph difference.”
10. **Audio context feather versus exact PCM.** Feathering is model mask behavior; it does not license changing delivered prefix audio. Node schema describes 8 ticks as the half-cosine release (`...cpu-runtime.json:1200–1227`). Replace with: “Use the captured 8-tick feather for model conditioning unless the task proves a different setting necessary. Composition still restores original prefix PCM exactly; never feather the delivered source audio.”
11. **“No audio,” “offset source trim,” refs and refusal timing.** “Stated result” is underspecified; bad combinations must fail before machine claim. Replace with explicit table admission/refusal: no source audio → reject with `prefix continuation requires source audio`; source trim/range not starting at the intended prefix origin → reject with a message to create an explicit timeline placement; prefix grant altering video/audio → reject naming grant and suggest separate jobs; unsupported timed guide → reject naming guide and reason. Add no hidden padding/silent substitution.
12. **Character Swap LoRA compatibility.** Current generated Character Swap compilation explicitly excludes continuation (`compile.py:858–862`), so the plan cannot claim the existing route already works. Mechanically, a LoRA in the model chain is upstream of sampling and the motion-context node edits the sampled latent; graph topology does not make the two inherently exclusive. Make compatibility an explicit CC-7a CPU graph case *only if CC-1's adapter-generalization is delivered*: “For a continuation request with Character Swap adapter, assert the Character Swap LoRA and FL2V Turbo LoRA are both connected in the intended model chain feeding the H3 sampler, while ExistingVideoMaskedContext conditions the sampled AV latent. Keep adapter reference order/tags. On CPU inspect emitted graph and manifest; make no inference-quality claim.” If CC-1 does not generalize the adapter path, refuse this combination in capabilities rather than pretending it works. CPU proof must use tiny inline mock graph assets and assert node/edge/model-chain plus reference manifest; do not load adapter weights or run ComfyUI.
13. **Captured workflow deletion/parity.** CPU fixtures prove graph structure and composition accounting, not visual/audio quality equivalence. `continuation.md` labels captures as wiring evidence only. Replace “keep until a live comparison passes, then delete” with CC-7d above and make the comparison a real prerequisite decision. Do not delete tests merely because their filenames mention workflows; retain runtime-declaration/bundle integrity assertions against the new authored graph.
