## Cross-case tension tests

These are disagreements the required independent reviewer should explicitly try to resolve, not new gap decisions:

1. **CAL-01 + CAL-02:** Durable creative edits and historical edit compatibility have different technical causes. Is their independently measurable user result the *same* reversible/editable-project outcome, or does one require distinct closure? A proposed gap must compare F-002, F-003 and AA-001, not simply aggregate two bugs.
2. **CAL-04 + CAL-12:** Spatial/identity control can be tested during a single supported creative operation; LS-004 is about a cross-modal *ecosystem*. Would a creator-facing control gap have its own primary vision goal and closure evidence, or is it a stage in AA-001?
3. **CAL-07 + CAL-16:** Real perceived generation latency can be independent from portability, while a meter's false positives have no such user evidence. Don't infer an independent speed gap solely from Plan 55's numerical KPI.
4. **CAL-13–15:** CA-002 and CI-002 are legitimate long-horizon gaps even if few fresh issues exist. F-005 and F-006 should remain distinct if local-vs-hosted custody demonstrably closes separately. A classifier that creates only from frequent issues, or merges all shared technologies, is unsound.
5. **CAL-08 + CAL-09:** Infrastructure failures can block contributor work yet still be specific bugs. The meaningful gap is the broader process or creator result, not a per-test “green” category.
