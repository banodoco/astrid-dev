# Tasks — Extensible timeline editing

[Plan](plan.md) · [Inputs](inputs.md)

A draft can use a short outline with unknowns. Before dispatch, every task needs one bounded outcome, its input and deliverable, dependencies, a suitable route, and focused proof. Name source identity where one task consumes another project's output. Reuse the prior-art and source identities in [inputs.md](inputs.md); don't repeat them.

**Task ids:** `CC-<n>` for phase 0 (the commit contract), `TL-<n>` for phase 1 (the command layer), `EX-<n>` for phase 2 (the extension proof). **Critical path:** phase 0 first (CC-7, CC-3, R0, about 9 to 11 elapsed days), then TL-1, RS1, TL-4, TL-5, TL-10, TL-12, R (about 25 elapsed days; see [below](#critical-path-and-estimates)). **Test inventory:** the existing test files this plan affects are listed [below](#test-inventory).

Paths: App paths are under `src/tools/video-editor/` unless they begin `scripts/`, `src/integrations/` or `config/`. "Agent" is astrid-agent, "Runtime" is astrid-runtime. Line numbers cite the template branch (`task/plan59-shot-trim`) and **will have moved after Release 14: re-check against the code at dispatch**.

Each `X` and `S` row gives its Starting N split and how many N helpers it launches. Proof is by counts and fixtures, never by a clock. Never copy content from the owner's timeline (`almost-ready.json` or realm data) into a fixture, a test or this plan: the repository is public, so only shapes and counts are recorded.

Limits: this proves the commit path is bounded and consistent on the corpus, not on every document a creator can make; wall time on the owner's timeline is recorded as evidence after CC-2, not gated.
