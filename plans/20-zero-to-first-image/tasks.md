# Tasks: zero-to-first-image onboarding

[Plan](plan.md) · [Inputs](inputs.md)

Routes: `N` is the default, `X` very hard, `S` super hard ([run contract](../../skills/astrid-dev-shared/run-contract.md#routing-and-bindings)). An `X` or `S` lead delegates reading, mechanical edits and running checks to `N` helpers, and keeps the judgment and the final change.

**Rules for every task:**

- Start only on the owner's go, and never before release 12 is published (Plan 29 owns `cand/29-r12`). App tasks check with Plan 29's orchestrator first.
- Write each new test first and see it fail on the base. Run only the selectors named here.
- Each task deletes what it replaces in the same change. The skill never gains a second copy elsewhere.
- **Step shape** (O1 defines it; every later step uses it): one command; the literal success check (a first line or a JSON field); and on failure, one fallback: run the installer's `--doctor` and give the user the file path. Don't try other fixes. Every Astrid command uses the launcher's absolute path (`docs/setup/SKILL.md:91-97`), never a bare `astrid`.

**Base.** Planning read Agent `origin/cand/29-r12` at `ff40f2c684` and App `cand/29-r12` at `3274a9c07`. Before O1, record the published release 12 revisions in [inputs.md](inputs.md#source-identities) and branch from those. Agent checks use `bash "$ENV/agent-pytest.sh"` ([env README](../../env/README.md)). App checks use `npx vitest run <file>` from the App checkout. The shared environment has no App script yet, so the first App task adds `env/app-vitest.sh` there if a cloud worker needs one.
