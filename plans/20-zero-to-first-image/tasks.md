# Tasks: zero-to-first-image onboarding

[Plan](plan.md) · [Inputs](inputs.md)

Routes: `N` is the default, `X` very hard, `S` super hard, `T` taste ([run contract](../../skills/astrid-dev-shared/run-contract.md#routing-and-bindings)). Most of this plan is text plus tests, so it is `N`, with wording split into small `T` tasks. The one `X` (P3.1) is justified in its row. An `X` lead delegates reading, mechanical edits and running checks to `N` helpers; a `T` lead makes its edits itself.

**Rules for every task:**

- Start only on the owner's go, and never before release 12 is published (Plan 29 owns `cand/29-r12`). App tasks check with Plan 29's orchestrator first.
- Write each new test first and see it fail on the base. Run only the selectors named here.
- Each task deletes what it replaces in the same change. The skill never gains a second copy elsewhere.
- **Step shape** (P1.1 defines it; every later step uses it): one command; the literal success check (a first line or a JSON field); and on failure, one fallback: run the installer's `--doctor` and give the user the file path. Don't try other fixes. Every Astrid command uses the launcher's absolute path (`docs/setup/SKILL.md:91-97`), never a bare `astrid`.
- **Taste rules for every `T` task:** plain words; one action per sentence, so a weaker agent can follow it; never claim what the product does not do; always a next step; no new scope. Proof is the exact before and after against these rules, plus the surface's own tests. Where the owner's taste decides (the consent wording, P2.4), Hannah sees the before and after.
- **Phase 1 describes only what is published.** The skill is read live from Agent `main`, so it may quote only behaviour in the published installer. P1.5 checks every quoted line against the published release 12 revision.

**Base.** Planning read Agent `origin/cand/29-r12` at `ff40f2c684`, Agent `origin/main` at `a105de3a48` and App `cand/29-r12` at `3274a9c07` (App `main` at `57e200b45` has the same brief lines at `copy.ts:163,280,307,322`). Before phase 1 merges, record the published release 12 revisions in [inputs.md](inputs.md#source-identities) and rebase onto them. Agent checks use `bash "$ENV/agent-pytest.sh"` ([env README](../../env/README.md)). App checks use `npx vitest run <file>` from the App checkout. The shared environment has no App script yet, so the first App task adds `env/app-vitest.sh` there if a cloud worker needs one.
