# Zero-to-first-image onboarding

**Vision gaps:** [Dependable creative execution](../../visions/gaps/F-003-creative-execution.md) (primary).

**Start here:** read [AGENTS.md](../../AGENTS.md), choose a workflow in the [skills guide](../../skills/README.md), follow the [run contract](../../skills/astrid-dev-shared/run-contract.md), and look up terms in the [glossary](../../docs/glossary.md).

Make the first useful result effortless: from an existing supported inference installation, one copyable command guides a person and their agent through setup to a generated image visible on an Astrid timeline. This is a top-priority upcoming draft; status, owner, and estimate live in the [project queue](../../README.md).

## Goal and scope

- Included: one excellent supported inference path, reusing current setup, connection, generation, media, and timeline capabilities; clear actionable prerequisite checks; matching agent instruction; focused recovery; measured agent effort.
- Also offer the full-stack sandbox path from [Plan 15](../15-openshell-safe-execution/plan.md), coordinating with [agent setup](../16-streamlined-agent-experience/plan.md) and [inference routing](../12-multiple-inference-routes/plan.md) where useful.
- Deferred: additional inference routes until the first journey is demonstrated; making every backend a prerequisite.
- Still undecided: supported starting environment, exact route, account/model prerequisites, and task breakdown, routes, and selectors. Scope these from current source before dispatch.

## What we build on

Reuse existing installation, connection, generation, media, and timeline capabilities where verified. The [extensibility philosophy](../../docs/extensibility-philosophy.md) calls for good defaults, understandable choices, and user control. Exact source identities and evidence limits belong in [inputs](inputs.md).

## Sequence

1. Establish the supported starting state and inspect existing onboarding and timeline paths.
2. Define the one-command journey, matching agent instruction, visible consent, and actionable prerequisite handling.
3. Prove a real image reaches the timeline, then cover named recovery paths and measure total token use including retries.
4. Demonstrate the full-stack sandbox variant and state its actual isolation boundary and granted access.

See [tasks](tasks.md) for the intended proof and the scoping still required.

## Completion

A new user can follow the short instruction from the declared starting state and see a real generated image on the timeline. Focused evidence covers the selected recovery paths, setup steps, interventions, and token cost; sandbox evidence covers the whole app/backend path and its stated boundary, with unsupported variants explicit. The roughly 50,000-token figure is a measured design target, not a recorded result. This draft does not authorize product work, compute use, or publication; follow the [shared run contract](../../skills/astrid-dev-shared/run-contract.md).
