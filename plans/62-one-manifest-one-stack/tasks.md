# Tasks — One manifest, one stack

[Plan](plan.md) · [Inputs](inputs.md)

**Routes** follow the [run contract](../../skills/shared/run-contract.md#routing-and-bindings). `N` covers everything below very hard, ordinary hard work included (Haiku or Luna). `X` is very hard (Sonnet or Terra), and `S` is super hard or the final review (Opus or Sol; the reviewer role is Opus or Astra). **Task ids:** `V0`, `V9`, then `V1` … `V8`, `R`, `V10`. V0 and V9 are listed first because `use` and `back` need both. **Critical path:** V0 → V1 → V3 → V4 → V6 → V8 → R → V10. V9 runs beside V0, and V2, V5 and V7 beside the path. **Test inventory:**
- astrid-app `scripts/installer/manifest.test.mjs` (pin.mjs);
- the Agent installer's launchd tests (V0), `test_absent_plist_still_rechecks_loaded_job_at_c1_bootout_boundary` among them;
- the Agent installer's source-ownership tests (V9);
- the Agent installer's manifest validation tests, if V3's first split finds that `app` is refused (re-check against the code at dispatch).

The tool's fixtures are new.

**How X tasks run:** the X worker writes its N split first, launches the independent N helpers at once, and checks what they return against the code. It keeps the decisions and the final edit, and reports how many N helpers it launched. Every task adds commits only and brings in a newer base by merging it ([run contract](../../skills/shared/run-contract.md#scope-source-identity-and-state)).
