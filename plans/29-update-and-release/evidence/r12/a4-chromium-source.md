# A4 Chromium source-only ownership note

This note records source inspection only; it does not establish the cause of CI run `42954826041` and does not propose a repair. No tests, CI, product changes or version changes were made in this inspection.

The CI setup installed Chromium `148.0.7778.96` (Playwright revision `1223`), but its versions artifact was inaccessible, so the launched-process identity was not independently verified. The inspected Chromium tag `148.0.7778.96` resolves to commit `8625e066febc721e015ea99842da12901eb7ed73`.

- The loader-side Mojo receiver registers `InterceptionJob::Shutdown` as its disconnect handler: [devtools_url_loader_interceptor.cc, lines 1038–1044](https://github.com/chromium/chromium/blob/8625e066febc721e015ea99842da12901eb7ed73/content/browser/devtools/devtools_url_loader_interceptor.cc#L1038-L1044). The client-side receiver also registers `Shutdown`: [lines 1632–1636](https://github.com/chromium/chromium/blob/8625e066febc721e015ea99842da12901eb7ed73/content/browser/devtools/devtools_url_loader_interceptor.cc#L1632-L1636).
- `CompleteRequest(status)` calls `client_->OnComplete(status)` and then `Shutdown`; `Shutdown` itself removes the interception job and deletes it: [lines 1780–1789](https://github.com/chromium/chromium/blob/8625e066febc721e015ea99842da12901eb7ed73/content/browser/devtools/devtools_url_loader_interceptor.cc#L1780-L1789). Thus the interceptor's disconnect handler can remove the job without that function itself calling `OnComplete`. This is not proof that a network terminal event cannot be emitted elsewhere.
- A later lookup for a removed job can return `Invalid InterceptionId`: [interceptor header, lines 240–247](https://github.com/chromium/chromium/blob/8625e066febc721e015ea99842da12901eb7ed73/content/browser/devtools/devtools_url_loader_interceptor.h#L240-L247). `FetchHandler::FailRequest` delegates to the interceptor: [fetch_handler.cc, lines 204–221](https://github.com/chromium/chromium/blob/8625e066febc721e015ea99842da12901eb7ed73/content/browser/devtools/protocol/fetch_handler.cc#L204-L221).
- `NetworkHandler::LoadingComplete` emits `loadingFailed` or `loadingFinished` from a `URLLoaderCompletionStatus`: [network_handler.cc, lines 3658–3682](https://github.com/chromium/chromium/blob/8625e066febc721e015ea99842da12901eb7ed73/content/browser/devtools/protocol/network_handler.cc#L3658-L3682). No claim is made that this one handler accounts for all terminal event paths in Chromium.

The CI diagnostic recorded a `Fetch.failRequest` rejection crossing a main-frame commit and no observed internal-CDP terminal for the correlated request. It did not retain the rejection text or record the Mojo disconnect and therefore does not prove that the source path above caused the failure. A locally reproduced stale abort had an `Invalid InterceptionId` classification, but that local result cannot identify CI's error.

The documented target/session detach notifications identify target or session lifecycle, not a per-request completion. CDP durable response storage retains received bytes across process navigation; response streaming exposes received data, not bytes never received. CDP Fetch response-body takeover requires the client to cancel or provide a replacement response, so it is not a demonstrated transparent preservation mechanism. The earlier real pagehide, interrupted-body and independent-CDP-session evidence remains in the separate A4 evidence records.

Under the existing requirement for genuine terminal events and complete observed response bodies, these source facts do not supply a supported mechanism proven to handle both late pagehide and interrupted streaming. No lifecycle inference should be counted as a real terminal, and the incomplete-scan outcome remains fail-closed.
