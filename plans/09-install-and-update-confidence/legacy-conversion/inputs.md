**Approach:** Extend the existing installer with one explicitly authorized conversion adapter and narrowly necessary Runtime custody/recovery support. Reuse the existing journal and update engine; preserve normal source/R0 refusal paths. The conversion distinguishes historical source provenance (unknown in the incident) from present OS/workspace custody (must be established). A new recovery policy must authorize that distinction explicitly; it must not manufacture an old `Version`, change a release number, impersonate Pinokio, suppress a guard, or treat a missing process as ownership proof. Stage a clean candidate and an independently pinned compatible recovery installation before stop. Reuse a release's own compatible bootstrap for recovery rather than adding a general cross-version command translator. Initial qualification is macOS and the supported schema31 legacy family from this incident. Other OS/version combinations continue to refuse until qualified.

Source: owner messages summarized in Scope decision. Enforced by LC-6/LC-8/LC-9. No fallback to an empty workspace or sibling `-r1` root.
- **D2 — Actual latest standalone outcome. Decided, 12 November 2026:** no Pinokio dependency; latest official qualified installer/release and functioning hosted timeline. Source: owner requests to update outside Pinokio and build the transition tool. Enforced by LC-8/LC-11. A preview is not completion.
- **D3 — No guard bypass or hand-run migration. Decided, 12 November 2026:** the installer owns adoption and migration; directory refusal is respected. Source: owner installation constraints. Enforced by LC-1/LC-2/LC-6 and unchanged ordinary refusal tests.
- **D4 — Recovery-adoption trust policy. Pending, consequential product decision:** recommend an explicit installer recovery mode that records historical loaded-code provenance as unknown, requires the current OS user's authority plus independently established exclusive workspace custody and complete recovery, and never blesses that unknown code. Alternative: admit only authentic managed legacy installations, which is smaller but does not solve this incident. LC-1 must produce the exact admissibility table and refusal evidence for review; if the incident class cannot be safely admitted, stop that feature before later implementation expands. This policy is not implied by consent alone.
- **D5 — Initial platform breadth. Planning assumption derived from the request:** macOS plus the concrete legacy schema31 family first; other platforms/version families retain current refusals. The owner asked to fix this Mac, not for a new all-platform release project. Broader qualification remains Plan09/30 work; expanding it needs a scope decision. This is not a reason to ask the owner to repeat the original goal.
- **D6 — Review budget and publication. Pending:** adopt the recommendation above when execution is authorized. Official publication and live apply remain separate steps; this plan does not assign a release number or override current release sequencing.
