**Review proposal:** RS1 one round after the model becomes load-bearing, R one final round. Both require the owner's agreement and actual reviewer identity at run start; review findings become their own bounded rows. R cannot be used to self-approve changes to shared checks.

**Worker setup and commands:** tasks operate in `astrid-dev` only and use its standard-library environment; see [env/README.md](../../env/README.md) if the worker session needs setup. A worker in this repository should use existing `scripts/` commands; no archive download, second repo, live GitHub request or new environment script is needed for the core work. On a clean, pinned checkout the load-bearing qualification commands are:

```sh
python3 -m unittest discover -s scripts -p "test_*.py"
python3 scripts/astrid_dev.py list
python3 scripts/astrid_dev.py check
python3 scripts/astrid_dev.py sync
python3 scripts/export_public_vision.py --revision <fixed-40-hex-sha> --output /tmp/vision.json
```

For feed parity, run the exporter with **the same fixed revision argument** on original and candidate source trees and compare bytes; do not count changing revision metadata as an intentional output difference. Run sync only in an isolated clean checkout and inspect its diff. Actual tests were not run as part of this planning-only project creation; source and candidate receipts belong to the authorized implementation run.
