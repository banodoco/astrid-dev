## Contract-card impact and boundaries

**MS-1/MS-8 intentionally supersede these old assertions, subject to explicit approval:** `scripts/test_workstreams.py` assertions that a workstream's canonical file is `SKILL.md` or must be `# Workstream: …`; `PARENT_SKILLS` registration and generated role-index markers; `scripts/test_skill_installer.py` assertions that installed symlinks target the old grouped authored packages or the `shared` pseudo-package; and `scripts/test_views.py` expectations of role/shared indexes. Preserve the semantic checks (description, actual procedure, duplicates, ownership and fail-closed validation) in new tests, and enumerate each assertion by exact test name at dispatch. Do not simply delete coverage.

**Do not change verdicts merely for ease of migration:** `markdown-links`, `link-anchors`, `workstream-structure`, `generated-views`, `scripts/test_golden.py` and protected document CI remain active. If a checked oracle is legitimately incompatible with the agreed new format, the task owner records failing-before behavior and the narrow replacement assertion first; no broad relaxation or expected-green rewrite.

**MS-2/MS-3 security and safety decisions:** a metadata flag never adds authority; no resolution may walk outside the intended repository checkout unnoticed; generated outputs are derived, not manually editable; stale cleanup is limited to entries owned by this repository; no install overwrites a foreign destination. Packaging must preserve at least the real run contract, a role-owned guide and an executable guide's relative paths when loaded through the installed entry point. Probe Windows symlink limitations rather than assuming POSIX behavior generalizes.

**MS-7 live-path sweep:** search fixed and generated references in `skills/`, `scripts/`, `docs/`, `templates/`, `releases/`, `plans/`, `env/`, README and contributing instructions, including fenced commands and references to `SKILL.md`. Active Release 14 mailboxes and packet instructions are not rewritten in place by a running worker; the cutover date and owner are a separate D5 decision. Search product repos for actual consumers, but report rather than edit other repos without authorization.

**Load-bearing proof order:** baseline the named current tests on the actual starting SHA; prove MS-1/MS-2 fixture behavior before RS1; prove each changed parser/installer/check after its card; run one full inventory on the integrated CI head before final review, with comparisons by named failing test, not counts or wrapper success. No hosted CI duplication just to show repeated success.
