**Approach:** Create a new project rather than reopen completed Plan 51: retain its one-home-per-rule policy and the reusable parser/view infrastructure, but eliminate authored skill packages and two document formats. Generate package directories from source frontmatter; derive names from filenames, package only necessary references, and replace the installer/validator assumptions. Keep role and shared-workstream ownership clear without introducing a new framework or database. The [CA-005 gap](../../vision/gaps/CA-005-parallel-contribution.md) already measures simpler contribution and extensions; this project supplies another scoped part of that outcome but not the concurrent-contributor proof.

The manager must report a precise blocker if no independent reviewer can be commissioned.

**Proof and limits:** Proposed, not run. Test negative cases and stale/foreign paths. Do not infer Windows symlink compatibility, portable standalone archives, or CA-005's ten-contributor outcome from an ordinary Unix build.

Default role-specific docs have no `skill: true`; adding it later must also preserve parent-role authority.
- **D4 — How generated skills reach referenced files (open, design choice):** *Recommend:* prove a minimal checkout-based package with correct links to canonical references, no duplicated rule bodies, and safe traversal; if directory symlinks fail on a supported target, use a tested copy/materialization fallback rather than shipping broken links. No claim of Windows support without a test.

Prefer these over teaching `sync.sh` another mode. Confirm after a small CLI fixture shows the smaller choice isn't sufficient.
