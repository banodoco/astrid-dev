This project is moved to Plan 73 without changing its scope, tasks or execution authority; the earlier scope proposal remains traceable in [PR #1062](https://github.com/banodoco/astrid-dev/pull/1062). Renumbering is a repository-integrity repair, not a project implementation task.
- **D1 — Authored format and opt-in (direction chosen 20 Nov 2026):** one Markdown source per agent instruction, optional `skill: true`, a short `description` and generated standard `SKILL.md` packages. No separate manually maintained skills. This direction is accepted for drafting, not an implementation go.
- **D2 — Naming and roles (direction chosen 20 Nov 2026):** derive `astrid-dev-<filename-stem>` from the source filename; call the four role identities **Leader, Orchestrator, Manager and Worker**. The proposed main skill is `astrid-dev-start`. No aliases. Confirm the deliberate entry-point rename at greenlight.
- **D3 — Ownership (direction chosen 20 Nov 2026):** role-specific workstreams beside each role; reusable workstreams in `agent/shared/workstreams/`; standing role definitions in single `leader.md`, `orchestrator.md`, `manager.md` and `worker.md`. Default role-specific docs have no `skill: true`; adding it later must also preserve parent-role authority.
- **D4 — How generated skills reach referenced files (open, design choice):** *Recommend:* prove a minimal checkout-based package with correct links to canonical references, no duplicated rule bodies, and safe traversal; if directory symlinks fail on a supported target, use a tested copy/materialization fallback rather than shipping broken links. Alternatives: recursive self-contained bundle (costly duplication and risk of recursion) or unconditional absolute paths (nonportable). Record fixture and real-install outcomes before choosing. No claim of Windows support without a test.
- **D5 — Cutover and historical paths (open, operational choice):** *Recommend:* rewrite active docs, templates, scripts and Release 14 run guidance in one integrated change, then tell active owners the exact new paths; leave historical evidence truthful by linking immutable revisions where needed. No long-lived compatibility aliases. The owner decides when active agents can switch.
- **D6 — Command surface (proposed):** `skills build`, `skills check`, `skills install`, `views generate`, plus existing `check` and `list`. The built packages are gitignored. Prefer these over teaching `sync.sh` another mode. Confirm after a small CLI fixture shows the smaller choice isn't sufficient.
- **D7 — Project integration and review (pending):** Recommend one new scope-review PR without touching `plans/priority.md`, owner review of the 8–12 day provisional estimate, one `RS1` and one final review round, and separate run/merge go after greenlight.
