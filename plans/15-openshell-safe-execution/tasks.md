### Sequencing and constraints

A–E and L can start as read-only investigations in parallel; do not assume an independent implementation writer for shared launcher/policy files. Agree one owner and landing order for shared policy/service catalog, guest mode/instance/lifecycle contract and onboarding choices. D and L can independently investigate their surfaces; agree the authenticated status/start/stop interface before dependent UI and host implementation, and keep one writer for shared launcher code. The security/compatibility design review precedes implementation of its dependent surfaces; F requires the integrated candidate, qualified platform and approved proof route. A mount-free attached ComfyUI proof need not wait for a separate GPU worker or universal custom-node compatibility. An agent unavailable in the VM must say so; it may not fall back to native. First qualified opt-in does not require universal agent/platform parity or automatic wake/idle shutdown. A later default recommendation is separately gated by measured usability, security and performance on each platform and owner approval; do not change defaults in this draft.

Keep native and strict modes separate. The connected profile is an explicitly accepted host service exception, not equivalent to the strict profile. Avoid broad refactors just to increase parallelism. Scope overlapping active work with [onboarding](../20-zero-to-first-image/plan.md), [agent setup](../16-streamlined-agent-experience/plan.md), [generation placement](../32-generation-placement-targets/plan.md) and [inference routing](../12-multiple-inference-routes/plan.md) at their actual shared contracts. No release changes or product execution under this draft; follow the [run contract](../../agent/shared/run-contract.md).
