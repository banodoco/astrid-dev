# Tasks — The renderer works end to end

[Plan](plan.md) · [Inputs](inputs.md)

These are proposed task cards, not dispatch authority. Every source path and symbol must be re-checked against the code at dispatch. The donor commits were written against `83d5f8fe`; `release/15/main` is 597 commits ahead of it.

**Task ids:** `RN-n`. **Critical path:** RN-0 → RN-1 → RN-3 → RN-4 → RN-5, RN-6 → RN-10. RN-7 and RN-11 start on day 1 beside RN-1.

**The rule for every task from RN-2 on:** after the change, the short contract render (RN-11's fixture, a few seconds) must complete and match its expected frames. The film-shaped fixture variant is rendered whole at three milestones: after RN-3, after RN-6, and before RN-10. A milestone render that fails stops the next task.

**What "matches" means:** frames are compared with the editor's frame at the same time, never with an earlier render. A render made with a stopgap is not a reference.

**Test inventory:** `tests/integrations/test_generic_host_remotion_render.py` (real Runtime and pack host, executes `rendering.render`), `tests/packs/rendering/test_remotion_backend.py` (a real 12-frame render), `tests/packs/rendering/test_managed_timeline_render.py`, `tests/core/rendering/test_managed_asset_identity.py`, `tests/core/rendering/test_remotion_host_regressions.py`, `tests/core/rendering/test_remotion_registry_context_key.py`, `tests/packs/rendering/test_remotion_v3_aliases.py`, `tests/core/test_subprocess_env.py`, `tests/fixtures/packs/astrid_motion/` ([CI facts](evidence/eff/ci.md)).

## Dispatch notes

- **Where the fixture builder lives.** At filing it is on the App's `release/15/plan-77` branch (`scripts/save-loop/`). It may have landed on `release/15/main` or `main` by the time this runs. At dispatch, look there first and use the landed copy; fall back to the plan-77 branch only if it has not landed. Record the commit used.
- **The donor branches are evidence.** `release/14/r6-fixes` supplies six commits to cherry-pick. `release/14/r6-render-stopgaps` shows what each remaining fix has to achieve and is not ported, apart from the two tracked experiments.
- **Experiments are tracked, not hidden.** The plan branch keeps a short note listing each experiment commit still present (`b051e8cc`, `7265aa5d`) and the task that removes it. The branch is not offered for merge while the note is non-empty.
- **Reset, do not repair.** If a failed render leaves the stack refusing work, run RN-0's reset procedure and continue. Do not fix recovery in the product here; add what you saw to [#1514](https://github.com/banodoco/astrid-dev/issues/1514).
- **Estimates are provisional.** Re-estimate after RN-7's first finding and after the first whole-fixture attempt in RN-10.
- **Routes:** N tasks go to the normal tier; X to the extra-hard tier with named helper subtasks for reading and running; S to the super-hard tier.
