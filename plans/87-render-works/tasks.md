### Journey fixture and proof

RW-7 reuses production startup/install routes in a temporary realm: a 3 s, 30 fps, 480×270 timeline, about 200 KB of media, built-in element, real-installed personal collection motion element (`am-burst`), admitted project element where the branch supports it (otherwise a named skip), real imported image/video, two resolvable word-anchored shot clips over timed narration, editor-style redundant locators in an unused entry, dark caption on a cream plate, and fade with explicit easing. Each element paints a known corner. Use real import, project-pack admit, SDK commit, swap and narration ripple; render through the actual command worker.

Assert Runtime completion/registered output, ffprobe's 90 frames/size/audio stream, expected pixels at 0.5/1.5/2.5 s, resolved anchor offset, at least one acknowledged heartbeat, and cleaned attempt scratch. Producer `complete:100` alone is not completion. Negative cases name the actual first failing boundary: foreign locator, changed root/revision after validation, unsupported animation input, word move without narration, worker killed then recovery/next admission. A tiny render cannot prove long-term liveness: RW-11/RW-23/RW-31 add loaded, rapid-helper and resumed-seam cases.

Build and run the journey by workflow_dispatch before relying on it; land it green. Proposed CI: Linux pull requests touching rendering/execution/pack/Remotion/Runtime pin surfaces; Linux/macOS, installed/source on release-main pushes. Do not infer required GitHub settings from workflow triggers. Reuse existing startup and render tests rather than introduce a parallel harness.

### Dispatch contract and focused commands

From each Agent task checkout use literal `bash /opt/astrid-dev/env/agent-setup.sh` and `bash /opt/astrid-dev/env/agent-pytest.sh -q <named test file or selector above>`; Runtime cards use `bash /opt/astrid-dev/env/runtime-setup.sh` and `bash /opt/astrid-dev/env/runtime-pytest.sh -q <named selector>`. The shared environment fetches public git at the checkout's exact pins. Existing in-repo copies under `scripts/worker-env/` may be used as the shared environment documents. App cards use `bash /opt/astrid-dev/env/app-test.sh <named file>` after selecting its actual existing test. Proposed files must exist before a test command is dispatched. Local baseline includes only the card's named tests.

Cards that alter a contract (RW-2/3/5/11/20/23/24/25/27/30/31) must list the exact existing test/fixture/oracle lines invalidated before implementation: parity assumptions, empty/unset contexts, environment roots, unresolved-word signatures, first-claim/heartbeat expiry, full-list observation, capture eligibility/terminal proof, verified session release, easing support, queued intent and checkpoint reuse. This draft does not waive pinned assertions. Re-check against code at dispatch; any unlisted invalidated invariant blocks that change until the card is corrected. Reconcile the syntax-tree archive assertion into behavioral parity; never weaken custody fencing or reclassify LIVE as terminal to obtain a pass.
