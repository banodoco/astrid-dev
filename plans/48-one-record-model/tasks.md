# Tasks — One model for astrid-dev's records, checks and generated pages

[Plan](plan.md) · [Inputs](inputs.md). Draft, not authorization to dispatch.

Routes: **N**, **X**, **S**, **T** per the [run contract](../../skills/astrid-dev-shared/run-contract.md). X and S tasks delegate reading, mechanical edits and checks to N helpers.

**Where work lands.** Every task lands by PR on `int/48-one-record-model` in astrid-dev, cut from `main` when the run starts. Record each task's base SHA when it starts. Only astrid-dev changes.

**Critical path:** PM-1 → PM-2 → RS1 → PM-6 → PM-7 → PM-11 → PM-12 → R. PM-3, PM-4 and PM-5 run in parallel after PM-1; PM-8, PM-9 and PM-10 in parallel after PM-6; PM-13 and PM-14 in parallel after PM-12's model lands.

**Test inventory** (every file is affected; all are standard-library `unittest`): `scripts/test_check_docs.py`, `test_check_completion.py`, `test_check_gap_boundaries.py`, `test_check_project_planning.py`, `test_claim_project.py`, `test_review_intake.py`, `test_export_public_vision.py`, `test_project_contract.py`, `test_gap_relationships.py`, `test_vision_subject.py`, `test_model_usage.py`.

**Checks a worker can run** (astrid-dev only, no other repository, no network):

```text
python3 -m unittest discover -s scripts -p "test_*.py"
python3 scripts/check_docs.py
python3 scripts/export_public_vision.py --output /tmp/vision.json
```

**Two standing proofs** used by most rows:

- **Same verdicts:** on the task's base and its candidate, the old commands and `astrid_dev.py check` print the same errors for (a) the clean tree and (b) each broken fixture already in the test files.
- **Same feed:** `export_public_vision.py --revision <one fixed SHA> --output` gives byte-identical JSON on base and candidate.
