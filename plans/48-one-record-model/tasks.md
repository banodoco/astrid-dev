Routes: **N**, **X**, **S**, **T** per the [run contract](../../skills/astrid-dev-shared/run-contract.md). X and S tasks delegate reading, mechanical edits and checks to N helpers.

**Where work lands.** Every task lands by PR on `int/48-one-record-model` in astrid-dev, cut from `main` when the run starts. Record each task's base SHA when it starts. Only astrid-dev changes.

**Critical path, Phase 1:** PM-0 → PM-1 → PM-2a → PM-2b → PM-3 → PM-4 → PM-5t → R1. This is one dependency chain: run it in one checkout on one task branch, in order, pushing after each task. Only PM-5 is independent; it may run beside the chain in a second checkout. **Phase 2:** PM-6 → PM-7 → R, with PM-8 and PM-9 in parallel after PM-6. Phases 3 and 4 (PM-11 to PM-15) are proposed only and start only if owner decision D7 accepts them.

Affected: `scripts/test_check_docs.py`, `test_check_completion.py`, `test_check_gap_boundaries.py`, `test_check_project_planning.py`, `test_claim_project.py`, `test_review_intake.py`, `test_export_public_vision.py`, `test_project_contract.py`, `test_gap_relationships.py`, `test_vision_subject.py`. **Checks a worker can run.** The worker's attached repository is astrid-dev itself, the scripts are standard library only and need no other repository or network, so no `env/` setup script applies:

```text
python3 -m unittest discover -s scripts -p "test_*.py"
python3 scripts/check_docs.py
python3 scripts/export_public_vision.py --output /tmp/vision.json
```

**Two standing proofs** used by most rows:

- **Same verdicts:** PM-1 first commits a set of small fixture trees under `scripts/fixtures/` (one clean, one per broken case the unit tests cover today as inline strings). On the task's base and its candidate, the old commands and `astrid_dev.py check` print the same errors for the real tree and for each fixture tree. In Phase 1 the old `check_*.py` modules stay importable as thin shims, so no existing test or trusted-workflow import changes.
- **Same feed:** `export_public_vision.py --revision <one fixed SHA> --output` gives byte-identical JSON on base and candidate.

## Phase 1 dispatch notes

Choices already made, so no worker has to ask:

- **Where code lives:** new modules sit flat in `scripts/`, beside the tests, because CI discovers tests with `-s scripts`. Standard library only.
- **Hard tasks write the test, normal tasks pass it.** PM-0 and PM-2a produce the tests; PM-1, PM-2b, PM-3 and PM-4 are done when those tests and the feed comparison pass. A worker never edits `golden.txt` or an existing test to get green; if it believes one is wrong, it stops and asks the manager.
- **Same feed:** run `python3 scripts/export_public_vision.py --revision 0000000000000000000000000000000000000000 --output <file>` on the task's base and on its candidate; the two files must be byte-identical.
- **The three PR gates** (completion, gap boundary, planning evidence) need a git base and a PR description, so the golden file does not cover them. Their existing unit tests do, and stay unedited through Phase 1.
- **PM-4's source file** is `vision/intro.md`, holding the Ambition and "Build Astrid with us" text under those two headings.
- **Marker:** an HTML comment on the first line of a generated file, or around a generated region, naming the view and its sources. PM-3 picks working text; PM-5t settles the wording.
- **Old entry points keep working** through Phase 1 (`python3 scripts/check_docs.py` and the rest), because skills, briefs and other runs call them. PM-10 removes them in Phase 2.
- **Landing:** task branches merge into `int/48-one-record-model`. astrid-dev `main` requires a pull request and the `documentation` and `vision-consumer-contract` checks. Progress updates to this file go to `main` as their own small PRs with auto-merge on. Nothing else reaches `main` before R1.
- **Not in Phase 1:** any change to `plans/index.md`'s role, the claim bot, review intake, `strategy.md` or the release template.

Before Phase 2 is dispatched: an ambiguity pass by N helpers, and a re-plan of its cards against what Phase 1 actually built and against Plan 31 if that started first.
