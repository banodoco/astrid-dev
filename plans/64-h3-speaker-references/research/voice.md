# H3 voice-reference findings

Read-only research against the requested release-14 plan-59 source, VibeComfy pin/cache, ComfyUI `6bfaacc`, H3 model card, spec #890 and Hivemind. The evidence separates what the implementation feeds to the model from what is documented as a capability and what still needs a generation run.

## 1. Do reference soundtrack or standalone audio condition generated speech voice?

**Evidence.** At ComfyUI [`nodes_minimax_h3.py`](https://github.com/comfyanonymous/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L242), `MiniMaxH3ReferenceToVideo` accepts up to three paired video soundtracks and three standalone audio clips (lines 272–283). Each soundtrack is matched to its same-numbered video (313–318); the prompt presentation receives an `<Audio n>` item before that `<Video n>` (333–340). If `audio_vae` is connected, `_encode_ref_audio` encodes the waveform (74–81), and the paired soundtrack is added to the video reference block as `audio_latent` (343–349); a standalone clip is added as an audio reference block (351–357). Without `audio_vae`, the schema tooltip explicitly says reference audio “only conditions the text encoder” (261), and no audio reference latent is added. The native workflow supplies the audio VAE: `generation.py:271–275` on `origin/release/14/plan-59` loads `minimax_h3_audio_vae_fp32.safetensors`, and the builder connects it to `audio_vae` in the target call at `generation.py:375–376`.

The official [MiniMax H3 model card](https://huggingface.co/MiniMaxAI/MiniMax-H3) lists reference-to-audio-video and audio-to-audio-video among its supported tasks and specifies up to three 2–15-second audio clips. Its prompting guidance includes an example that explicitly identifies `<Audio 2>` as a “voice timbre reference” and asks the generated subject to speak new dialogue in that timbre (model card README, prompt example). This supports the intended voice-reference use, not a guarantee of a perfect voice match in every sample.

Hivemind message `1535652366978781244` (Dannidee Parker, `minimax_h3_chatter`, 2026-08-08) says: “I'm messing with turning minimax into a voice generator for giggles. Works pretty good at generating voices and maintaining them.” This is a general anecdote about maintaining generated voices; it does not report a controlled reference-voice test.

**Verdict: resolved yes, as a supported conditioning capability.** With `audio_vae` connected, both a video’s soundtrack and a standalone clip are encoded into reference-audio latents, and the model card expressly describes voice-timbre reference prompting. Pairing the soundtrack with a visual `<Video n>` also exposes it as `<Audio n>`; standalone audio is a direct, cleaner choice when only voice is wanted. A no-VAE graph only gives the text encoder the audio tag/context and does not pass an audio latent. Fidelity for a particular speaker and dialogue remains sample-dependent and is not proven by code or the anecdotal Hivemind post.

## 2. Reference limits and interaction with the 17-frame step

**Evidence.** The core ComfyUI schema at `nodes_minimax_h3.py:263–283` allows 9 images, 3 videos, 3 standalone audio clips; it labels reference videos and audio as 2–15 seconds. The official model card adds a combined limit of 12 files and a total-duration cap of 15 seconds for all video references combined and separately all audio references combined. Paired soundtracks are additional audio-bearing references in the node interface; the model card wording describes file-count and modality duration totals, so do not assume a combined video-plus-audio duration budget beyond that text.

The node’s output `length` is a 24 fps frame count, UI step 17; valid model frame counts follow `17k+5` (5, 22, 39, …, 124, …, 362). The native node aligns the requested output up to that grid (`align_frame_count`, lines 37–50); the schema tooltip says trained output range is about 124–362 frames (about 5–15 seconds), longer untested (265–266). For each reference video, execution first truncates decoded frames to the generated `frame_count`, then trims the remaining clip down to `17k+5` frames (325–332). Thus long references are shortened to at most target length and then possibly by up to 16 frames; at least 5 frames must remain. The 17-step is a frame-count grid, not a requirement that each source reference be exactly a multiple of 17 seconds/frames. H3’s model card’s 2-second minimum is stricter than the node’s internal 5-frame minimum, so use the model-card range for supported inputs.

The native request composer caps video references at three (`generation.py:266–268`); request normalization assigns `<Video n>` / `<Audio n>` labels per modality (`request_v2.py:357–390`). VibeComfy pins the motion/context node pack at `custom_nodes.lock:31–39`, commit `361624fb406b63eb6694442eac6c895fc1533a70`; its cached schema is `vibecomfy/porting/cache/object_info/ComfyUI-H3-Motion-Context-MultiRef@cpu-runtime.json`.

**Verdict: resolved yes.** Use up to 3 video refs, each 2–15 seconds and 15 seconds total; up to 3 audio refs, each 2–15 seconds and 15 seconds total; up to 9 images; 12 files total. Generated length uses the `17k+5` frame grid. Reference video frames longer than the requested generated length are truncated, then rounded down to that same valid frame grid.

## 3. VRAM and time for 2–15 second video references on 32 GB RTX 5090

**Evidence.** The H3 node says reference tokens are carried through every sampling step and that the `ref_image_size="max"` choice can be “several times slower” for image references (`nodes_minimax_h3.py:266–267`); this warns of cost, but does not quantify video-reference overhead. The execution code keeps the reference video VAE latent as a reference block (`343–349`), so longer retained clips add reference tokens, but source code cannot predict peak VRAM or wall time for the specified GPU, model, resolution, sampler, steps, and attention setup.

Hivemind search for 5090/H3/reference video and VRAM found no report giving both a video-reference duration and measured memory/runtime on an RTX 5090. Search surfaced general or unrelated H3 machine reports, not evidence for this specific workload. The lone relevant general performance anecdote found was Ryko’s `top_gens` repost (message `1535827850257637376`) of a 3090 24 GB run: “1344x768, 2,127 second generation time”; it does not say that a reference video was used and is not transferable to a 5090. The Hivemind anecdote `1572458663342514207` mentions a 5060 Ti video INT8/CONVROT setup using under 14 GB, but concerns H3 image generation, not reference video. Neither answers this question.

**Verdict: still unknown.**

**Cheapest way to resolve it:** one controlled GPU spike on the exact 32 GB RTX 5090 runtime and pinned graph/model, with one 24 fps 768p reference video and otherwise fixed generation settings. Compare a 2 s reference at a 5 s target (124 frames) with its no-reference baseline, then a full 15 s reference at a 15 s target (362 frames) with its matching no-reference baseline. Keep prompt, model, 8 steps, sampler, VAE, and attention flags fixed. Record peak allocated/reserved VRAM and end-to-end seconds for each pair, plus whether the input was truncated to target length. This avoids mistaking a 15 s input cropped to a 5 s target for a full 15 s reference measurement. No machine claim can be made from the available research evidence.
