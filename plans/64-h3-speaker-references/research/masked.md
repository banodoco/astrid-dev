# Masked edit + speaker reference: findings

Read-only research against `origin/release/14/plan-59`, the pinned ComfyUI and motion-pack sources, VibeComfy's cached node schema, and hivemind. No tests or GPU runs were performed.

## 1. Do native masked edits pass speaker references through `MiniMaxH3ReferenceToVideo`?

**Verdict: resolved no, for `ref_videos` and `ref_audios` in the current Astrid compiler.** The intended conditioning route is the normal `MiniMaxH3ReferenceToVideo` node, not a separate speaker-reference path, but today's source-backed compiler only binds image references and therefore does not deliver speaker video/audio references to it.

Evidence:

- In `generation.py:367-376`, Astrid constructs `MiniMaxH3ReferenceToVideo` with `positive` and `LATENT` outputs. `generation.py:432-450` then passes the target latent through `H3V2VGranularFractionalDenoise`; `generation.py:456-457` gives the sampler `target.positive`. Thus masked V2V adds source latent preparation/denoising after the ordinary H3 conditioning node; it does not replace that conditioning route.
- But `compile.py:614-620` rejects more than two references and binds each as `reference_N` image input; `compile.py:662-670` passes only those image bindings into the workflow call. The builder supports video refs (`generation.py:237`, `346-364`) but this compiler call does not populate `video_references`; there is no `ref_audios` loading loop in the builder. The H3 request parser does create `<Video n>` / `<Audio n>` tags (`request_v2.py:377-385`), but parsing tags is not graph binding.
- The pinned ComfyUI node at commit [`6bfaacc`](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L242-L359) has `ref_videos`, paired `ref_video_audios`, and `ref_audios` inputs; its execute method at lines 313–359 builds video/audio reference blocks and attaches them to positive conditioning. Astrid's V2V node receives the `LATENT` output while the sampler receives that positive conditioning, so adding the missing bindings would use the ordinary node path.
- Astrid's pinned custom node is recorded at `generation.py:302-307` (commit `361624fb406b63eb6694442eac6c895fc1533a70`). VibeComfy's matching cached `H3V2VGranularFractionalDenoise` schema labels `source_audio` and `audio_strength`, but contains no speaker reference conditioning input.

Cheapest way to resolve the remaining practical question (whether a newly wired video/audio speaker reference has the intended effect): one GPU spike with one 3-second, 24-fps source close-up, a mouth/lower-face mask, one 3-5-second speaker video reference with soundtrack (or one standalone voice clip), the literal line in the prompt, and otherwise the current masked-edit settings. Inspect both the voice and mouth motion. Current behavior does not yet wire those reference inputs, so this requires the minimal graph/compiler binding first.

## 2. What does `audio_strength` do, can it target only the line, and can composition restore source sound?

**Verdict: resolved.** Zero freezes/preserves the source audio latent; one fully denoises/regenerates audio. The node applies one constant value over the whole target audio latent, not a time mask. Astrid's compositor can select generated audio only in a declared interval and source audio elsewhere, but audio inside the generated interval—including room tone around the speech—is regenerated by H3.

Evidence:

- The pinned motion-pack implementation [`h3_v2v_fractional.py`](https://github.com/seitanism/ComfyUI-H3-Motion-Context-MultiRef/blob/361624fb406b63eb6694442eac6c895fc1533a70/h3_v2v_fractional.py#L260-L283) says source audio is preserved at strength 0 and fully regenerated at 1. Its `prepare` method constructs `audio_mask` as a full tensor of the scalar `audio_strength` across all audio latent steps (`lines 371-424`), while only video has inside/outside spatial masks. There is no audio interval or temporal audio mask input.
- Astrid currently hard-codes `audio_strength=0` (`generation.py:445-450`) and rejects masked-edit audio regeneration when no fixed replacement clip is supplied (`compile.py:541-547`). Its source-backed-edit instructions also say the current replacement-audio path holds strength at zero and splices the fixed clip (`docs/SKILL.md:319-326`).
- Composition is independently segmented per stream: `compose.py:898-901` derives `audio_segments` from the generated-audio intervals; `compose.py:940-951` chooses generated audio only for those intervals and source audio for the others; `compose.py:1006-1018` trims and concatenates the selected pieces. Therefore source audio outside the selected spoken interval can be restored. This is a compositor capability, not a temporal control on the H3 audio denoising itself.

Hivemind did not return a direct report about `audio_strength` or room tone; the answer comes from the pinned node implementation and Astrid's composition code.

## 3. Is there hivemind evidence for lip-sync quality when H3 audio is generated but the picture is kept?

**Verdict: still unknown.** I found no hivemind report documenting this exact masked-edit setup or assessing its lip-sync quality. There is adjacent, non-equivalent H3 evidence: motion-pack author seitanism wrote, “the lipsync kinda degrades after 30sec or so” (hivemind message `1535832954859954217`, `minimax_h3_resources`), and another user wrote, “I really hope that the next model which come will fix audio / dialogue” (message `1572556642183155833`, `minimax_h3_chatter`). Neither describes a masked edit with generated audio and preserved picture, so neither establishes quality for this case. Astrid's `docs/SKILL.md:349-351` records 18 November GPU runs with fixed replacement audio for a mouth edit, not generated audio.

Cheapest way to resolve it: one GPU spike on a short (about 3-second) source close-up. Keep the picture with an outside-preserving mask except the mouth/lower face, generate the spoken line with `audio_strength=1`, use a speaker voice reference, and compare the mouth motion against the generated transcript/audio. Include a frozen-audio (`audio_strength=0`) baseline to distinguish visual-mask behavior from audio regeneration. Do not infer longer-duration quality from this one short clip.
