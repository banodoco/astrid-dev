# Does an exact first frame need MiniMaxH3AddGuide?

**No. Astrid already has an exact-output mechanism for source-backed edits.** It takes protected frames from the prepared source during composition. AddGuide solves a different problem: it lets the model see a time-positioned guide while generating a shot. For Plan 64, make exactness a composition requirement and choose the generation route according to the picture and audio the shot needs.

## What AddGuide actually writes

At ComfyUI 6bfaacc, AddGuide reads the nested H3 AV latent to determine canvas size and timeline bounds. It appends a record to the positive conditioning’s `minimax_keyframes` list and returns only positive conditioning. The record contains a resolved pixel-frame index and a video latent, an audio latent, or both. The target samples and denoise mask are untouched. There is no guide-strength input. [Node implementation](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L151-L219) · Cached schema (`integrate/VibeComfy/vibecomfy/porting/cache/object_info/comfy_core@cpu-runtime.json:58944`)

A single image is center-resized to the target and VAE-encoded. A batch shorter than five frames contributes its first image. Longer batches are trimmed to the largest fitting input length of the form 17k + 5 (5, 22, 39, …). The resulting visual guide must fit from its requested index. Negative indices count from the end of the model timeline. Audio uses its own VAE and is cropped to the remaining audio duration. Chaining nodes appends anchors at additional indices. [Guide execution](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy_extras/nodes_minimax_h3.py#L175-L219)

The model payload collects keyframes and ordinary references together. The transformer assigns the keyframe its own conditioning rows at the requested target time. Those rows stay fixed while the model generates the target rows. This supports wiring AddGuide after ReferenceToVideo with other references and no source video. Rendered adherence with the chosen Ref2VA weights is an empirical question. Neither VAE encoding nor this row layout promises pixel equality or exact audio samples. [Payload assembly](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy/model_base.py#L2184-L2207) · [Transformer layout](https://github.com/Comfy-Org/ComfyUI/blob/6bfaacc/comfy/ldm/minimax/model.py#L369-L401)

## Why the silent reaction keeps four frames

1. S-02b supplies a 2.5-second timeline video and grants full-frame generation over the half-open interval 1/6, 2.5) seconds. At 24 fps that is frames 4–59. The canonical spec carries the source and edit separately. The compiler requires a source window matching the output duration and bounds the spatial mask to the edit interval, black before frame 4 and white thereafter. [Request (`recast/batch6/S-02b-silent-seed7.json`) · [Astrid compiler](https://github.com/banodoco/astrid-agent/blob/60f838a/astrid/packs/h3_av/shared/compile.py#L552-L607) · [Spec conversion](https://github.com/banodoco/astrid-agent/blob/60f838a/astrid/packs/h3_av/shared/spec.py)
2. ReferenceToVideo supplies conditioning and the target latent geometry. The V2V node replaces the sampler’s starting video and audio samples with encoded source samples. It attaches a nested noise mask with video strength zero outside the edit, the selected strength inside, and audio strength zero. The scheduler stays at denoise 1. The per-frame permission mask is reduced onto H3 latent tokens by taking the maximum over each temporal group. [Graph wiring](https://github.com/banodoco/astrid-agent/blob/60f838a/astrid/packs/h3_av/shared/generation.py#L368-L455) · [V2V implementation](https://github.com/seitanism/ComfyUI-H3-Motion-Context-MultiRef/blob/361624fb/h3_v2v_fractional.py#L384-L452)
3. H3’s repeating token spans are 1, 4, 4, 4, 4 pixel frames. Token 0 covers frame 0 alone. Token 1 covers frames 1–4, so the permission on frame 4 makes that whole token editable. Calling frames 0–3 four frozen latent frames would misdescribe this recipe. The compositor takes the protected prefix from source input 0 and joins it to the generated interval. For spatial edits it merges generated pixels over the source through the mask. Exactness refers to decoded prepared-source pixels through the preservation output path. A lossy still-to-video conversion could already have changed the original image. [Mask reduction](https://github.com/seitanism/ComfyUI-H3-Motion-Context-MultiRef/blob/361624fb/h3_v2v_fractional.py#L228-L254) · [Composition](https://github.com/banodoco/astrid-agent/blob/60f838a/astrid/packs/h3_av/shared/compose.py#L931-L1010)

## Plan 64 decision and cheapest proof

For an existing still-as-video source, begin regeneration at frame 1 (1/24 second) to keep exactly one output frame. Frame 0 also occupies its own latent token, which gives generation source context at the boundary. This needs only a recipe change. A public timeline **image** at frame 0 still needs admission, preparation and lowering. A compiler can build the source internally and reuse V2V plus composition. That route carries full-duration source preparation and the current masked path preserves source audio, a material difference for Plan 64’s generated dialogue. Plan 64 input decision (`recast/plans6465/plans/64-h3-speaker-references/inputs.md:51`)

For a source-free speaker shot, keep the existing image/speaker-conditioned generation and compose the prepared still at frame 0. This preserves the generated soundtrack and gives a deterministic picture contract with no new Comfy node. AddGuide is an optional way to improve continuity into frame 1, or to guide a clip, soundtrack or several points without constructing a full source timeline. The source-backed route can preserve arbitrary source pixels, regions and audio outside edit permissions. An arbitrary AddGuide index alone supplies none of those preservation guarantees.

The cheapest future proof for exact output is CPU-only: compile a public timeline-image request, inspect the frame-0 composition boundary and audio routing, then compose a visibly different stand-in generated clip. Compare decoded frame 0 to the prepared still in the agreed output dimensions and color representation, frame 1 to the stand-in, and the decoded soundtrack to the intended track. Compilation alone proves wiring. If D3 asks whether AddGuide improves the generated transition with Ref2VA, use one GPU render against an existing matched no-guide baseline, inspect raw frames 0 and 1 before paste-back, and compare the transition. Without a matched baseline a single render establishes execution and observed adherence only. No tests or jobs were run for this report.
