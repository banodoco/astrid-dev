**LE-2 contract card (part a).** The Runtime runs the Agent's commit code in its own process (`runtime_protocol/timeline_commit_provider.py:70-99`), and the element registry there is an `lru_cache` (`astrid/core/element/registry.py:197`). `element_schema` already clears it when a known provider changes on disk (`astrid/sdk/timeline_address.py:471-492`) but not when an element was missing, so a pack installed later stays invisible until restart. The fix is one retry on that miss path, in the Agent; no Runtime change and no new message between processes. Makes untrue: `tests/core/pack/test_cli_manage.py:test_packs_add_with_a_pending_host_refresh_prints_the_one_availability_line`, which pins "The pack is available after the host's next start." The pack host in fact acknowledges the refresh while idle (`GenericPackHost.acknowledge_pack_refresh`), so reword the line to say the pack is picked up by the running host, and update that assertion. Find other pinned wording with `rg 'next start|refresh_pending' tests` and re-check against the code at dispatch.
