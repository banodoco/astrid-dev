# H3 output size unknowns

Evidence is from `origin/release/14/plan-59` at `ec758a9b86a43416ace0650eb8109cb5967575dc`, VibeComfy's pinned object-info cache, and hivemind message `1541127211602546773` and `1572496981547421728`. The motion-context source checkout was not present locally; its pinned commit and commit-matched object-info schema were inspected. No GPU or machine was used. Hivemind searches did not surface evidence about H3 training resolution or the specific 512×288 voice-only quality claim.

## Suggested resolution boundary

Make width/height explicit in the normalized request (or an equivalent sealed output profile), validate positive multiples of 32 within the intended operational bounds, and pass the pair through conform, source checks, preparation manifests, generation node bindings, masked-tail allocation, static-region rasterization, and compiler inputs. Keep stored still masks in their original dimensions. Standalone preview currently applies fill to its source frame and refuses an explicit size that conflicts with a stored mask (`astrid/core/media_mask.py:139–173,196–228`). The proposed preview uses explicit CLI geometry and the same spatial transform as preparation. Moving masks have a separate frame-size and clock contract. Keep candidate/source dimension equality as a composition invariant. Before claiming quality support beyond the current 1024×576 profile, run controlled small and larger-size GPU comparisons; node schema limits alone do not prove model quality.
