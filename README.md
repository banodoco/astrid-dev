# Astrid development workspace

Astrid Dev connects Astrid's vision to practical work. [Contribution design principles](docs/contribution-design-principles.md) keep the process simple, and the [project catalog](plans/index.md) tracks what we're working on.

## What we're building

**A tool to unlock the collective artistic ambition of the open-source community.**

Our vision has four main pillars and four guiding principles. They define the destination and guide every project and plan. [Read the full vision](vision/README.md).

## From vision to work

The vision defines the destination. [Gaps](vision/README.md#gaps--15-assessed-outcomes), related to one or more pillars and principles, record what isn't yet true and what would prove it. Projects in the [plan catalog](plans/index.md) are attempts to close those gaps. Completing a plan doesn't automatically close a gap; it informs a reassessment. [How gaps are assessed](docs/contribution-workflow.md#define-or-reassess-a-vision-gap).

## Want to contribute? Give this to your agent.

Share this prompt with your agent—or, if you're an agent, follow it to get set up:

```text
Help me contribute to Astrid. Begin at
https://github.com/banodoco/astrid-dev and read
skills/astrid-dev/SKILL.md and docs/contribution-workflow.md.
Find existing issues or project tasks before suggesting new work.
Match a useful contribution to my interests, time and tools.
For bugs and small fixes, use an issue and real focused proof,
not a project. For independently useful new scope, investigate
prior art, choose a simple approach, and agree a clear outcome.
Respect source identity, user data and execution permissions.
```

[How to contribute](docs/contribution-workflow.md) covers claiming, proposing, submitting and completing work. You can [claim an available project](https://github.com/banodoco/astrid-dev/edit/main/plans/index.md) with a single owner-only PR, which is automatically merged if claim automation is enabled and the checks pass; [propose a project](https://github.com/banodoco/astrid-dev/issues/new?template=project-proposal.md), or [open an issue](https://github.com/banodoco/astrid-dev/issues/new) for a small fix. Claiming ownership doesn't authorize execution.

The [main development skill](skills/astrid-dev/SKILL.md) is the agent entrypoint. The [domain map](skills/astrid-dev/references/domains.md) routes you to the right code, and [writing and documentation](docs/contribution-workflow.md#write-or-improve-documentation) use the same reviewed PR process. [Ask a project question](https://github.com/banodoco/astrid-dev/issues/new?template=project-question.md) if you need help or a start decision.
