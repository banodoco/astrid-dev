# Astrid development workspace

This is where Astrid connects its creative ambition to practical work, alongside development skills and the plan catalog. Our [contribution design principles](docs/contribution-design-principles.md) guide how we keep that work rigorous and simple.

## What we're building

**[A tool to unlock the collective artistic ambition of the open-source community](vision/README.md).** Four artistic [pillars](vision/README.md#four-pillars) describe the creative aim; four [guiding principles](vision/README.md#four-creator-principles) — local-first/cloud-capable, open by design, creator-controlled and eliminating needless technical wrangling — apply across the whole system.

**[Vision → Gaps → Plans → Evidence](vision/README.md).** The vision defines the destination. [Gaps](vision/README.md)—relevant to one or more pillars and principles—record what's not yet true and what would prove it. Projects in the [plan catalog](plans/index.md) are attempts to close those gaps; their actual evidence informs the next assessment. **Completing a plan does not automatically close a gap.**

The [project catalog](plans/index.md) alone owns status, ownership, priority and estimates. [How gaps are assessed](vision/gaps.md).

## Want to contribute? Give this to your agent.

Copy this prompt into your agent:

```text
Help me contribute to Astrid. Begin at
https://github.com/banodoco/astrid-dev and read
skills/astrid-dev/SKILL.md and docs/contribution-workflow.md.
Find existing issues or project tasks before suggesting new work.
Match a useful contribution to my interests, time and tools.
For bugs and small fixes, use an issue and real focused proof,
not a project. For independently useful new scope, investigate
prior art, choose a simple approach, and agree a clear outcome.
Respect source identity, user data and execution permissions.
```

**[How to contribute: claim, propose, submit and complete](docs/contribution-workflow.md).** Browse the full [project catalog](plans/index.md) for current status, ownership and priorities. You can [claim an available project](https://github.com/banodoco/astrid-dev/edit/main/plans/index.md) with a single owner-only PR, [propose a project](https://github.com/banodoco/astrid-dev/issues/new?template=project-proposal.md), or [open an issue](https://github.com/banodoco/astrid-dev/issues/new) for a small fix.

The [contributor entrypoint](skills/astrid-dev/SKILL.md) owns the agent process; the [domain map](skills/astrid-dev/references/domains.md) routes people to the right code. [Writing and documentation](docs/contribution-workflow.md#write-or-improve-documentation) use the same reviewed PR pipeline. [Ask a project question](https://github.com/banodoco/astrid-dev/issues/new?template=project-question.md) if you need help or a start decision; claiming alone doesn't authorize execution.
