# Bridge — Collective Intelligence, from Hivemind to the vision

**Purpose:** Show how [this principle](principle.md) builds on current Hivemind and Astrid work and where implementable scopes belong. It is not a new approved plan.

## What exists

The [Banodoco Hivemind](references/source-map.md) currently has a corpus of Discord messages and revisioned resources, accepted-head search, explicit reported/observed evidence and editorial decisions. It has ingestion tools for articles, ComfyUI workflows and YouTube transcripts, plus lexical/semantic retrieval paths. That is real infrastructure for *source-grounded knowledge*, not yet proof of a general agent-native, multi-community learning loop.

Astrid Agent already has manifest-backed packs, skills and capability discovery; Astrid Runtime owns durable project/execution state; Astrid App has editor/agent-facing interfaces. These are possible consumers/integration surfaces, **not** evidence that Hivemind is already integrated as a universal live knowledge layer.

## Missing seams to prove

| Intended outcome | Gap to establish | First bounded proof |
| --- | --- | --- |
| Cross-community participation | Source-neutral adapters, contributor identity, access boundaries for public/private sources and curation authority | Ingest a second genuinely different source with exact provenance and visibility rules |
| Reliable collective knowledge | Repeatable extraction, evidence-backed deduplication, editorial promotion and revision freshness | Discord discussion → proposed guide → reviewed accepted revision with cited supporting and competing evidence |
| Context-aware agent use | Trusted retrieval as data (never instructions), scoped search by model/version/environment and citations | Agent answers a concrete creative question from pinned evidence and explains applicability |
| Tool/workflow discovery | Link knowledge to actual reusable packs, workflows, dependencies and versioned capabilities | Agent proposes a compatible workflow/capability and shows why; no invented compatibility |
| Feedback and contribution | Clear user-controlled route from a useful result or fix to a proposed knowledge revision | Submit correction → review → searchable accepted update, preserving author/source |
| Sustainable distributed curation | Quality/authority rules that preserve uncertainty and dissent without a single opaque score | Different contributors can propose competing methods without destroying one another's evidence |

## Relationship to plans

The current [Astrid Dev queue](../../../README.md) does **not** yet define a dedicated umbrella implementation plan for this entire collective-intelligence experience. Do not quietly append it to unrelated packs/timeline work. [Plan 19](../../../plans/19-first-principles-documentation/plan.md) can help with human/agent documentation principles; [Plan 06](../../../plans/06-packs/plan.md) and [Plan 17](../../../plans/17-vibecomfy-extensibility/plan.md) are relevant to reusable capability discoverability; Hivemind's own project source and plans remain the starting point for knowledge-specific work.

If implementation is desired, first define a bounded **Hivemind ↔ Astrid agent retrieval/use** proof, fresh source identities and evidence. Only then scope a separately owned plan in Astrid Dev, preserving Hivemind's own development authority and source roadmap.
