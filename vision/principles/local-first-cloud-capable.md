# Local-first, cloud-capable

## Statement

Creative work should remain yours, whether it runs locally or in the cloud.

## Explanation

Astrid should work on your own machine, online or offline, with local projects and files under your control. Cloud models, agents, and rendering can extend that work when useful, but moving between local and remote execution must be a deliberate, understandable choice.

## Characteristics

### Local work as the default

Creators should be able to make and preserve work on their own computers.

The local project should remain authoritative when the creator chooses a local-first workflow. They can inspect, reopen, revise, and retain the underlying files without depending on a permanent cloud connection.

### Optional cloud capabilities

Remote computation should extend local work without quietly taking it over.

Creators and their agents can explicitly select hosted models, remote agents, or rendering services when those are useful. Results should return to the correct project, with clear data boundaries.

### Clear boundaries and costs

The creator should know where work runs and what leaves their machine.

Choices about uploaded data, remote storage, permissions, services, and costs should be visible and revocable where possible, so convenience does not obscure control.

### Cloud as frugal as possible

Cloud tools should be inexpensive enough to encourage experimentation rather than ration it.

Artists have always shared tips on where to find affordable materials—even cheap turpentine matters when you need the freedom to try things. We want the same spirit in cloud inference: use efficient models and infrastructure, make costs easy to compare, and seek the least expensive suitable route to a creative result. Frugality should broaden experimentation without sacrificing quality, privacy, or the creator's choices.
