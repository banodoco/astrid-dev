# Contribution design principles

> **Make good contributions easy, poor decisions difficult, and results independently verifiable—with the least machinery necessary.**

Each principle answers a failure that happened here. Cite principles by name; numbers 1–8 keep their older meaning.

## The principles

1. **One way in.** Every contribution starts at the [contributor skill](../skills/astrid-dev/SKILL.md), which routes each stage to one specialist skill; a specialist deepens a stage, never starts a second process. *Failure:* a manager ran an effort without guidance reachable only through links ([archive row 1](process-ledger.md)). *Example:* its "One path" section. *Check:* judgment.
2. **One home per fact.** Write each rule or fact once, in its home; elsewhere link it, or generate it into a marked region never read back as a source. *Failure:* rules copied into up to five files; five skill conflicts ([findings](../plans/51-astrid-dev-clean-up/inputs.md#prior-art-what-was-verified)). *Exception:* until Plan 51's CU-13a, the public feed reads principles from the generated `vision/README.md`. *Example:* `plans/index.md`. *Check:* `generated-views`.
3. **Rigor in proportion.** Scale route, challenge and review to uncertainty, impact, cost and irreversibility; review where later work builds on a result. *Failure:* a normal-route manager could not do the taste and review rows ([ledger](ledger/2026-11-11-manager-route.md)). *Example:* [`skills/astrid-dev-shared/run-contract.md`](../skills/astrid-dev-shared/run-contract.md#routing-and-bindings). *Check:* judgment.
4. **Read before building.** Trace existing behaviour and prior work in the code before replacing or adding; keep what works. *Failure:* a new runner dropped the old kit's keep-alive, so a restart killed a Codex manager ([ledger](ledger/2026-11-09-codex-keepalive.md)). *Example:* the Prior art line of [`templates/project/inputs.md`](../templates/project/inputs.md). *Check:* `project-planning-evidence`.
5. **One owner, one accountable agent.** A project has one owner, declared once on its plan's `**Owner:**` line, and a run one accountable agent, on its `Run start` line; others propose changes to an active pack by pull request, and the owner or the manager running it merges. Ownership is accountability, not permission. *Failure:* nobody answered for Plan 48's run finishing ([ledger](ledger/2026-11-11-nobody-answered-for-the-run.md)). *Example:* [`plans/51-astrid-dev-clean-up/plan.md`](../plans/51-astrid-dev-clean-up/plan.md). *Check:* `catalog-paths`.
6. **Evidence for the exact claim.** A result names its candidate, command, environment and observed outcome, runs the path users run, and counts an interrupted run as no result. *Failure:* Release 10 shipped all green while `--update` installed nothing on handed-off machines ([archive row 51](process-ledger.md)). *Example:* [`templates/product-pr/review.md`](../templates/product-pr/review.md). *Check:* `completion-assessment`.
7. **Checks see structure; people decide.** A check validates what it can see and fails closed; whether evidence proves a claim is a reviewer's call; claiming, scoping, authorizing, merging, completing and publishing are separate decisions, each from the owner's own message or a recorded standing go. *Failure:* reordering principle headings in the generated vision page passes checks but changes the public feed ([findings](../plans/51-astrid-dev-clean-up/inputs.md#prior-art-what-was-verified)). *Example:* `scripts/checks.py`. *Check:* judgment.
8. **Subtract before adding.** Change the system only for a recorded failure ([ledger](ledger/README.md) entry or issue): fix it at its home, prefer removing or reusing, and add a state, document, role or check only to remove a real ambiguity. *Failure:* fifteen skill changes in two days each added a paragraph ([alternatives](../plans/51-astrid-dev-clean-up/inputs.md#alternatives-including-doing-less)). *Example:* `docs/ledger/`. *Check:* judgment.
9. **One word per thing.** Each term has one sense, defined once; two needed senses become two terms. *Failure:* three documents named a plan's parts three ways ([ledger](ledger/2026-11-11-planning-process-friction.md)). *Example:* `scripts/lifecycle.py`, the status words. *Check:* judgment.
10. **State outlives the session.** What the next agent needs to resume lives in a tracked file or durable scheduled task, never only in a session, process or machine. *Failure:* a run stalled about nine hours when a session-only timer was lost ([archive row 23](process-ledger.md)). *Exception:* model IDs, kept in git-ignored `run.yaml`. *Example:* the Progress column of [`templates/project/tasks.md`](../templates/project/tasks.md). *Check:* judgment.

## Where to apply them

Routing: the [contributor skill](../skills/astrid-dev/SKILL.md). Runs: the [run contract](../skills/astrid-dev-shared/run-contract.md) and product repositories' instructions. GitHub steps, records and bots: the [contribution workflow](contribution-workflow.md), [project format](project-format.md) and [maintainer setup](contribution-automation-setup.md).
