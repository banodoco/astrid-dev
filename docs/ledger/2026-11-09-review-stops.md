Planners now suggest reviews in every plan, biased towards one review at the end. A significant project may also get a review stop right after a load-bearing part (a contract, data model, protocol, security boundary or shared interface that later tasks build on), where a late finding would redo later tasks or reach users. A stop uses the same protocol as the final review, has its own agreed rounds and a stated reason, and the tasks built on it depend on it. The plan skill, the run contract, the tasks template and the run template say so.
