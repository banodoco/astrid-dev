What went well: every card was landed from a worker's uncommitted tree only after the host re-ran every proof file the card named, which caught a worker test that passed on the base (PM-9b) and a missing test run in a merge; the review stops found real defects before anything was built on them (RS1 blocked the contracts, R2 and R3 each found should-fix items). What stopped a worker, four times: a card's scope list written before the code it describes moved (PM-6z's grep proof could not pass inside its file scope after Phase 2 moved the link pattern; PM-8a's contract made four other pinned tests untrue); a pinned test that pinned a fail-open behaviour (R3.4); and a worker that could not run the card's own commit-based proof because its sandbox cannot commit, so the host ran it in a real scratch clone (a `cp -a` copy shares the real `.git`). What to change: (1) a card that names a grep or a pinned-test list should say "re-check against the current code at dispatch", and the plan skill should require the planner to list every other test a changed contract makes untrue; (2) the manage skill should say that a worker whose card conflicts with its own contract stops and the host rules at once with before-and-after, rather than the worker guessing; (3) the run-contract's Codex section should say plainly that a commit-based proof is run by the host in a real clone, never a `cp -a` copy; (4) a host step that merges must check `git diff --name-only --diff-filter=U` and stop before running any proof; (5) a cut-over runbook should say which side effects of the saved migration script to undo (here `plans/priority.md`'s preamble) because it was found only by rehearsing it.
