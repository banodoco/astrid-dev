# Release 18 — Astrid Dev gap integrity

**Release:** 18
**State:** Draft
**Kind:** patch
**Release manager:** Plan 71 whole-project manager (this owner-authorized ChatGPT conversation, 20 November 2026); future handoffs require a recorded accountable successor.

## Highlight

Astrid Dev describes what Astrid still cannot reliably do through a validated gap definition and an evidence-backed, coherent gap catalogue.

## Intent

This is a **documentation and developer-workspace release**, not an Astrid Runtime, Agent, App, installer or published product-version change. Its sole delivery project is [Plan 71](../plans/71-gap-definition-reconciliation/plan.md). The owner explicitly requested an Astrid-Dev-focused release and directed its execution on 20 November 2026, following the merge of [Plan 71's scope PR #1063](https://github.com/banodoco/astrid-dev/pull/1063).

The intended outcome is that someone can distinguish a gap from an issue, project, goal or implementation choice, verify that definition against representative and held-out evidence, and use it to correct the current gaps without losing the history of their references. A successful assessment may leave a gap unchanged; neither the number of new gaps nor the number of resolved GitHub issues is a success metric.

## Approach

Run the accepted **first five phases of Plan 71 only**, in order:

1. Inspect and define a rigorous gap boundary and independent closure standard using existing Astrid Dev sources, not a second schema.
2. Collect a balanced sample of issue/project/release and vision evidence, including cases with no relevant issue.
3. Calibrate the definition with counterexamples, an untouched holdout and independent review; obtain the owner's separate acceptance of the definition.
4. Reconcile all original gap IDs against actual issues and project outcomes, proposing a complete keep/refine/split/merge/retire/close/pending mapping and separate new-gap candidates.
5. After an independent catalogue review and the owner's separate migration decision, integrate only approved record/relationship changes, tests and generated views. Preserve project/release authority and exact source evidence.

**Publication and scheduling:** This release is Draft until its reviewed, qualified Astrid Dev release branch meets the required checks and publication is separately authorized. Its cut line is the completion and independent qualification of the first five phases; the owner has not set a calendar deadline. No product publication, manifest update, installed version bump or deploy is authorized by this brief. The release's GitHub branch and plan branch may be built and verified before that final decision.

**Dependencies and exclusions:** [Plan 53](../plans/53-vision-aspirations/plan.md) and the open [Astrid Dev Goals PR #1059](https://github.com/banodoco/astrid-dev/pull/1059) with [App PR #323](https://github.com/banodoco/astrid-app/pull/323) own overlapping authoring/feed semantics. Do not edit their shared contracts until an accepted owner/landed revision is established. [Plan 52](../plans/52-issue-intake/plan.md) remains the source for issue intake; [Plan 44](../plans/44-vision-execution-trail/plan.md) owns public evidence presentation. Preserve the existing first-principles gap-boundary review and original assertions.

**Deliberately deferred:** Plan 71's **Phase 6 recurring gap-review workstream** and **Phase 7 recurring qualification/activation** are out of this release. Do not install a weekly skill, schedule an automation, add a bot or create permanent recurring review state.

**Branch-base decision:** The existing `release/14/main` branch for `astrid-dev` was inspected at `321523e52bddbbd13477634b05974a16b54b825b`; it was divergent from the current `main` (about 344 commits behind and four ahead at inspection) and does not contain the accepted Plan 71 records. Because Release 18 exclusively changes current Astrid Dev documentation and should not import unfinished Release 14 work, cut its independent `release/18/main` from the latest verified `main`, rather than treating the unrelated Release 14 branch as an authoritative ancestor. This is an explicit non-product exception to the normal forward-only product-release branch chain, to be independently reviewed before publication.
