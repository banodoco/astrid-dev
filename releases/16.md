# Release 16 — Install and update everywhere

**Release:** 16
**State:** Draft
**Release manager:** not yet named

## Highlight

Installing, updating, rolling back and removing Astrid works on Windows, macOS and Linux, and you can see which version you have. A creator can also connect their existing ComfyUI, including Desktop, or prepare a supported local generation environment and recover from ordinary setup failures.

## Intent

A stable version has to survive its own updates. A good outcome: the full install, update, rollback and removal matrix proven on the three systems, one process identity for Agent and Runtime, and releases defined and published from astrid-dev with visible version numbers.

Proposed by the advisor and agreed by Hannah on 15 November 2026 (version 0.1 is "focused on hardening, updates, stability and speed"), with fixes and plans added on the fly from actual usage and user reports. See [Strategy](../strategy.md#decisions).

A stable version must survive its own updates on every system.

## Approach

Finish the update work Release 12 started, then the less common setups. Whether Pinokio is a supported route in version 0.1 is an open owner decision; if not, it is declared unsupported plainly.

Each release has one theme and a [standing lane](../agent/shared/glossary.md).

- [Plan 76](../plans/76-editing-together/plan.md) — editing together, after Plan 63: an agent edits beside a person without blocking or overwriting them (about 12 days; moved from Release 15 on 23 November 2026).
- [Plan 18](../plans/18-timeline-editing/plan.md) — phase A only, agents and packs (about 18 days, Agent and Runtime, no App code), after Plan 63's server track; phase B waits on its D4 (moved from Release 15 on 23 November 2026).
- [Plan 39](../plans/39-green-mains/plan.md) — Runtime and App main green: every Runtime and App CI workflow green and kept green, through a ceiling that only shrinks, a prune pass and one card per cause, with a nightly red report (about 60–80 engineering days; moved from Release 15 on 23 November 2026; rebuilt on 24 November on `release/15/main`, its Agent share now Plan 91). The release rule that every required check is green on each pinned commit is Plan 31's `release-contract` job.
- [Plan 50](../plans/50-recorded-boundaries/plan.md) — rented-machine failures found on a CPU (moved from Release 15 on 23 November 2026).
- [Plan 92](../plans/92-generate-within-a-second/plan.md) — generate within a second: `astrid generate` queued in under 1 s through a resident host and thin client, after Plan 82's caches (about 5 to 6 days; owner, 24 November 2026).
- [Plan 13](../plans/13-execution-host-refactor/plan.md) — the execution host split into modules: first a guard so the 18,888-line `generic_host.py` cannot grow, then the tests that pin its behaviour brought across and one small, measured move, with a re-estimate for the rest (about 5 to 6 engineering days; the owner chose this scope on 22 November 2026). That is the whole of this plan. The further moves out of the file are Plan 83 (execution host in modules, linked from this plan), which is in no release and is decided on that re-estimate. Moved from Release 15 by the owner on 24 November 2026; not started there.
- [Plan 79](../plans/79-local-media-any-size/plan.md) — local media of any size: a clip from the creator's own computer is placed at any size the Runtime accepts, with one limit, streaming instead of loading the file into memory, and the original never touched (about 8 engineering days across the Runtime's client, the Agent and the App; the owner asked for the project and this release on 21 November 2026; she decided D1, D2, D4 and D5 the same day; it starts after Plan 77 lands, with an interim 1 GiB limit meanwhile). Moved from Release 15 by the owner on 24 November 2026; not started there.
- [Plan 91](../plans/91-agent-main-green/plan.md) — Agent main green: every Agent CI workflow green and kept green, behind a ceiling of today's failing tests that may only fall and is compared by id on every batch run, with a bold prune of tests of retired behaviour before anything is fixed (about 55–72 engineering days, five workers; started on 24 November 2026 and moved here from Release 15 by the owner the same day: it runs now and targets `release/16/main` from the start). Its branch `release/16/plan-91` was cut from `release/15/main` and merges it forward until `release/16/main` is cut. Its dispatch is in [the run board](16/run.md#plan-91-dispatch).

- [Plan 93](../plans/93-comfyui-desktop-and-existing-environments/plan.md) — ComfyUI Desktop and existing environments: discover, safely connect or recover a person's existing installation and prove real Desktop generation; Windows first, other layouts declared and qualified explicitly (owner requested Release 16 on 24 November 2026; draft scope, critique and estimate pending).
- [Plan 94](../plans/94-dependable-environment-setup-and-recovery/plan.md) — dependable environment setup and recovery: when no usable target exists, prepare or recover a supported local environment using existing engine and workflow capabilities; run a real first-creation loop using Plan 93's handoff (owner requested Release 16 on 24 November 2026; draft scope, route decision, critique and estimate pending).
