# Release 16 — Generation complete

**Release:** 16
**State:** Draft

## Highlight

Every bundled workflow sets itself up and runs, with its models downloaded for you, on your own ComfyUI.

## Intent

Release 13 proves the default workflows; around them are rough edges a creator meets in the first hour. A good outcome: model download for every kind of workflow (image, edit, music, speech, sound effects, video), resumable; every bundled workflow either ready or honestly marked; the rest of onboarding; video models beyond the default qualified.

Proposed by the advisor and agreed by Hannah on 15 November 2026 ("those releases make sense"), with fixes and plans added on the fly from actual usage and user reports. See [Strategy](../strategy.md#decisions).

## Approach

The headline is one command that sets up everything a workflow needs, bundled or the person's own (Hannah, 15 November 2026: "a way to just download all the models for a workflow and if we can't find them we have a simple way to reconcile them, similar with custom nodes"). It plans first: every model and node pack the workflow needs, each marked present, found (source, size, destination) or not found. After one approval it downloads the models, installs the node packs with their requirements, and says whether a restart is needed. Anything not found is reconciled the same way for both kinds: offer what the person already has under another name, search (Hugging Face; the ComfyUI-Manager node list, which VibeComfy can already read but readiness does not use), or ask once for an address and record the answer. Today an unknown model ends at "put this file in this folder" and an unknown node is misreported as a ComfyUI core node. Open owner decision: Astrid does not install node packs into a person's own ComfyUI today; the proposal keeps that as the default and installs only on explicit approval of the plan.

Scope is set from what users and testers actually report after Releases 14 and 15, starting from Release 13's deferred list. Workflows are never refused for something Astrid can resolve itself. Identifying a model Astrid does not recognise, and finding one it does not have, is [issue 665](https://github.com/banodoco/astrid-dev/issues/665): its first half (offering a match the person already has, download plans for any workflow, one clear path in the skills) goes in the standing fixes lane; its second half (identify a file, find a source, remember the answer) is in this release.

Each release has one theme, plus a standing lane for fixes and small plans that come from actual usage and user reports.
