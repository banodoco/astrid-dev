# Release 16 — Make Astrid dependable

**Release:** 16
**State:** Draft
**Kind:** minor
**Release manager:** not yet named

## Highlight

A creator can install Astrid on Windows, macOS or Linux, set up generation, create, import, edit, save, render and update without losing work or needing an agent to improvise system administration.

## Intent

The next product release concentrates on dependable everyday creative work, not general architectural polish or the complete performance/extensibility programme. Owner direction, 25 November 2026: split the former Release 16 into this release, [Release 17 — Continuous hardening](17.md), and [Release 18 — Fluid and powerful](18.md). This release is the intended first minor version, 0.1.0: targeted evidence of dependable operation, followed by continuous hardening and sustained speed/creative proof on the path to 0.2. This is a draft scope for evidence-led reconciliation, not a go to implement.

## Approach

**Support decisions:** retain Windows, macOS and Linux and Pinokio (including the genuine launcher journey). RunPod is experimental; spending, consent and lifecycle safety are still mandatory. Investigate representative mainstream NVIDIA RTX 20/30/40/50 family support on Windows and Linux, and compatible existing ComfyUI on macOS/Apple Silicon; state explicit qualification and model-specific limits. Do not hard-code one tester's GPU as the whole product promise. A hard cut permits one current contract and retiring obsolete implementations, not discarding user projects, preferences, environments or safe update/rollback. Everything accepted into Release 16 ships together.

**Scoping first:** reconcile the exact pushed Release 15 tuple, remaining active work and its issue handoffs; independently inspect every included plan against code and recorded issues; scout dependability issues independently of selected plans across the product repositories, tester reports, previous qualification, and open/closed/reopened issues. Route supported-path defects involving installation, generation, editing, saving, media, rendering, state, permissions, recovery or data loss to one owner; record evidence and disposition. Scout prerequisites in adjacent plans without pulling their full scope forward. Keep the dedicated green-suite programme in Release 17, but do not relax Release 16 safety, regression or required-check rules. Resolve Plan 31's required-check gate before committing scope; no full-green claim without full-green evidence. Plan 31 stays here: scope and sequence canonical release publication, semantic versioning, migration from the actually served numbered release, exact-pinned manifest and user-visible version identity before the 0.1 publication. Reuse completed Plan 58 and its existing strategy generator, verify current consumers and do not duplicate roadmap data. Distinguish a minor version from an explicitly required update. Check the order and safe transition with Plan 29; a Draft or strategy edit must never publish.

**Provisional sequence:** first freeze sources, inventory existing measurement tools (85), define supported environments and shared state, update, save and custody contracts (35, 38, 63, 29, 93). Then sequence environment preparation (93/94/90, consuming 56), installation and qualification (29/30/09/10/31), dependable editing (63/04) and large media (79), plus remaining rendering (87). Verify the real file and interface dependencies, revise the order to avoid duplicate changes and preserve active runs. Plan 04 supplies basic safety, not all of Plan 76; Plans 75/76/18/80/92/86/37 remain later unless a minimal prerequisite is explicitly reconciled. Use an independent synthesis and independent review of the actual amended plan records, then agree a single integrated release scope and exact acceptance journeys before dispatch.

**Qualification:** real installed journeys on supported platform/install routes, a first creative result with existing or freshly prepared supported environments, safe edits and conflict/restart/recovery, substantial local media, correct rendering, and lived-in update/rollback. Compare against the served release; evidence belongs to the exact candidate. The existing [Plan 91 lane](16/run.md) is preserved as a handoff to Release 17; it is not Release 16 scope.

Each release has one theme and a [standing lane](../skills/shared/glossary.md).

## Included plans

- [Plan 09](../plans/09-install-and-update-confidence/plan.md) — Safe installation, update, rollback, repair and removal on Windows, macOS and Linux; protect lived-in state.
- [Plan 10](../plans/10-pinokio-qualification/plan.md) — Qualify the actual Pinokio controls, safe Stop/Quit, custody and hosted and fully-local journeys on all three operating systems.
- [Plan 29](../plans/29-update-and-release/plan.md) — Complete one understandable update path, including Pinokio and fully local.
- [Plan 30](../plans/30-update-everywhere/plan.md) — Finish less common setups and prove the real update actions, including older Linux systemd and Pinokio.
- [Plan 31](../plans/31-releases-from-astrid-dev/plan.md) — Publish 0.1.0 from one authoritative release record and verified manifest, with correct user-visible semantic versions and historical mapping; reuse Plan 58, reconcile Plan 29 and the staged CI-hardening gate without weakening safety.
- [Plan 38](../plans/38-one-process-identity/plan.md) — One process identity, custody and signalling contract across all three platforms.
- [Plan 93](../plans/93-comfyui-desktop-and-existing-environments/plan.md) — One verified readiness path for existing ComfyUI environments including Desktop, Portable, Git and Pinokio; reconcile support across platforms.
- [Plan 94](../plans/94-dependable-environment-setup-and-recovery/plan.md) — Consented, recoverable local environment provisioning, real GPU checks and first creation; scope representative mainstream NVIDIA Windows/Linux combinations.
- [Plan 90](../plans/90-workflow-setup-exact-plan/plan.md) — One exact dependency plan and approval, repeatable/resumable application and recorded trust, building on Release 15 Plan 56.
- [Plan 35](../plans/35-one-home-for-user-state/plan.md) — One owner for user/project choices and work; preserve machine-local bootstrap and recovery state, and reconcile reusable workflow trust.
- [Plan 63](../plans/63-dependable-saving/plan.md) — Dependable saves and explicit server outcomes for editor and agent writes; no lost edits, silent overwrites or stuck state.
- [Plan 04](../plans/04-concurrent-edits/plan.md) — Retained concurrent-editing safeguards: independent writers cannot silently overwrite or block each other; reconcile with Plan 63 and keep richer collaboration in Release 18.
- [Plan 79](../plans/79-local-media-any-size/plan.md) — Use substantial local media up to the Runtime limit by streaming, protecting the original and recovering interrupted imports.
- [Plan 87](../plans/87-render-works/plan.md) — Complete only the remaining renderer handoff from Release 15, including correct preview/export, restart and custody issues that threaten dependable work.
- [Plan 85](../plans/85-one-place-to-measure/plan.md) — Reuse and consolidate existing measurement machinery; record comparable installed-product evidence early, not a new framework.
