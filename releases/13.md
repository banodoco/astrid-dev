## Highlight

Creators generate media through one path, locally or on a rented GPU they control, and a failed generation comes back with a receipt that says why.

## Intent

Deliver generation, machine lifetime controls and first-image onboarding, with live GPU proof, on top of the published Release 12. Before any paid proof, make the path one that agents and people can run without confusion: one documented way to rent a machine and wait for it, one failure receipt that returns to the user's machine, and one source of truth for pins.

**Done:** the gate below holds on one frozen tuple built on published Release 12, the orchestrator publishes on Hannah's go, and every in-scope GPU cell has passed live.

## Approach

The [Release 12 operating principles](12.md#operating-principles) apply here unchanged: iterate freely and qualify once, cheapest model first, never weaken a check, a ruling on every finding within the hour, Hannah's decisions reach her the same day, and the safety rules. One manager session owns this release and delegates to sub-agents; the orchestrator checks in every three hours.

### Why the earlier attempt stalled (11 Nov findings)

- **Live TTS fails and the cause is unknown.** Two live failures on 10 Nov; the paid diagnosis never ran because setup failed first. SFX has never passed on a GPU.
- **Failures come back without a cause.** On failure only a 4 KB output tail returns, reduced by a strict allowlist to a code and a category. That is why TTS came back as "input rejected, field unknown". Successful outputs are fetched with a verified manifest; failures use no such path. A kept machine preserves the evidence, but no command reads it.
- **Renting a machine looks like failing.** The product command already waits until a machine is claimed, but the preview and the per-attempt progress line both print `stock_unavailable`, a `--gpu` without `--max-hourly-usd` steers callers onto an exact-offer path that needs a deadline, and the GPU-validation skill never names the waiting command. There are also four separate pod launchers in the Agent, of which one is the product path.
- **Pins live in several files.** The VibeComfy and ComfyUI pins are in two pin files, the lifecycle pin in three places, and one GPU run already failed because an override reached one and not the other.
- **Two fixes for one bug.** Release 12 ships an owner-token fix for the pack-host attach refusal (`3639d63d`, Runtime `42ae24aff`); the generation branch carries a different one that needs Runtime `8b312c4b`. Merging the two heads conflicts in 14 files.

### GPU rules

- **RTX 4090 or RTX 5090 only**, no more expensive substitute (Hannah, 11 Nov). Video needs 32 GB, so video cells name the 5090 alone; listing the 4090 first would wait for a machine that then fails the job.
- One waiting product command per cell, no time window, no geographic filter. Waiting for stock is normal; it is not a failure and needs no retry logic from the caller.
- A census before each rental and after each release. A kept machine is released when its batch ends, at its idle limit, or at once if custody is unclear. Only the manager's GPU duty rents.
- No scheduler or check-in is a paid-resource safety mechanism: whoever rents supervises until the census is empty.
