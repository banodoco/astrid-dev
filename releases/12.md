## Approach

### Operating principles (every manager reads these first)

Use these principles when a task leaves a case open.

1. **Two different bars. Know which one applies.**
   - **The release's own checks** (the 11-row matrix, Direct Journey, App Tests) must have **0 failures**. "It fails on `main` too" is never an excuse there: fix the failure, and question it.
   - **Broad suites** (Agent CI, lanes) are judged by **no regressions**, not "all green". A regression is a test that ran and passed on a baseline (R10, R11 or `main`) and fails on the candidate. Product regressions against R10 are fixed here (P39-D8).
   - **Pre-existing broad-suite failures go to [Plan 39](../plans/39-green-mains/plan.md)** with their cause, via a records PR. Exceptions here are product regressions against R10 under [P39-D8](../plans/39-green-mains/inputs.md#owner-decisions), the release's own checks, and A0's collection/reporting repairs needed to measure the candidate. D8's proven stale-test, test-infra and Mypy debt stays in Plan 39; judge it against served R11 and `main`, not a blanket R10-green requirement.
   - **"Pre-existing" needs a base comparison run, not anyone's word.**
2. **Never weaken a check.** Skipping, deleting or xfail-ing a test, widening a timeout, loosening an assertion, or changing an expected value without trace evidence all count. Removing a test is Hannah's decision. Prove "test drift" from the trace.
3. **Product behaviour is Hannah's.** If a fix changes what the user sees or does, bring it to her with a recommendation (as with Direct Journey `:426` and `:708`). Test changes must trace to an intended product change and its commit reasoning.
4. **Evidence is bound to an exact SHA.**
   - Earlier SHAs, sibling branches and CPU fakes do not prove the candidate; CPU never stands in for GPU.
   - Check workers' diffs; don't trust summaries.
   - Say what wasn't run, for example "tsc not run".
5. **Decided; don't reopen:**
   - P39-D8;
   - `:426` keeps the draft; `:444` removed; `:708` keeps the auto-reload;
   - custody doesn't block;
   - the 659 Lanes failures are on Plan 39, with no install or update breakers;
   - generation is in Release 12;
   - H1–H4 below.
6. **Route; don't expand.** A real but non-blocking finding goes to the plan that owns it as a recorded follow-up: Plan 39 for green mains, Plan 30 for Pinokio and older setups, or the owning plan. Fix what the release needs; record the rest.
7. **Nothing important lives only on a machine.**
   - Decisions go here.
   - Task progress goes into small `tasks.md` PRs.
   - Evidence is committed to astrid-dev.
   - Branches are pushed by full GitHub URL.
8. **Spend like it's yours, and keep machines warm between related work.** A rented GPU stays up between closely bundled tasks: run every cell that needs the same GPU type back to back on one pod, within its consented idle and spend limits, rather than releasing and re-renting each time. Release when the batch ends, when the idle limit is reached, or **at once** if reuse is unsafe (a custody mismatch, a lost or unknown lease, an unverifiable install, host shutdown). The same thinking applies to environments and clones: build once per repo per SHA and reuse them.
9. **How Hannah works:**
   - keep moving and think around obstacles;
   - don't invent limits (geography, time windows, oversized GPUs); when unsure, take the less restrictive option and say so;
   - bring her only genuine decisions, each with a recommendation;
   - talk plainly, and give money as "spent $X of $25".
10. **Safety:**
    - never read `~/.codex`, `.env` files, or credential or token files; name credentials, never print them;
    - don't work around a classifier or safety refusal; report it;
    - no model names in commits or PRs;
    - keep Hannah's email private;
    - never land the Windows update-refusal fallback `2f975f62`;
    - no force-push or rebase.
11. **Known traps:**
    - installer changes run every `tests/test_installer_*.py`, and the installer must import without third-party packages;
    - the keep-going diagnostic covers only the fresh-install leg, so it can't see update bugs;
    - VibeComfy is pinned in two places;
    - astrid-dev has two Plan 40 folders; this release means `40-machine-lifetime-controls`.

### Operating rules (orchestrator)

- **Mailboxes:** on every wake, read **all five** managers' `run/to-orchestrator.md` and `status` before re-arming `codex-hold.sh`. It exits on the first event, so writes from other managers in the same window are otherwise missed. Relay each label to the receivers in the hand-off table straight away.
- **Liveness:** while any run is live, keep a check-in at most 20 minutes away. Make sure the SessionStart hook for `codex-hold-daemon.sh` is in place before starting managers; Hannah adds it (all-plans brief, open questions). After a container restart, the daemon restarts runners; check every `heartbeat`.
- **Timeouts:** a manager `WAITING` for over 2 hours on a sender that isn't `running` gets a ping, or its sender gets restarted. A `BLOCKED` gets a decision within 1 hour.
- **Failure defaults:**
  - **Merge conflict in B5 or B7:** P32 resolves it against both parents. It posts `CONFLICT file=<f>` only for another plan's unclear hunk, and carries on with the rest.
  - **Red release check:** inspect its trace. The orchestrator may authorize one same-input retry for an infrastructure/transient failure; a product failure becomes a fix task immediately. A second red result is a fix task.
  - **Re-freeze after a fix:** identify the changed inputs and affected gate claims, then authorize their replacement proof under the freeze rule. Preserve the old evidence as history.
  - **GPU cell fails:** route it to the owning plan; rerun per [generation.md](12/generation.md#start-here--p34-manager).
- **Pipelining:**
  - At `A-CAND`, start review round 4 and Checkpoint A's Agent CI in parallel. Start App Tests, Direct Journey and matrix once A4 is clear and re-pin #1 exists; reuse that exact-tuple proof at Checkpoint A rather than dispatching it twice.
  - Promote an early rehearsal only when its Agent parent equals `A-FROZEN`, its generation parent equals the accepted `B-CANDIDATE`, and it has the required pin reconciliation, `d70bed508` repair and focused proof. Otherwise build B7 on the correct inputs.
  - B8 and the Agent part of B9 may start at `FINAL-B7`; B9 finishes after `FINAL-TUPLE` supplies the App merge delta. Final GPU cells start at `FINAL-TUPLE`, in parallel with CI/review if still running. The earlier TTS diagnosis is separate.
- **Precedence:** for Release 12, these pages override the manage, release and gpu-validate skills and `manager-brief.md` where they differ: no `int/<NN>` pushes, the CI list here, the cell table instead of gpu-validate's flow, and the gate here instead of the Release skill's "no broad suites" rule.
