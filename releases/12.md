## Approach

### Operating principles

1. **Iterate freely; qualify once.** Getting a test green is cheap, disposable work: rerun on new commits as often as needed, keep raw logs, no permission and no review. Gate evidence is produced once, on the frozen tuple, on CI. Nothing before that is evidence, and no scratch run needs an authorization paragraph here. See the [iterate skill](../skills/astrid-dev-iterate/SKILL.md#iterate-freely-qualify-once).
2. **Judge difficulty, then delegate.** One manager delegates everything to sub-agents. For this release: plain fact-finding and running a named check go to Haiku; everything else starts on Sonnet unless it is clearly very hard, which starts on Opus. Escalate one step only on evidence, per the [run contract](../skills/astrid-dev-shared/run-contract.md#cheapest-model-first). The route letters in the task list are a first estimate of difficulty, not a model binding.
3. **Two bars.** The release's own checks (the 11-row matrix, Direct Journey, App Tests) must have **0 failures**; "it fails on `main` too" is no excuse there. The broad Agent suite is judged by **no regressions** under [P39-D8](../plans/39-green-mains/inputs.md#owner-decisions): a regression is a test that passed on a baseline and fails on the candidate. Pre-existing broad-suite debt goes to [Plan 39](../plans/39-green-mains/plan.md).
4. **Never weaken a check.** No skipping, deleting, xfail-ing, loosening or widening timeouts to get a pass. Removing a test is Hannah's decision.
5. **Every finding gets a ruling within the hour.** The manager marks it one of: product regression (a fix task, now); test drift (fix the test and cite the commit that intentionally changed the behaviour); pre-existing (Plan 39, with the baseline run that shows it). "Unresolved" is not a state.
6. **Product behaviour is Hannah's, and it reaches her the same day.** Anything that changes what a user sees or does goes to her through the orchestrator as options plus a recommendation. A blocker framed as "needs more evidence" for more than half a day is a decision that has not been asked. **Building is free; merging waits.** A manager may build any user-visible change on a branch without asking. Only merging it into the release candidate needs Hannah's answer, which the orchestrator gets from a few lines of before and after.
7. **Evidence is bound to an exact SHA** at the gate. Check workers' diffs, not their summaries. Say what was not run.
8. **Decided; don't reopen:** P39-D8; Direct Journey `:426` keeps the draft, `:444` removed, `:708` keeps the auto-reload; the 659 Lanes failures are Plan 39's; the split (H5) and the decisions in the table below.
9. **Safety.** Never read `~/.codex`, `.env` files or credential files; name credentials, never print them. Don't work around a classifier or safety refusal. No model names in commits or PRs. Keep Hannah's email private. Never land the Windows update-refusal fallback `2f975f62`. No force-push or rebase. No paid GPU work in this release.
10. **Known traps.** Installer changes run every `tests/test_installer_*.py`, and the installer must import without third-party packages. The keep-going diagnostic covers only the fresh-install leg. VibeComfy is pinned in two places. The re-pin uses release number **12** (a provisional run used 13 and failed its Release 11 row for that reason).

### Roles

| Role | Who | Owns |
|---|---|---|
| **Orchestrator** | One session | Hannah's decisions, the gate review, the freeze label, publication. Checks in every three hours using cheap fact-finding sub-agents: what moved, what is stuck, what is waiting on Hannah. Not a relay for routine work |
| **Release 12 manager** | One high-judgment session | Everything in the [task list](12/fixes.md) through `GATE-GREEN`. Delegates to sub-agents cheapest-first, rules on findings, integrates, dispatches CI |

The manager messages the orchestrator directly, for three things only: a decision that is Hannah's, a label (`A-FROZEN`, `GATE-GREEN`), or a blocker it cannot clear in half a day. There are no mailboxes, relay labels or required consultations.

### Sequence

1. **Bring the candidates up to date.** Merge App `main` (the onboarding tour) into the App candidate; integrate the pushed Agent and App repairs.
2. **Get to green.** Direct Journey, App Tests, the affected Agent groups. Iterate freely.
3. **Freeze.** One Agent CI run and one review on the candidate; re-pin; App Tests, Direct Journey and the 11-row matrix on the exact tuple. Post `A-FROZEN`.
4. **Publish.** `GATE-GREEN`, Hannah's go on the exact SHAs, the Release skill, her Mac check.

**After a freeze, a fix means a new freeze:** new SHAs, and rerun only the checks the change can affect. Never relabel old proof as a new-SHA pass.
