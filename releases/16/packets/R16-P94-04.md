## What to do

1. Finding to bake in: the existing transfer already resumes from a `.<file>.astrid-resume` part with a `Range` request (`asset_alignment._ResumingClient`), refuses and deletes a file whose size or SHA-256 differs (`fetch_verified` raises `IntegrityError` that starts with the file name), and keeps the partial only on an interrupted transfer. What is missing is one total across files and a resume line; the per-file lines (`_progress`) restart at zero for each file.
2. Add `resume_summary(plan)` returning `None` when no file has a partial and otherwise `Picking up where we left off: <done> of <total> done.` where `done` is the sum of the plan's non-zero `partial_bytes` (from R16-P94-03; recompute from the part files if the key is absent) and `total` is `plan['total_bytes']`, both through `_size`. `apply_attached_model_download` prints it with `_say` once, after the checks and before the first fetch.
3. Change `_progress(name, total)` to `_progress(name, total, *, finished=0, grand_total=None)`. When `grand_total` is given, each report also prints `Downloading models: <finished + done> of <grand_total>` (through `_size`) at the same cadence (every `_PROGRESS_STEP` bytes or `_PROGRESS_SECONDS` seconds); the per-file line stays. `apply` passes `finished` = bytes of files already finished in this run and `grand_total` = `plan['total_bytes']`.
4. In `_stopped`, keep the existing text, and make sure a mismatch reads as refused: when the cause is an `IntegrityError` the message says `<file> did not match its checksum and was refused; its partial copy was removed.` before the `Finished in this run` sentence. The partial-kept sentence stays only when the part exists.
5. Write `tests/core/generation/test_download_progress_and_resume.py`. Use `serve_release` from `tests/core/generation/environment_states.py` and `httpx.Client()` passed as `http_client`/`client`, and call `asset_gaps._fetch_into_folder(item, client, progress=...)` directly with `item = {file, folder, url, sha256, bytes, hard_links: True}` for a real small file served by `serve_release(..., break_after=N)`. Cases: an interrupted transfer raises and leaves exactly one `.<file>.astrid-resume` part; a second call resumes with a `Range` request (see `server.requests`) and publishes a file with the right SHA-256; a served file whose bytes differ from `sha256` raises `IntegrityError`, leaves no final file and no part; `_progress` output (capture stderr with `capsys`) shows the running total across two files with `finished`; `resume_summary` for none, one and two partials; `_stopped` text for a mismatch and for an interrupted file (build the plan dict by hand). Apply-level: monkeypatch `_fetch_into_folder` and the plan function as in `test_download_space_budget.py` and assert the `Picking up where we left off` line is printed only when a partial exists.
