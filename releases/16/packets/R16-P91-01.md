**Route:** X (ChatGPT mode: Extra High; [run contract](../../../skills/shared/run-contract.md#chatgpt-session-modes))
**Estimate:** 3 days
**Outcome:** Every `ci:` row of the prune candidates is sorted into retire, redundant or keep under D5's support line; retired and redundant tests are deleted with their citation or covering test, one PR per area; every kept ID is handed back to its owning card.
**Dependencies:** none (day one). AG-A5 waits for this card's verdict on the installer tests.
**Proof:** AG-P1's Focused proof column: for each deletion, the citation or the covering test's ID, and a passing run of the covering tests in the worker environment; any refusal test passes. An `X` reviewer (the orchestrator's) reads every deletion list.
**PR destination:** astrid-agent: one branch per area, `p91/AG-P1-<area>` (for example `p91/AG-P1-runpod`), each its own PR → `release/16/plan-91`.
**Authority:** [run board](../run.md) (Plan 91 dispatch) and the [Run start](../../../plans/91-agent-main-green/inputs.md#planning-evidence).

## This card

- **Candidates:** the `ci:` rows of [prune-candidates.md](../../../plans/91-agent-main-green/evidence/release-15-514499de/prune-candidates.md); the card also owns outright the IDs in [cards/AG-P1.tsv](../../../plans/91-agent-main-green/evidence/release-15-514499de/cards/AG-P1.tsv) (the removed RunPod bootstrap entry point, the `astrid timeline publish` command, and the executors of packs moved to poms_packs under D10).
- **Also sort AG-A5's installer tests** ([cards/AG-A5.tsv](../../../plans/91-agent-main-green/evidence/release-15-514499de/cards/AG-A5.tsv)): the R0 and R1 copy-only boundary and older installs are retired; updating from the previous published release, failure recovery, retry and the busy-owner refusal are kept.
- **Test deletions only; no product code.** Where a user could still reach the old path today (an API route, a command, a file the App opens), keep or add a test that it refuses, as with `410 retired_route`.
- **Every PR body has one table:** `id | verdict (retire / redundant / keep) | citation, or covering test id and what both assert | owning card (for keep)`. Post the kept list on the mailbox as soon as each area is sorted, before its PR, so the owning cards can start on them.
- Be bold with what is old and careful with what is current: a test of something users do today is never deleted for being hard to fix.

## Rules for every Plan 91 packet

- **Base:** astrid-agent `release/16/plan-91` (cut at `514499de` on 24 November 2026; Plan 91 is in Release 16). The orchestrator merges its base (`release/15/main`, then `release/16/main`) into it; a packet never does. Never rebase a shared branch.
- **[Triage rules](../../../plans/91-agent-main-green/tasks.md#triage-rules) 0–6, in order.** Reproduce first; name one kind per cause with evidence; fix only the way that kind allows; change only the card's scope; prove by ID; stop and report at twice the estimate.
- **Prune first (rule 0).** An ID in [prune-candidates.md](../../../plans/91-agent-main-green/evidence/release-15-514499de/prune-candidates.md) is AG-P1's or AG-P2's to sort: leave it until the orchestrator posts that ID's verdict on the mailbox, then fix it only if it is kept.
- **Never:** edit `ci/agent-ceiling.tsv`, add to a skip, deselect or xfail list, loosen an assertion, stub an input, widen a deadline, or move a pin (post `READY-PIN`). Changing an existing assertion beyond what the triage rules allow is the owner's: stop and post a `REQUEST`.
- **Proof runs where the network is.** The packet's own proof is its focused tests in the worker environment: `bash scripts/worker-env/agent-setup.sh` once, then `bash scripts/worker-env/agent-pytest.sh -q -rA <files>` by literal path. Then post `READY-PROOF astrid-agent <PR> <head> <files or ids>` on the [mailbox](https://github.com/banodoco/astrid-dev/issues/1826); hosted runs and the batch comparison are the orchestrator's. Never dispatch CI.
- **Every PR body** lists: each ID with its kind and the cause's one-line evidence; the IDs that still fail with their new first-failure line; any deletion with its citation or covering test; and the output of astrid-dev `env/baseline-diff.py` (standard library only; read it through the connector, as astrid-agent has no copy) on base and head for the card's files and the files that import the changed code (rule 5).
- **Rulings from Release 15's first dispatches** ([Plan 82 rulings](../../15/run.md#rulings-for-plan-82-from-the-first-three-dispatches)), as they apply here:
  - *No network, no hosted test.* The IDs that already fail on the plan branch are this card's list; its focused selectors are the test files in it.
  - *Pass unchanged.* Every test in the card's files that passes on the base still passes. An existing assertion changes only as the triage rules allow (a stale-test fix with its stated source, or a D5 deletion with its citation), each listed in the PR. If the card can't be done that way, post `BLOCKED` once with the exact list rather than arguing it over several rounds.
  - *About three hours per PR.* A card larger than that is delivered as consecutive PRs at its natural seams, each reviewable alone.
  - *Sweeps carry their count.* A change to a pattern across call sites lists every site found and every site changed, before the first review.

One packet starts **one fresh ChatGPT session**. The session opens task PRs and submits proof, **but does not merge or edit `tasks.md`**. The orchestrator reviews, integrates and reconciles tasks; the manager reports the handoff in its hourly STATUS.
