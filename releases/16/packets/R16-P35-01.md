## What to do

1. Create `astrid/core/user_state.py`, standard library only at import time. Constants: `APP_STATE_MAX_BYTES = 16 * 1024` (the Runtime refuses larger documents: `RuntimeService.APP_STATE_MAX_BYTES`), `KEY_PATTERN = re.compile(r"[a-z0-9][a-z0-9._-]{0,63}")` (the Runtime key rule). Class `UserStateError(Exception)` with `.code` (one of `invalid_key`, `too_large`, `unavailable`, `conflict`, `rejected`), `.key` and `.status` (int or None).
2. Add `content_digest(content) -> str`: `"sha256:" + sha256(json.dumps(content, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode()).hexdigest()`. Add `encoded_size(content) -> int` using the same JSON text (UTF-8 bytes). Add `check_key(key)` and `check_size(key, content)` raising `UserStateError` with codes `invalid_key` and `too_large` (the message names the key, the size and the limit).
3. Store plumbing, copied in spirit from `generation/settings.py` but independent of it: a `ContextVar` store, `using(store)` context manager, `set_store_factory(factory_or_None)`, and `current_store() -> store | None`. Order: `using` value, then the factory, then the default opener. The default opener lazily imports `astrid.sdk.client.AstridClient`, calls `AstridClient.open_existing_from_launcher()` (never `open_from_launcher`: it must not start a Runtime), takes the app-state transport (`client` itself if it has `get_user_app_state`, else `getattr(getattr(client, "_remote", client), "_transport", None)`), caches the result for the process, and caches a failure as `None` so a missing Runtime is probed once. `reset_default_store()` clears that cache (tests). Any exception from the opener means `None`.
4. Add `@dataclass(frozen=True) class Document: content: dict | None; version: int`. Add `read(key, *, store=None) -> Document`: check the key; use `store` or `current_store()`; no store raises `UserStateError("unavailable")`. The transport returns either a mapping with `content` and `version` or an object with those attributes (the generated client's `AppStateResource`); accept both. A transport `OSError`/`ConnectionError`/`TimeoutError` becomes `unavailable`; an exception with `.status == 409` becomes `conflict`; any other exception with a `.status` becomes `rejected` carrying the status.
5. Add `write(key, content, *, expected_version, idempotency_key, store=None) -> Document`: check key and size BEFORE any call; call `store.update_user_app_state(key, dict(content), expected_version=..., idempotency_key=...)`; map errors as in `read`. Add `idempotency_key_for(key, version, content) -> str` returning `f"{key}.v{version}.{content_digest(content)[7:23]}"` (the Runtime accepts `[A-Za-z0-9][A-Za-z0-9._~-]{0,255}`).
6. Add `update(key, change, *, validate=None, store=None, attempts=3) -> Document`: read the document, deep-copy its content (or `{}`), call `change(copy)` (it edits in place), run `validate(copy)` if given (it returns the normalized dict or raises), and return the `Document` it read, with no write, when the result equals the current content (also when the document does not exist and the result is `{}`). Otherwise write with the version it read. On a `conflict`, re-read and re-apply `change` to the fresh content, up to `attempts` times, then raise `UserStateError("conflict")`.
7. Create `tests/user_state_fakes.py` with `FakeApiError(RuntimeError)` (`.status`, `.code`) and `InMemoryAppState`. It behaves like the Runtime: `get_user_app_state(key)` returns `{"content": copy_or_None, "version": int}`; `update_user_app_state(key, content, *, expected_version, idempotency_key)` raises `FakeApiError(422, "validation")` for a bad key (same regex), non-dict content or content over 16 KiB (same JSON text as `encoded_size`), raises `FakeApiError(409, "version_conflict")` when `expected_version` differs from the stored version, replays the first result for a repeated `(key, idempotency_key)` even if the version has moved, and stores deep copies. Test hooks: `self.unreachable = False` (when true every call raises `ConnectionError`), `self.fail_writes = set()` (1-based write attempt numbers that raise `ConnectionError` before changing anything), and `self.writes` (list of `(key, expected_version)` for every accepted or failed write attempt).
8. Write `tests/test_user_state.py` against that fake (use `user_state.using(store)` or the `store=` argument; never touch a real Runtime). Cases: key and size refusals happen before the transport is called (`store.writes == []`); read of a missing document gives `Document(None, 0)`; update creates, then updates, then a no-change update writes nothing; two writers: a conflict injected between read and write is retried and both edits survive; a persistent conflict raises `conflict` after exactly `attempts` reads; `unreachable` gives `unavailable` for read, write and update; no store in scope and a factory returning `None` give `unavailable`; the default opener is never called when `using(...)` is active (monkeypatch `reset_default_store` target to fail if opened); a document of exactly 16 KiB is accepted and 16 KiB plus one byte is refused; `idempotency_key_for` output matches the Runtime key grammar and is stable for the same content.

## Done when

- `read`, `write` and `update` work against `InMemoryAppState` as listed, with the error codes named above.
- A key or size problem is refused before any Runtime call.
- A missing Runtime gives `UserStateError("unavailable")`, never a hang or a traceback from the transport.
- `astrid/core/user_state.py` imports nothing from `astrid` at import time and contains no `Path.home()`, `XDG_*` or file access.
- The Proof passes.
