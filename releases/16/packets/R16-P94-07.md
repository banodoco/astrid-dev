## What to do

1. Layout under the destination `D` (bake in exactly): `D/.astrid-install/journal.json` (`{schema: "astrid.comfy-install-journal.v1", offer_sha256, release, phase, renaming}`; `phase` is `started`, `downloaded`, `extracted` or `complete`), `D/.astrid-install/lock` (a `filelock.FileLock`), `D/.astrid-install/archive/<archive_name>` and `<archive_name>.part`, `D/.astrid-install/staging/`, `D/<inner_directory>/` (the final root), `D/.astrid-install/receipt.json`. Write the journal atomically (write a temp file in the same folder, `os.fsync`, `os.replace`). Nothing outside `D` is ever written.
2. Define `Steps` (a frozen dataclass of three callables): `download(pin, archive_path, part_path, progress)` (raises on failure; leaves the verified archive at `archive_path`), `extract(archive_path, staging_dir, pin)` and `missing(root, pin)` returning the list of `required_files` absent under `root`. Define `InstallResult` as a dict `{status: "installed" | "already_installed", resumed_from: None | phase, root, comfy_dir, python, release, kept_previous: None | path}` where `root = D/<inner_directory>`, `comfy_dir = root/ComfyUI` and `python = root/python_embeded/python.exe`.
3. `install_portable(destination, consent, *, pin=None, steps, platform=None, gpu=None, disk_usage=shutil.disk_usage, environ=None, progress=None)`: (1) `consent` must be a string equal to the fresh `build_offer(...)['offer_sha256']`; `None` raises `PortableError('consent_required')`, a different value `consent_mismatch`, and a refused offer raises `PortableError(refusal code)`, in each case before any file or folder is created. (2) Create `D/.astrid-install/` and take the lock with `FileLock(timeout=0)`; if held, raise `install_in_progress`. (3) Read the journal. No journal: write phase `started`. Same `offer_sha256`: resume. A journal with a different `offer_sha256`: raise `consent_mismatch` and change nothing.
4. Phases: `started` -> call `steps.download` (the step itself resumes its `.part`), then set `downloaded`. `downloaded` -> delete `D/.astrid-install/staging` if present (only that path), call `steps.extract(archive, staging, pin)`, check `steps.missing(staging/<inner_directory>, pin)` is empty (else `PortableError('archive_incomplete')`, leaving the archive for inspection), set `renaming: true` in the journal, `os.replace(staging/<inner_directory>, D/<inner_directory>)`, then set phase `extracted`. `extracted` -> delete the archive and part files, write `receipt.json` (`release`, `root`, `python`, `installed_at` as a UTC ISO string) and set `complete`. Crash recovery for the rename: journal `renaming: true`, final root present, staging absent and `missing` empty counts as `extracted`; a final root present in any other `downloaded` situation raises `destination_changed` and touches nothing. Progress callbacks go to `progress(phase, done_bytes, total_bytes)`.
5. `complete` journal: if `steps.missing(final root)` is empty return `already_installed` and touch nothing (no write, no mtime change; take no lock if you cannot without writing, otherwise take it and release it). If files are missing, the earlier install is kept, not deleted: rename `D/<inner_directory>` to `D/<inner_directory>.broken-<UTC yyyymmddThhmmss>`, reset the journal to `started` for the same offer digest, install again, and report the new folder in `kept_previous`. Nothing the journal did not create is ever deleted or renamed, and the earlier install is never deleted.
6. Extend `build_offer` for state `ours`: add `resume: {phase, done_bytes}` (bytes under `D/.astrid-install/archive` and `staging`, measured with `stat`) and subtract `done_bytes` from the space it requires, without changing `offer_sha256`. A `complete` destination whose files are present returns status `offered` with `state: "complete"` and `works` unchanged (so a second apply is accepted as a no-op).
7. Write `tests/core/generation/test_comfy_portable_install.py` using fake steps built in the test (download writes a small archive file and counts calls; extract writes the required files into `staging/<inner_directory>`) and `snapshot`: no consent, wrong consent, a refused offer (low disk, foreign destination, unsupported GPU) each raise and leave the machine snapshot unchanged and the destination absent; a full install ends `complete` with a receipt, no archive left, and the right paths; a second `install_portable` is `already_installed` with an unchanged snapshot and zero step calls; an interruption (the extract step raises after the files are written) then a rerun resumes at `extract` with zero new download calls; an interruption inside download (raises after writing part) resumes with a second download call and finishes; a stale `staging` folder is replaced; a crash between rename and the `extracted` journal write (simulate by raising from the journal write) recovers without extracting again; a held lock (open a second `FileLock`) raises `install_in_progress`; a different offer digest in the journal raises `consent_mismatch`; deleting `python_embeded/python.exe` from a complete install then rerunning keeps the old folder as `.broken-*` with its contents intact and installs a new one; a file the person put in `D` before the install (the `foreign` case) is refused and never modified.

## Done when

- An interrupted install resumes from verified work or is replaced under the same consent, never admitted half-done, and a second run is a no-op.
- Decline, wrong consent, low disk, an unsupported GPU and a foreign folder write nothing.
- Nothing that the journal did not create is deleted, and a broken earlier install is kept.
