## What to do

**The ladder contract** (written by R16-P93-02 in `astrid/core/generation/preflight.py`, section "Readiness ladder"; do not change it): seven ordered rungs `installed, reachable, identified, compatible, computes, workflow_ready, delivered`; a ladder has a `through` rung (the last rung this answer owns; never `delivered`); each rung is `{rung, owner, state, observation, reason, message}` with `state` one of `observed | failed | unchecked`; `readiness_envelope(..., ladder=, next_action=)` reads `ready` only when every rung up to `through` is `observed`, otherwise it is `blocked` with one error issue and exactly one `next_action`; no timestamps or durations anywhere; an envelope built without a `ladder` is exactly what it was before.

An **installation observation** is `{"layout": "desktop", "state": <state>, "version": str|None, "endpoint": "http://127.0.0.1:<port>" (where it answers when running, else where it is expected), "recorded": {"executable": str|None, "data_dir": str|None}, "files": {"executable": bool, "data_dir": bool}, "responder": {"kind": "comfyui"|"other"|"denied"|"none", "port": int|None, "base_dir": str|None, "matches_install": bool|None}}`, and `<state>` is one of `running | closed | stale | wrong_responder | denied | ambiguous`.

In `GenerationFacade.targets` (local branch, where R16-P93-04 builds the ladder):

1. Read installations once: `desktop_install.observe_installations()` (empty and request-free where no Desktop is registered). **Bound selection** (`selection.bound`, an explicit URL, a saved target or the Runtime placement): pick the installation whose `endpoint` equals `record.endpoint`, if any, and pass it as `installation=` to `preflight.observe_target_rungs` and `ladder_next_action`. **Unbound discovery** (`not selection.bound`, the 8188 default): `servers = astrid.packs.vibecomfy.local.scan([8188, 8000])["servers"]` (any exception means `[]`), `choice = desktop_install.select_candidate(installations, servers)`.
   - `one`: replace `record` with `TargetRecord(endpoint=<that choice's endpoint>)` (nothing is saved), set the placement block from `TargetSelection(record, "discovery", False)`, observe it (with its installation if it is the Desktop one), and, when the ladder has no stop, set `next_action` to the agent action `make_next_action("agent", "Use the ComfyUI at <url> for generation, once the person says yes.", argv=["astrid", "generate", "settings", "set", "placement", <url>])`. This is the existing consented placement command; the skill asks first.
   - `several`: the ladder stops at `identified`, reason `several_installs`, with `next_action` a person action whose `choices` lists each choice's `label` and `endpoint`. No placement command is offered.
   - `none` with exactly one `not_running` installation: use that installation (its endpoint as `record`), which reads `closed`, `stale`, and so on.
   - `none` otherwise: the default 8188 record, as R16-P93-04.
   In every ladder answer set `payload["summary"] = preflight.ladder_summary(ladder, url=record.endpoint, installation=installation)` (a new top-level string; managed and RunPod answers carry none).
2. `save=True` guard: when the ladder's stop reason is `not_this_install`, `cannot_tell_which_install` or `not_comfyui`, raise `GenerationInputError("refusing to save a target that is not your ComfyUI: <reason>")` before anything is written (no config write, no settings write). Closed, not answering, denied and stale still save exactly as before.
3. Unsupported here: add reason `not_supported_here` (rung `installed`) to `LADDER_REASONS` and `LADDER_TEXT` (person; message "ComfyUI Desktop is only supported on Windows here."; step "Use a running ComfyUI Portable, Git or Pinokio copy, or ask me about a separate copy."). Add `preflight._platform()` returning `sys.platform`. When `record.layout == "desktop"` and `_platform() != "win32"`, the ladder fails `installed` with that reason (no probe). Tests monkeypatch `_platform`.
4. Write `tests/core/generation/test_generate_targets_desktop.py`. Monkeypatch `Path.home` to `tmp_path`, delete `VIBECOMFY_COMFYUI_URL`, monkeypatch `desktop_install.observe_installations`, `astrid.packs.vibecomfy.local.scan` and `preflight._comfy_get_json`; build installations with `desktop_install.classify` from the fixtures. Cover:
   - a bound URL equal to Desktop's endpoint, for each of running (`ready`, no action), closed, stale, wrong_responder, denied and ambiguous (each `blocked`, its reason, one fix, one next action);
   - in all of those, and in the unbound several-installs case, nothing was written: no `.vibecomfy` directory, and `generation_settings_store.documents` (the conftest fixture) unchanged;
   - `save=True` is refused (`GenerationInputError`, nothing written) for wrong_responder and ambiguous, and still saves for closed;
   - unbound: one running Desktop gives `ready` with the attach action and `payload["target"]["endpoint"]` the Desktop's; Desktop plus a Portable server gives `several_installs` with two `choices` and no `settings set placement` anywhere in the payload; only a stale Desktop reads stale; nothing found reads `not_answering` on 8188;
   - a "declined" run: after any of the above, call `targets()` again and show the payload is unchanged and nothing was written (declining means the agent simply does not run the command);
   - `not_supported_here` with `_platform` patched to `linux` for a saved record with `layout="desktop"`;
   - `payload["summary"]` equals `preflight.ladder_summary(...)` in each case; and the only payloads whose `next_action["argv"]` is a `settings set placement` command are the unbound one-ready ones.
