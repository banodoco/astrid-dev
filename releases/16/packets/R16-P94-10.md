## What to do

1. In `cli.py`, beside `fetch-models`, add `command = sub.add_parser('install-comfyui', help='Show, then on confirmation set up, a separate ComfyUI Portable install on this computer.')` with `--destination` (default: `comfy_portable.default_destination`), `--apply` (metavar `OFFER_SHA256`) and `--json`. In `_main_request` dispatch `parsed.modality == 'install-comfyui'` to `comfy_portable.main(parsed)` (lazy import, like `fetch-models`).
2. `main(parsed, *, steps=None)`: without `--apply`, build the offer and print `render_offer` (or the offer dict with `--json`); exit 0 when `offered`, 2 when `refused`; nothing is written. With `--apply`, call `install_portable(destination, parsed.apply, steps=steps or default_steps(), progress=<prints to stderr: 'Downloading ComfyUI: <done> of <total>', 'Picking up where we left off: <done> of <total> done.' when the journal shows earlier progress, 'Unpacking ComfyUI', 'Checking the install'>)`, then `attach_installation(result)`, and print one JSON object (or text with a sentence per field) `{status, root, python, endpoint, kept_previous, previous_target, undo, next_action: {who: 'person', text: <start text>}, then: 'astrid generate targets --json'}`; exit 0. A `PortableError` prints `{'error': {'code', 'message'}}` to stderr and exits 1; an offer that is no longer the confirmed one exits 1 with code `consent_mismatch` and the new offer's text on stderr. Progress goes to stderr so `--json` keeps stdout to the result.
3. Never run any shell, installer or downloader other than through `default_steps()`; the command takes no URL or archive from its arguments (the release comes only from the pin).
4.
