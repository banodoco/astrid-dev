## What to do

Bug 1 (found): `_peer_token`, `current_process_audit_token` and `signal_audit_token` raise "Darwin audit-token custody is unavailable" on every OS but macOS, and the host calls them everywhere. Bug 2 (found): `default_process_identity` returns `ps-lstart:...` from `/bin/ps` on Linux, while the Runtime writes `proc-start-ticks:...;boot:...;pidns:...`, so the host-only preparation check (`generic_host._prepare_host_only`, "host-only preparation is not from original Runtime peer") can never match.

1. At the top of each of `audit_token_details`, `_peer_token`, `current_process_audit_token`, `signal_audit_token`, add: `from runtime_protocol import process_binding` (at module top with the other imports) and `if process_binding.backend() in ("linux", "windows"): return process_binding.<details|peer_token|token|signal>(...)`. For `signal_audit_token` keep the existing `_admitted_signals()` check first. Darwin keeps its own code below; the non-Darwin `raise CustodyError("Darwin audit-token custody is unavailable")` stays for "other" OSes. Wrap provider errors that callers catch today: let `LinuxBindingError`, `ProcessBindingError` and `OSError` pass through unchanged.
2. In `default_process_identity`: for every OS except Darwin return `platform.process_identity(pid, timeout=timeout)` (it already raises `OSError` on unknown observation: convert that to `CustodyError("process identity observation failed")` to keep this function's contract, and keep the `timeout <= 0` check). Delete the `/bin/ps` `subprocess.run` block and the `"ps-lstart:" + parts[2]` Linux encoding. Keep the Darwin branch and `_ps_lstart_birth` (Darwin only).
3. Write `tests/core/execution/test_custody_provider.py` (no network; a platform `pytest.mark.skipif` is allowed in Agent tests):
   - `test_private_peer_verifies_on_every_os`: over `socket.socketpair()`, `AuthenticatedCleanupActor.private_peer(a).verify()` returns a dict whose `pid` is `os.getpid()`; and `AuthenticatedCleanupActor.current().verify()` does too.
   - `test_agent_and_runtime_birth_ids_agree`: for `os.getpid()` and for a live sleeper child, `default_process_identity(pid)["birth_id"] == runtime_protocol.platform.process_identity(pid)["birth_id"]`.
   - the host-only peer comparison: build a Runtime-owner dict from `platform.process_identity(os.getpid())` (`pid`, `uid`, `birth_id`) and assert `all(actor.verify()[k] == owner[k] for k in ("pid", "uid", "birth_id"))` for `AuthenticatedCleanupActor.private_peer(a)` over a socketpair (this is the exact comparison in `_prepare_host_only`).
   - `test_signal_audit_token_reaches_only_the_token_owner` (Linux, pidfd available else the existing lane mark): token of a sleeper child, `signal_audit_token(words, platform.TERM)` ends it; a token with flipped start ticks raises and the child survives; `signal.SIGHUP` raises `CustodyError`.
   - Windows dispatch with fakes: `monkeypatch.setattr(process_binding, "_platform", lambda: "win32")` and fake `platform.handoff_*` functions; `_peer_token`, `current_process_audit_token`, `audit_token_details`, `signal_audit_token` reach them.
   - `test_default_process_identity_never_runs_ps`: patch `subprocess.run` to fail the test, call `default_process_identity(os.getpid())`.
