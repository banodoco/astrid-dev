## What to do

**The ladder contract** (written by R16-P93-02 in `astrid/core/generation/preflight.py`, section "Readiness ladder"; do not change it): seven ordered rungs `installed, reachable, identified, compatible, computes, workflow_ready, delivered`; a ladder has a `through` rung (the last rung this answer owns; never `delivered`); each rung is `{rung, owner, state, observation, reason, message}` with `state` one of `observed | failed | unchecked`; `readiness_envelope(..., ladder=, next_action=)` reads `ready` only when every rung up to `through` is `observed`, otherwise it is `blocked` with one error issue and exactly one `next_action`; no timestamps or durations anywhere; an envelope built without a `ladder` is exactly what it was before.

1. Add `observe_target_rungs(record, *, get_json=None) -> ladder` to `preflight.py`. `record` is a `TargetRecord` (`astrid/core/generation/targets.py`) that is human-owned with an `endpoint`; any other record is a `ValueError`. `get_json(url, path)` returns parsed JSON or raises; when `None`, use the module-level `_comfy_get_json` looked up at call time (so tests can monkeypatch it). Return `new_ladder("compatible")` with these rungs set (a failed rung leaves every later rung `unchecked` with reason `not_reached`, and no further probe runs):
   - `installed`: if `record.root` is `None`, observed with `{"identity": "endpoint_only"}` (an explicit endpoint has no filesystem identity to check); if `root` is set, observed with `{"root_exists": True}` when `Path(root).is_dir()`, else failed, reason `files_missing`.
   - `reachable`: `get_json(url, "/system_stats")`. Success is observed with `{"endpoint": url}`. A failure classified `access_denied` or `not_answering` (see step 3) is failed with that reason. A failure classified `answered_not_comfyui` means something answered, so `reachable` is observed and `identified` fails (below).
   - `identified`: the stats must be a dict with a dict under `"system"` (the same test `_select_generation_target` uses, so existing stand-in servers still count). Observed with `{"tied_to_install": False}`. Otherwise failed, reason `not_comfyui`.
   - `compatible`: `get_json(url, "/object_info")` must be a non-empty dict. Observed with `{"comfyui_version": <system.comfyui_version if a string, else None>}`. Otherwise failed, reason `api_unsupported`.
   - Messages and observations contain no exception text, no timing and no timestamps, so repeated calls are equal.
2. Add `_comfy_get_json(url, path)`: builds `ComfyTargetClient(ComfyTarget(url, "attached"))` (`astrid/core/generation/backends/comfy_target.py`) and calls `request_json(path, timeout=1.0)` for `/system_stats` and `/internal/folder_paths`, and `request_json("/object_info", timeout=5.0, response_limit=MAX_JSON_BYTES)` for the schema. Note that `request_json` wraps every `OSError` and `URLError` in a `ValueError("... request failed")` whose `__cause__` is the original.
3. Add `_failure_kind(exc)`: walk `exc`, then each `__cause__` and `.reason`, up to 6 links. If any link has an integer `.code` (an HTTP error) return `answered_not_comfyui`. Else if any link is a `PermissionError` return `access_denied`. Else return `not_answering` (refused, timed out, reset, any other `OSError`, or an unexpected exception type). It never raises.
4. Add `LADDER_REASONS` (dict `reason -> rung`) holding `files_missing: installed`, `not_answering: reachable`, `access_denied: reachable`, `not_comfyui: identified`, `api_unsupported: compatible`. Later packets add Desktop reasons to it, so build it as a plain module-level dict. Add `LADDER_TEXT` (dict `reason -> {"message", "step", "who"}`); this is the one place person-facing text lives. Provisional wording:
   - `files_missing` (person): message "The folder recorded for this ComfyUI no longer exists."; step "Tell me the address of a ComfyUI that is running, or reinstall it, then ask me to check again."
   - `not_answering` (person): message "Nothing is answering at {url}."; step "Start your ComfyUI so it answers at {url}, then ask me to check again."
   - `access_denied` (agent): message "Access to {url} was denied."; step "Retry the same check through the normal permission request."
   - `not_comfyui` (person): message "Something that is not ComfyUI answers at {url}."; step "Close it, or tell me the address of your ComfyUI."
   - `api_unsupported` (person): message "The ComfyUI at {url} does not offer the API Astrid needs."; step "Update that ComfyUI, then ask me to check again."
5. Add `ladder_next_action(ladder, *, url=None, installation=None)`: `None` when `ladder_stop` is `None`; otherwise build the action with `make_next_action` from `LADDER_TEXT[stop reason]` (format `{url}`; unknown reasons use the default step from R16-P93-02). A person action gets `then_argv = ["astrid", "generate", "targets", "--placement", url or "auto"]`; the agent action's `argv` is that same command. Also put each rung's `message` from `LADDER_TEXT` into the rung when `observe_target_rungs` fails it. (`installation` is unused until R16-P93-07; accept it and ignore it.)
6. Write `tests/core/generation/test_target_rungs.py` with an injected fake `get_json` (no sockets) and `tmp_path` for roots. Cover:
   - endpoint-only record, healthy fake: all four rungs observed, `through == "compatible"`, `ladder_stop` is `None`, and wrapping it in `readiness_envelope` gives `ready`;
   - a record whose `root` was removed: `installed` failed `files_missing`, the other three `unchecked` `not_reached`, and the fake was never called;
   - `URLError(ConnectionRefusedError)` raised through a `ValueError` wrapper with `__cause__` set: `reachable` failed `not_answering`, one person action with `then_argv` carrying the URL;
   - the same with `PermissionError`: `access_denied`, an agent action whose `argv` is the targets command;
   - an `HTTPError` 404 on `/system_stats`: `reachable` observed, `identified` failed `not_comfyui`;
   - stats lacking `system`: `not_comfyui`; `/object_info` raising, or returning `[]`: `api_unsupported`;
   - an unexpected `RuntimeError` from the fake never escapes and reads `not_answering`;
   - a managed (`owner="astrid"`) record or one with no endpoint raises `ValueError`;
   - two runs give equal ladders and `json.dumps` works;
   - the default `_comfy_get_json` path: monkeypatch `ComfyTargetClient.request_json` to raise `ValueError` from a `URLError(PermissionError)` and check `access_denied` end to end.

## Done when

- A healthy attached endpoint yields four observed rungs; every failure names its rung, a stable reason and exactly one next action.
- A failed rung stops probing, and no exception text or timing is in the result.
- The reason table covers every reason the code can emit.
