## What to do

**The ladder contract** (written by R16-P93-02 in `astrid/core/generation/preflight.py`, section "Readiness ladder"; do not change it): seven ordered rungs `installed, reachable, identified, compatible, computes, workflow_ready, delivered`; a ladder has a `through` rung (the last rung this answer owns; never `delivered`); each rung is `{rung, owner, state, observation, reason, message}` with `state` one of `observed | failed | unchecked`; `readiness_envelope(..., ladder=, next_action=)` reads `ready` only when every rung up to `through` is `observed`, otherwise it is `blocked` with one error issue and exactly one `next_action`; no timestamps or durations anywhere; an envelope built without a `ladder` is exactly what it was before.

1. In `GenerationFacade.targets` (`astrid/sdk/generation.py`, search for "Inspect selection without probing"), after the existing validation and after `record` is settled, handle only the local, non-RunPod path. If `record` is human-owned and has an `endpoint`: import `preflight` lazily, `ladder = preflight.observe_target_rungs(record)`, `action = preflight.ladder_next_action(ladder, url=record.endpoint)`, and build `payload = readiness_envelope(target=record, ladder=ladder, next_action=action)`. Keep `payload["placement"] = generation_listing.placement_block(selection)` as today. Managed or `record is None` selections (including `--placement managed`) stay on the old path and carry no `ladder` key. The RunPod branch is untouched.
2. Keep every existing early refusal first (unsupported engine, `local target input updates are not supported`, `select an explicit target before saving`); probe only after them. `save=True` still saves exactly what it saved before, then returns the probed answer; a blocked ladder does not stop a save in this packet.
3. Update the method docstring: it now probes the selected attached endpoint (read-only GETs, `/system_stats` and `/object_info`), writes only on an explicit `save`.
4. Write `tests/core/generation/test_generate_targets_ladder.py`. Each test sets `monkeypatch.setattr(Path, "home", lambda: tmp_path)`, deletes `VIBECOMFY_COMFYUI_URL`, and monkeypatches `preflight._comfy_get_json` with a fake; pass an explicit URL placement (for example `http://127.0.0.1:18111`), never `auto`. Cover:
   - a healthy fake: `status == "ready"`, `ladder["through"] == "compatible"`, `ladder["stopped_at"] is None`, `next_action is None`, and `payload["target"]["endpoint"]` and `payload["placement"]` as before;
   - a refusing fake: `blocked`, one issue `target_unreachable`, one fix, `next_action["who"] == "person"`, and the `then_argv` re-runs `generate targets --placement <url>`;
   - `--placement managed` returns the old shape with no `ladder` key;
   - without `save`, nothing is written (no `.vibecomfy` directory under the fake home); with `save=True` and the refusing fake, the config file is written with that endpoint and the answer is still `blocked`;
   - two identical calls return equal payloads; the CLI path `cli.main(["targets", "--placement", url, "--json"])` prints the same payload as the facade (set `cli._open_client` to fail the test, as `test_workflow_input_a01.py` does).
