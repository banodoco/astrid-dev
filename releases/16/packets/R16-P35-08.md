## What to do

1. In `astrid/core/compute_profile.py` add `RUNTIME_KEY = "agent.compute-profiles"` and a document shape `{"schema": "astrid.compute-profiles.v1", "profiles": {<id>: <validated profile>}}`. Add a module sentinel `_AUTO = object()` and a `store=_AUTO` keyword to `load_profile` and `resolve_compute_profile`. Rule: an explicit `home` (as every current test passes) means files only; `store=None` means files only; `store=_AUTO` with `home is None` uses `user_state.current_store()` (which may be `None`, meaning files); an explicit store object uses the Runtime. Existing behaviour with `home=` must not change at all.
2. Runtime-backed `load_profile(profile_id, store=...)`: read the document; if it does not exist, call `user_state_import.run_import` with `import_id="compute-profiles"`, `source_label="~/.astrid/compute-profiles/*.json"`, a `read_source` that loads each `*.json` in `profile_dir()` that passes `validate_profile` (invalid files are skipped, never raised) and returns `{id: profile}` or `None` when none are valid, and re-read. Then return `(validate_profile(profiles[id], expected_id=id), Path(f"runtime:{RUNTIME_KEY}/{id}"))`; an id that is not in the document raises the same `FileNotFoundError` text as today (`compute profile 'x' not found at ...`, with the runtime location). If the store is unreachable, fall back to the files exactly as today. `resolve_compute_profile` keeps its precedence (explicit field > env selected > named/default > executor defaults), including `ASTRID_COMPUTE_PROFILE`, and reports `profile_path` as that `runtime:` string when the profile came from the Runtime.
3. Add `save_profile(document, *, store=_AUTO)` (validate with `validate_profile`, then `user_state.update(RUNTIME_KEY, ...)`; no reachable Runtime raises `RuntimeError("the Runtime is not reachable; the compute profile was not saved")`; a document that would pass 16 KiB raises `ValueError` naming the limit and the profile id), `remove_profile(profile_id, *, store=_AUTO) -> bool` and `list_profile_ids(*, store=_AUTO) -> list[str]`. Saved profiles are validated again on read. A save before any import first runs the import so the files are not lost.
4. Credentials stay environment-variable NAMES (`_validate_env_ref`); a literal key such as `rpa_...` or `sk-...` is refused on save and skipped on import. No secret is ever read or written here.
5. Write `tests/core/test_compute_profile_runtime.py` with `InMemoryAppState` and an explicit `store=`: fresh profile (document present, no files) resolves; files import once (receipt present) and a later edit of the file is ignored while the document wins; precedence cases mirrored from `tests/core/test_compute_profile.py` (explicit field beats env profile beats default) against the Runtime store; `ASTRID_COMPUTE_PROFILE` selects a Runtime profile; unreachable store falls back to files; `home=` with a store object present still uses files only; save, list and remove round-trip; a literal secret is refused; an oversize set of profiles raises `ValueError`; `write_resolved_snapshot` output contains no value read from a credential variable.
