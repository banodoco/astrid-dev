## What to do

1. `process_birth_identity(pid)` on Linux: `identity = platform.process_identity(pid)`; return `identity["birth_id"]`, or `""` when it is `None` or `OSError` is raised (same "empty when gone or unreadable" contract as before). Win32 and other branches stay.
2. `_zombie_birth_identity(pid)`: return `process_binding.zombie_birth(pid, proc_root=_PROC_ROOT)` (the module's `_PROC_ROOT` stays so fixtures can point it at a fake tree). Remove its own `/proc` and `boot_id` reads.
3. `_linux_process_snapshot()`: call `process_binding.census(proc_root=_PROC_ROOT)` and convert: each `entries` row to `_ProcessInfo(pid, parent_pid, pgid, birth_id, uid=uid, session=session)`, `exited` into `census.exited`, and a non-None `failure` to `_failed_census(failure)`. Delete `_linux_process_record` and the body that read `/proc` directly. In `_parse_census` and `_linux_ppid` remove the Linux-only branches (the `ps` census is only used where `/proc` is not): births there are `"ps-lstart:" + fields[3]`.
4. `custody_broker._checked_pid_target(pid, birth, held)`: replace the regular-expression translator (`proc-start-ticks:...;boot:...;pidns:...` against `"<boot>:<ticks>"`) with `platform.process_birth_matches(birth, runtime_birth) is True`; anything else (False, None) returns `None`. A recorded `<boot-uuid>:<ticks>` birth therefore yields `None` and is never signalled.
5. Run the Proof. Update only the old-form birth strings and fake-`/proc` census fixtures in the existing tests listed in May touch (for example `"boot:500"` becomes `"proc-start-ticks:500;boot:boot"` in the fake-tree tests, because the fake tree has no `ns/pid`). Do not weaken or delete an assertion.
6. Write `tests/core/execution/test_birth_provider.py` (Linux; platform `pytest.mark.skipif` is allowed):
   - `process_birth_identity(os.getpid()) == platform.process_identity(os.getpid())["birth_id"]`; it is `""` for an absent pid.
   - `held_child_birth_identity` of a child that exited but is not reaped equals the birth id seen while it lived; `_zombie_birth_identity` is `""` for a live child.
   - `_process_snapshot()` lists `os.getpid()` with the same `birth_id`.
   - D3: `_checked_pid_target(os.getpid(), f"{boot_uuid}:{ticks}", held=False)` is `None` for the old form built from this process's real boot id and ticks, and is not `None` for `process_birth_identity(os.getpid())`.
   - `ps` is never run on Linux: patch `subprocess.run` to fail the test and call `_process_snapshot()` and `process_birth_identity(os.getpid())`.
