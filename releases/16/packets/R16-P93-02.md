## What to do

This packet defines the contract Plans 93, 94, 56 and 90 build on. Plan 94 adds the `computes` rung and Plans 56/90 the `workflow_ready` rung through the helpers below, so keep the names exact.

1. In `preflight.py`, add a section "Readiness ladder" with a docstring that states the contract in this packet (rungs, states, `through`, one next action, no timestamps, no ladder means unchanged) and the pinned-test note in step 7. Add:
   - `LADDER_RUNGS = ("installed", "reachable", "identified", "compatible", "computes", "workflow_ready", "delivered")`; `LADDER_OWNERS = {installed|reachable|identified|compatible: "existing-install", computes: "environment", workflow_ready: "workflow", delivered: "delivery"}`; `LADDER_THROUGH = LADDER_RUNGS[:6]`; `LADDER_ISSUE_CODES = {installed: "target_not_installed", reachable: "target_unreachable", identified: "target_not_identified", compatible: "target_incompatible", computes: "target_not_computing", workflow_ready: "workflow_not_ready"}`; an `unchecked` rung always uses code `rung_unchecked`.
   - `new_ladder(through)`: a dict `{"through": ..., "rungs": [7 rung dicts], "stopped_at": None}`; each rung dict is `{"rung", "owner", "state": "unchecked", "observation": None, "reason": None, "message": None}`. `through` must be in `LADDER_THROUGH` (`ValueError` otherwise).
   - `with_rung(ladder, rung, state, *, observation=None, reason=None, message=None)`: returns a deep copy with that one rung set. `observed` needs `observation` to be a dict (it may be empty); `failed` needs a non-empty `reason` string; `unchecked` may carry a `reason`. Anything else is a `ValueError`.
   - `ladder_stop(ladder)`: the first rung dict, in order and only up to and including `through`, whose state is not `observed`, else `None`.
   - `make_next_action(who, step, *, argv=None, then_argv=None, alternative=None, choices=None)`: `who` is `"person"` or `"agent"`; a person action has `step` and optionally `then_argv` (the Astrid command the agent runs after the person has acted); an agent action has `argv`. Returns `{"who", "step", "argv", "then_argv", "alternative", "choices"}` (absent ones `None`). Exactly one of the two shapes; `ValueError` otherwise.
2. Extend `readiness_envelope(*, entry=None, target=None, issues=(), fixes=(), attempt_count=None, ladder=None, next_action=None)`.
   - `ladder is None`: output identical to today's; `next_action` without a ladder is a `ValueError`.
   - With a ladder: validate it (seven rungs in order, valid states and `through`); set `stopped_at` from `ladder_stop`; put deep copies of `ladder` and `next_action` (or `None`) in the envelope under those two keys.
   - If there is a stop: add exactly one error issue `{"code": <LADDER_ISSUE_CODES[rung], or rung_unchecked for an unchecked rung>, "severity": "error", "message": <the rung's message, else "<rung> was not observed">, "details": {"rung": ..., "reason": <the rung's reason>, "field": "target"}}`, unless an issue with that code and rung already exists (the call must be idempotent). The status is then `blocked`. `next_action` is required when stopped; if the caller gave none, build a default: a person step "Check the <rung> step (<reason or not checked>), then ask me to check again." with `then_argv = ["astrid", "generate", "targets", "--placement", <target endpoint or "auto">]`.
   - `fixes` for a ladder envelope is `[]` or exactly `[mirror(next_action)]` (a `ValueError` for anything else). The mirror of a person action is `{"scope": "attached_target", "details": {"guidance": step, "who": "person", "then_argv": ...}}` with no `argv` key; the mirror of an agent action is `{"argv": [...], "scope": "read_only", "details": {"guidance": step, "who": "agent"}}`. Never put top-level `id`, `who`, `instruction` or `placeholders` on a fix: that opts the envelope into the strict setup contract in `setup_contract.py`.
   - No stop: the status comes from the issues as today (`ready` only with no issues). A `next_action` may still be given (a later packet uses it to offer attaching); its mirror goes in `fixes`.
   - Invariant to test: `status == "ready"` implies `stopped_at is None` and every rung up to `through` observed. `delivered` is never part of `through`; it stays `unchecked` here (the result path owns it).
3. In `GenerationReadinessError.__init__`, pass `ladder` and `next_action` through to `readiness_envelope` like the other keys, so `to_envelope()` keeps them. A round trip through `GenerationReadinessError(envelope).to_envelope()` must not duplicate the stop issue or the mirror fix.
4. In `interfaces.py` add `TypedDict`s for a rung, the ladder and the next action, and optional `ladder` / `next_action` keys on `ReadinessEnvelope` (`NotRequired`).
5. Write `tests/core/generation/test_readiness_ladder.py` with stdlib and pytest only. Cover:
   - with no ladder, `ready`, `ready_with_warnings` and `blocked` envelopes equal literal expected dicts (the old behaviour);
   - `new_ladder` order, owners and validation; `with_rung` validation and that it does not mutate its input;
   - all rungs up to `compatible` observed with `through="compatible"`: `ready`, no issues, `fixes == []`, `next_action is None`, and `delivered` still `unchecked` without blocking;
   - an `unchecked` rung under `through` with `issues=[]`: `blocked`, one issue `rung_unchecked` (no false ready on empty issues);
   - a `failed` rung keeps its `reason` and `message` in the issue, with the right code per rung, and its `next_action` appears once as the only fix;
   - rungs after `through` never stop the answer; with `through="workflow_ready"` an `unchecked` `computes` stops at `computes`;
   - the person-mirror has no `argv`, and `uses_setup_contract(envelope)` (from `setup_contract.py`) is false for every ladder envelope;
   - the `GenerationReadinessError` round trip (`to_envelope()` adds `task_id`; compare the rest), idempotence, and two identical calls are equal. `json.loads(json.dumps(envelope)) == envelope` (lists only, no tuples), since existing tests compare a CLI's JSON with the facade's dict.
6. Keep every existing function signature working (callers pass keywords only).
7. In the section docstring, record: "Pinned tests owed to later packets: `tests/packs/test_vibecomfy_local.py::test_scan_reports_pinokio_when_no_script_is_running` and `::test_scan_continues_when_pinokio_is_absent` compare the whole scan response and gain `\"installations\": []` (R16-P93-06). No other pinned test changes: envelopes without a ladder are unchanged, and the tests that call `generate targets` (`test_workflow_input_a01.py`, `test_settings_set_placement.py`, `test_generation_readiness_fields.py`) assert only `target` and `placement`."

## Done when

- A ladder envelope reads `ready` only with every rung up to `through` observed, and never from an empty issue list alone.
- A stopped ladder has one error issue, one `next_action`, and one mirrored fix, and survives `GenerationReadinessError` round trips.
- Envelopes without a ladder are byte-for-byte what they were.
- No ladder envelope opts into the strict setup contract.
