## What to do

1. Create `tests/test_user_state_restore.py` with a `service` helper that does `RealmStore.initialize(root).close()` then `RuntimeService(root)` (as `tests/test_app_state.py` does) and a helper `snapshot(service)` that returns one dict with: for actors `alice` and `bob` and keys `agent.choices`, `agent.compute-profiles`, `state-imports`, `ext.demo`, `generation`, `get_app_state(...)` (content, version, created_at, updated_at); `current_project('alice')` for scopes set with `select_project('alice', project_id, scope='user')` and `select_project('alice', project_id, scope='workspace')`; `get_document` for the project documents named below; `list_grants(identity=alice)`.
2. Test 1, `test_backup_and_restore_keep_user_state`: build a realm with a project (`create_project({'slug': 'demo', 'name': 'Demo'})`), Alice's five app-state documents (two writes to `agent.choices` so its version is 2), one document for Bob, a user-scope and a workspace-scope selection, three project documents (`create_document(project_id, {'document_id': 'hidden-shots', 'kind': 'ui.hidden-shots', 'content': {...}}, idempotency_key=...)`, plus kinds `ui.inpaint-strokes` and `ui.join-clips`; these stand for the App's project work that Plan 35 moves later), one approved and one revoked grant. Take `snapshot`, call `service.backup(tmp/'backup')`, `service.restore(tmp/'backup', tmp/'restored')`, close the original, open `RuntimeService(tmp/'restored')` and assert the snapshots are equal, including versions and timestamps.
3. Test 2, `test_restored_runtime_replays_old_writes_and_refuses_stale_writers`: after the restore, repeating Alice's first `update_app_state` call with the same idempotency key, content and version returns the same result with no version change; a write that expects an older version raises `ConflictError`; Bob's documents are untouched by Alice's writes.
4. Test 3, `test_restore_from_before_a_revocation_is_corrected_by_the_export`: realm A approves a grant, takes a backup, then revokes it and calls `export_revocations`. Restore the backup into a new realm: the grant reads `approved` (this is the hole being shown). `apply_revocations(export)` makes it `revoked`. `approve_grant` is refused and `reapprove_grant` gives generation 2 approved; applying the old export again changes nothing (`ignored_newer == 1`). A backup taken AFTER the revocation restores as revoked without any export.
5. Test 4, `test_user_state_documents_are_in_the_sqlite_backup_not_the_json_export`: assert that `service.export_structured()` has no key for app-state or selections today (it lists `projects`, `documents`, ... only) while the restored database has them. The assertion documents a known gap that the plan tracks in `tasks.md` (Later); keep it as a plain assertion on the key set, with a comment saying a future export change should update it. Do not change `structured_export`.
6. If any assertion fails because the product loses state, do not change product code: post BLOCKED with the failing assertion.
