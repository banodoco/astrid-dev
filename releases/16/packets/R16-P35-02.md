## What to do

1. Create `astrid/core/user_state_import.py` (standard library plus `astrid.core.user_state`). Constants: `RECEIPT_KEY = "state-imports"`, `MAX_RECEIPTS = 64` (the receipts document stays far below the 16 KiB Runtime limit; the key is valid under the Runtime key rule).
2. `@dataclass(frozen=True) class ImportSpec`: `import_id: str` (stable, for example `"skills-disabled-defaults"`), `target_key: str`, `source_label: str` (a human label of the old location, never a secret), `read_source: Callable[[], Any | None]` (returns the old value as JSON data, or `None` when the old location is absent or holds nothing worth importing), `to_document: Callable[[Any], dict]` (maps that value to the target document content).
3. `@dataclass(frozen=True) class ImportResult`: `status`, `target_version: int`, `source_digest: str | None`, `note: str`. Statuses: `imported`, `already_imported`, `nothing_to_import`, `target_kept`, `source_changed`, `unavailable`.
4. `run_import(spec, *, store=None) -> ImportResult`. (a) No store: return `unavailable`, write nothing. (b) Read the receipts document (`user_state.read(RECEIPT_KEY)`). If it holds a receipt for `spec.import_id`: read the source again; if its `content_digest` differs from the receipt's `source_digest`, return `source_changed` (the note names both digests and says the old copy was edited after the import, for example by an older Astrid); otherwise return `already_imported`. Never write the target in either case. (c) No receipt: call `read_source()`; `None` returns `nothing_to_import` and writes NO receipt (so an old copy that appears later can still be imported). (d) Build `desired = spec.to_document(value)`, then read the target document. If the target already has content: when it equals `desired` (an earlier run wrote the target but not the receipt) record the receipt as `imported`; otherwise keep the Runtime value, record the receipt with outcome `kept`, and return `target_kept` (the Runtime value always wins over an old copy, including a deliberately emptied value). (e) Target absent: write it with `expected_version=0` and `user_state.idempotency_key_for(...)`, then record the receipt and return `imported`.
5. Receipt entry for each import id: `{"source": source_label, "source_digest": ..., "target_key": ..., "outcome": "imported" | "kept", "target_version": n, "at": <UTC ISO-8601 from an injectable clock argument `now=` defaulting to `datetime.now(timezone.utc)`>}`. Write receipts with `user_state.update(RECEIPT_KEY, change)`; if the document already holds `MAX_RECEIPTS` entries and the id is new, raise `user_state.UserStateError("too_large")`.
6. The helper never opens, rewrites, renames or deletes the old location (it only calls `spec.read_source`). This is the rollback rule: an older Astrid that still reads the old copy keeps working, and `source_changed` is how a newer Astrid notices that the older one wrote there.
7. Write `tests/test_user_state_import.py` with `InMemoryAppState` and a real file under `tmp_path` as the old location. Cases: first run imports and writes one receipt and one target at version 1; second run is `already_imported` with no new writes (`store.writes` unchanged); the old file is byte-identical and its mtime unchanged afterwards; editing the old file after the import gives `source_changed` and still no write; absent or empty old copy gives `nothing_to_import` and no receipt, then the file appears and a later run imports it; target already present with different content gives `target_kept` and the target is unchanged, receipt outcome `kept`; interrupted copy: `store.fail_writes = {2}` (the receipt write) raises `unavailable`, then a second run with a healthy store ends `imported` with exactly one target version bump; interrupted before the target write (`fail_writes = {1}`), then a healthy run imports; two different import ids do not disturb each other's receipts; a receipts document at `MAX_RECEIPTS` refuses a new id; `unavailable` store writes nothing.

## Done when

- First, repeated, interrupted, changed-source and target-already-there cases behave as listed.
- The old location is never modified (bytes and mtime compared in a test).
- A receipt is written only after the target holds the imported value.
- The Proof passes, including the Proof of the previous packet's tests.
