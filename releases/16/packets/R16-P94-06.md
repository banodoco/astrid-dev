## What to do

1. Route decision to bake in (ER-0, D3): the install is official ComfyUI Portable, not Astrid's Windows recipe. Reason: finishing the recipe needs a Windows runner adapter (`engine_runner.py:336` and `:1103` refuse `windows-` platforms), Windows custody and install locking (`engine_custody.py`, `engine_platforms.py` are Linux file-descriptor code), a Windows-capable endpoint root (`engine_local_endpoint.py:_valid_root` is POSIX-only), and checked-out sources plus a hash-locked pip sync from the network; none of it can be proved on a CPU Linux chat. Portable is one verified archive, an unpack and a rename. Do not use `gpu_environment.environment_plan` or `provision_environment`.
2. Create `astrid/packs/vibecomfy/portable.pin.json` with exactly: `{"schema": "astrid.comfy-portable-pin.v1", "platform": "win32", "supported_gpu_patterns": ["RTX (20|30|40|50)\\d\\d"], "release": null, "note": "No release is pinned until its URL, size and SHA-256 are taken from the official release page (plan 94, ER-L0). Until then the install refuses."}`. A pinned release is an object with `tag`, `url` (https), `archive_name`, `archive_format` (`7z` or `zip`), `archive_bytes`, `archive_sha256` (64 hex), `extracted_bytes`, `estimated_minutes`, `inner_directory`, `required_files` (relative posix paths, at least `python_embeded/python.exe` and `ComfyUI/main.py`), `start_script`, `launch_args` (list). Never invent values for a real pin.
3. In `astrid/core/generation/comfy_portable.py` define `class PortableError(RuntimeError)` with a `code` attribute; `load_pin(path=PIN_PATH)` (validates the schema and every field above, raising `PortableError` code `pin_invalid`; returns the dict); `peak_bytes(release)` = `max(2 * archive_bytes, archive_bytes + extracted_bytes) + MARGIN_BYTES` with `MARGIN_BYTES = 1 << 30` (the archive download peaks at the partial plus the staging copy, the unpack at archive plus unpacked tree); `default_destination(environ, platform)` = `<LOCALAPPDATA or ~/AppData/Local>/Astrid/ComfyUI`; `destination_state(destination)` returning `absent`, `empty`, `ours` (the file `.astrid-install/journal.json` exists and parses as JSON with schema `astrid.comfy-install-journal.v1`) or `foreign` (anything else non-empty, or a file).
4. Add `build_offer(destination, *, pin=None, platform=None, gpu=None, disk_usage=shutil.disk_usage, environ=None)`. `pin` defaults to `load_pin()`, `platform` to `sys.platform`, `gpu` to `gpu_environment.detect_nvidia()`. It never writes or creates anything. It returns `{schema: "astrid.comfy-install-offer.v1", status: "offered" | "refused", refusal: None | {code, message, works}, destination, release (tag or None), download_bytes, installed_bytes, peak_bytes, free_bytes, minutes, cost_usd: 0, state, offer_sha256}`. `offer_sha256` is the SHA-256 of canonical JSON (sorted keys, compact) of `{destination, release tag and archive_sha256, platform, peak_bytes, gpu_devices}`, so it does not change with free space or progress. Check in this order and stop at the first refusal: `unsupported_platform` (not `win32`: for `linux` the `works` text names `astrid engines install comfyui --platform linux-x86_64-cu130`; for `darwin` it says to use your own running ComfyUI), `no_gpu` (no NVIDIA GPU is usable: say what works, a computer with an RTX 20, 30, 40 or 50 series card, or your own ComfyUI), `unsupported_gpu` (any device name not matching `supported_gpu_patterns` via `re.search`: name the card and the supported series), `no_verified_release` (pin `release` is null), `destination_invalid` (not absolute, or the path exists and is a file), `destination_occupied` (state `foreign`: say that a different folder is already there and nothing was touched), `insufficient_space` (free bytes on the nearest existing ancestor of the destination, from `disk_usage`, are below `peak_bytes`; the message gives both numbers). A refusal still reports the numbers it knows.
5. Add `render_offer(offer)`: for `offered`, exactly this shape in one paragraph: `No working ComfyUI here. I can install one in <destination>: about <download GB> to download, <peak GB> of free disk needed at the peak, about <minutes> minutes, nothing else on your computer touched, no cost. It becomes the ComfyUI Astrid uses, and your current choice is kept so you can switch back. Go ahead?` (decimal GB with one decimal), followed on a new line by `To confirm: astrid generate install-comfyui --destination <destination> --apply <offer_sha256>`. For `refused`: the refusal message, then `What works: <works>`, then `Nothing was written.`
6. Write `tests/core/generation/test_comfy_portable_offer.py` with an in-test fixture pin (a dict, not the shipped file) and the fixtures from `environment_states.py`: the shipped pin loads and its release is null; `load_pin` rejects a missing field, a non-https url and a bad hash; an offered case for each of `rtx5070ti`, `rtx4090` with the exact sentence; every refusal code above (low disk with `fake_disk_usage`, unsupported GPU `gtx1060`, no GPU, Linux, macOS, foreign destination from `foreign_destination`, relative destination, unpinned release); `offer_sha256` is stable across different free space and changes when the destination, release or GPU changes; `snapshot` of the machine is identical before and after every call (nothing written, no folder created); a declined offer is simply not applying it, so the test only checks that building an offer twice leaves the destination absent.
