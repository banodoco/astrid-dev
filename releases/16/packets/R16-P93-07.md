## What to do

**The ladder contract** (written by R16-P93-02 in `astrid/core/generation/preflight.py`, section "Readiness ladder"; do not change it): seven ordered rungs `installed, reachable, identified, compatible, computes, workflow_ready, delivered`; a ladder has a `through` rung (the last rung this answer owns; never `delivered`); each rung is `{rung, owner, state, observation, reason, message}` with `state` one of `observed | failed | unchecked`; `readiness_envelope(..., ladder=, next_action=)` reads `ready` only when every rung up to `through` is `observed`, otherwise it is `blocked` with one error issue and exactly one `next_action`; no timestamps or durations anywhere; an envelope built without a `ladder` is exactly what it was before.

An **installation observation** is `{"layout": "desktop", "state": <state>, "version": str|None, "endpoint": "http://127.0.0.1:<port>" (where it answers when running, else where it is expected), "recorded": {"executable": str|None, "data_dir": str|None}, "files": {"executable": bool, "data_dir": bool}, "responder": {"kind": "comfyui"|"other"|"denied"|"none", "port": int|None, "base_dir": str|None, "matches_install": bool|None}}`, and `<state>` is one of `running | closed | stale | wrong_responder | denied | ambiguous`.

1. Give `observe_target_rungs(record, *, get_json=None, installation=None)` the new `installation` argument (a dict produced by `desktop_install.classify`). When it is `None`, behave exactly as R16-P93-03 built it. When given, trust it for the first three rungs instead of probing them, and probe only `/object_info` (through `get_json`) when the state is `running`. Mapping, using `installation["endpoint"]` as the URL:
   - `running`: `installed` observed `{"layout": "desktop", "files": {...}}`; `reachable` observed `{"endpoint": url}`; `identified` observed `{"tied_to_install": True, "by": "data_dir"}`; `compatible` as in R16-P93-03.
   - `closed`: `installed` observed; `reachable` failed, reason `closed`.
   - `stale`: `installed` failed, reason `stale_registration`.
   - `wrong_responder`: `installed` and `reachable` observed; `identified` failed, reason `not_this_install`.
   - `denied`: `installed` observed; `reachable` failed, reason `access_denied`.
   - `ambiguous`: `installed` and `reachable` observed; `identified` failed, reason `cannot_tell_which_install`.
   - Every rung after a failed one is `unchecked` with reason `not_reached`. Observations carry no paths from the machine beyond what is already in the installation's `recorded` block, and nothing time-based.
2. Add to `LADDER_REASONS` (reason to rung): `stale_registration: installed`, `closed: reachable`, `not_this_install: identified`, `cannot_tell_which_install: identified`, `several_installs: identified` (used by R16-P93-08). Add their `LADDER_TEXT` entries. Provisional wording (R16-P93-10 finalises it):
   - `closed` (person): message "Found your ComfyUI Desktop. It is closed."; step "Open ComfyUI Desktop and I will carry on."
   - `stale_registration` (person): message "Your ComfyUI Desktop install points at files that no longer exist."; step "Reinstall ComfyUI Desktop."
   - `not_this_install` (person): message "Something else is answering where ComfyUI Desktop should be."; step "Close that program, or tell me the address of the ComfyUI you want."
   - `cannot_tell_which_install` (person): message "I cannot tell whether what answers is your ComfyUI Desktop."; step "Tell me which ComfyUI to use."
   - `several_installs` (person): message "More than one ComfyUI is running."; step "Tell me which one to use."
3. Add `ladder_summary(ladder, *, url=None, installation=None) -> str`, the one sentence the person reads: for a ladder with no stop, `LADDER_TEXT["running_desktop"]["message"]` when `installation` is a running Desktop (add that entry, provisional wording "Using your ComfyUI Desktop."), else "Using the ComfyUI at {url}."; for a stopped ladder, the stopping reason's `LADDER_TEXT` message with `{url}` filled in. Then `ladder_next_action(ladder, *, url=None, installation=None)`: for `closed` the person action's `then_argv` is the targets command for `installation["endpoint"]` (the re-probe after the person opens Desktop); for `stale_registration` the person action carries `alternative = {"kind": "separate_copy", "owner": "plan-94", "available": False, "step": "Set up a separate copy of ComfyUI, with your consent."}` (Plan 94's ER-2 flips `available` and supplies the offer; Plan 93 never installs anything) and its `then_argv` is `["astrid", "generate", "targets", "--placement", "auto"]`; for `access_denied` the action stays the agent retry; for `several_installs` the action may carry `choices` (list of `{"label", "endpoint"}`; the packet that raises it passes them). Never an action that launches, restarts, patches or deletes anything of Desktop's.
4. Write `tests/core/generation/test_desktop_rungs.py`. Build each installation with `desktop_install.classify(registration, files=..., responders=...)` from the fixtures (use `tests.fixtures.comfyui_desktop.load`, `get_json_for`, `desktop_install.probe_ports`), so the contract between R16-P93-05 and this packet is tested. Cover every state's rungs, reason and exactly one next action, and `ladder_summary` for running Desktop, other ready, and each stopped reason; `denied` built with `get_json_for(fixture, denied_ports=(8000,))`; `ambiguous` built by making `/internal/folder_paths` fail; the stale registration leaves `reachable`..`compatible` `unchecked` `not_reached` and `get_json` is never called; wrapping each ladder in `readiness_envelope(ladder=..., next_action=...)` gives `blocked` with one error issue and one fix for every state except `running`, which is `ready`; the closed action's `then_argv` re-probes the endpoint; the stale action has the `alternative` with `available` false and no action contains `argv` that starts or deletes anything; with `installation=None` the results equal R16-P93-03's.
