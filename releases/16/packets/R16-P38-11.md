## What to do

1. `engine_custody._vibe_birth(pid)`: VibeComfy's session registry stores only the start ticks. Return `str(process_binding.birth_ticks(identity["birth_id"]))` where `identity = platform.process_identity(pid)`; if the identity is `None` raise `ProcessLookupError(pid)`; if `birth_ticks` is `None` raise `OSError("process start ticks are unavailable")`. Remove the `/proc/<pid>/stat` read.
2. `target_launch.ProcLaunchObserver`: change `_birth(self, folder)` to `_birth(self, pid)` returning `None` for a missing or exited process (`platform.process_identity` returns `None`) and otherwise `identity["birth_id"]`; update both callers in `process()` (they bracket the cmdline/cwd/exe reads) and remove the `boot_id` read. The `/proc/<pid>/cmdline`, `cwd`, `exe` reads stay (they are not identity).
3. `host_bootstrap._host_pid_alive`: `platform.process_identity(value)` already returns `None` for a Linux zombie, so delete the `/proc/<pid>/stat` zombie probe; keep the Darwin native branch and the `ps` fallback for other systems.

A legacy `<boot-uuid>:<ticks>` retained value stays unmatched unless the strings are equal.
