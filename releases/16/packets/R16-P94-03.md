## What to do

1. Finding to bake in: VibeComfy's `fetch.download` streams into its own temporary file next to the destination while `_ResumingClient` (in `asset_alignment.py`) replays the resume part into it and keeps appending to the part, so for the file in flight the part and the temporary file coexist. A file of `b` bytes with `p` bytes already in its part needs `2*b - p` extra bytes at its peak (`fetch.py:635-641`, `asset_alignment.py:191-200`). Today `plan_attached_model_download` checks `free >= sum(bytes) + DOWNLOAD_MARGIN_BYTES` (`asset_gaps.py:~452`) and calls `_hard_links_supported` (which creates probe files in each target folder) before that check.
2. Add `download_peak_bytes(files, partial_bytes=None)`: `files` is a list of dicts with `file`, `folder`, `bytes`, in download order; `partial_bytes` maps `(folder, file)` to the size of an existing `.<file>.astrid-resume` part (default empty, each value capped at the file's `bytes`). The peak is `max over k of (sum of bytes of files before k + 2*bytes_k - partial_k)`; an empty list is 0. This is pure: no filesystem access.
3. In `plan_attached_model_download`, read each existing part's size with `Path.stat` only (a missing part is 0, a symlink or non-regular part counts 0 and is left to the apply step's existing `unsafe_partial` refusal), compute the per-device groups as today, and set `enough` per group to `free >= download_peak_bytes(group files, partials) + DOWNLOAD_MARGIN_BYTES`. Add the plan keys `peak_bytes` (sum of the group peaks) and `partial_bytes` (list of `{file, bytes}` for non-zero parts). Do not change the plan digest body (`wanted`, `manual`, `entry`, `mode`, `target`): `peak_bytes`, `partial_bytes` and `space_ok` stay out of it.
4. Remove the `_hard_links_supported` calls and the `f['hard_links']` assignment from the plan. In `apply_attached_model_download`, after the digest check and the `space_ok` re-check (recomputed with the same function, so a changed disk is caught) and after the existing `file_exists` check, probe each distinct folder once with `_hard_links_supported` and set `f['hard_links']` on the plan's file items, then fetch. The plan must write nothing at all; an apply that refuses for space must create no file and no probe.
5. Update `render_attached_download_plan`: keep the `Total:` line, and add one line stating the peak: `At its peak the download needs <size> because a file being rebuilt sits beside its partial copy.` (use `_size`), and when `space_ok` is false the existing `Not enough free space` line stays. The `insufficient_space` refusal text in apply names the peak and the free space and still ends `Nothing was written.`
6. By reading, update these pinned tests in `test_attached_model_download.py` so they still hold: `test_the_plan_records_whether_each_folder_takes_hard_links` (the plan no longer records it; assert the plan writes nothing and that apply sets it), `test_refuses_when_free_space_is_below_the_total` and `test_free_space_margin_is_part_of_the_check_and_is_stated` (the numbers now use the peak). List each edit in the PR body, because this file cannot be run in the chat.
7. Write `tests/core/generation/test_download_space_budget.py` using only `asset_gaps`, `engine_contracts.ModelSpec`, `types.SimpleNamespace` and `tmp_path`. Pure cases for `download_peak_bytes`: one file, two files, a partial that is 0, half and the whole file, an empty list. Plan cases: monkeypatch `asset_gaps._download_gaps` to return `(gaps, present, spec, info)` for two roles in two real tmp folders (gap dicts have `role`, `key`, `names`, `folder`, `served`, `local`; the folders' `served` and `local` sets are equal so nothing goes to `manual`), pass `sources={"<key>/<name>": ModelSpec(...)}` with `url="https://huggingface.co/x/resolve/main/<name>"`, a `client=SimpleNamespace(target=SimpleNamespace(url="http://127.0.0.1:8188"))`, and monkeypatch `asset_gaps.shutil.disk_usage` to a fake. Assert: `snapshot` of the folders (from `tests/core/generation/environment_states.py`, written by R16-P94-01) is unchanged after the plan; `_hard_links_supported` monkeypatched to fail the test is never called by the plan; with free space just below the peak plus margin `space_ok` is false, and just at it, true; a partial raises `partial_bytes` and lowers the peak. Apply cases: monkeypatch `asset_gaps._fetch_into_folder` to record calls; with too little space apply raises `AttachedDownloadRefused` code `insufficient_space`, makes no `_fetch_into_folder` call, calls no probe, and leaves the folders' snapshot unchanged; with enough space the probe is called once per folder before the first fetch.
