## 2. Independent problem inventory (prior to task mapping)

- A successful install/doctor is not evidence of an editor connected to a usable capability. Historical Windows reports show real generation only after fixes, model acquisition failures, save failures and conflicting build instructions. #1848 is a strong newer negative: portable workaround and actual local GPU output, but no end-to-end editor or Desktop proof.
- Wrong recovery advice is not cosmetic when it directs reinstall of a healthy busy runtime, hides a disk shortage or sends a newer installation to an older public updater. Same cross-layer loss of typed cause appears in installer, browser renderer, realm attach, CLI and remote claims.
- First-use assumes a project, correct target, matching editor, agent credentials and service ownership. Ordinary users and weaker agents cannot be expected to inspect private files or logs to make these choices.
- Scope of a supported local system is broader than one Windows GPU. Native OS process/network enforcement, long paths, previous-release upgrade and actual ComfyUI compute are not established by Linux mocks.
- Failed paid tasks may retain slots or block release; the safety contract matters even if RunPod is experimental.
- A rendered asset or saved clip is not equivalent to a successful complete journey; media dropped then lost after reload and incorrect Saved are harm, not feature polish.
- Release identity has three distinct surfaces: strategy grouping, public version/manifest, and actual installed identity. Mixed versions occur normally when the App is hosted, and proof at a previous tuple cannot be copied indiscriminately.
- Baseline red CI is not necessarily product harm, but a job that never executes a required safety test is no evidence. Need narrow executable gates instead of pulling the entire future green programme forward.
