# Release 14 — Local speed

**Release:** 14
**State:** Draft

## Highlight

On your own computer with the model already loaded, a generation comes back in about the time the model takes.

## Intent

Release 13 made generation work through one path; on a person's own ComfyUI it adds about 30 seconds to every job. This release removes that. A good outcome: under 2 seconds of Astrid's own time for every caller, and under a tenth of a second for a caller that is already connected, measured by a standing test on every build.

Proposed by the advisor and agreed by Hannah on 15 November 2026 ("those releases make sense"), with fixes and plans added on the fly from actual usage and user reports. See [Strategy](../strategy.md#decisions).

## Approach

Designed from the work a warm local job fundamentally needs, not by trimming today's path: a resident session, a workflow prepared once, completion by push, checks only when the installation changes, and a default-delete list of everything else ([Plan 55](../plans/55-local-speed/plan.md)). Rented-machine speed is out of scope. Riding along because they are small and users hit them: a stored record of test results per commit, so new failures are told from old ones without re-running; the last tasks of issue intake, which is the route for user reports; frames at positions on the default video workflow (first frame, last frame or any position, one feature); the seed in every receipt; and whatever the Windows testers report. The first fix after Release 13, looking up a model's fingerprint and size from Hugging Face instead of refusing, ships before this release as an update.

Each release has one theme, plus a standing lane for fixes and small plans that come from actual usage and user reports.
