**State:** Draft

The plan it rests on, [Plan 55](https://github.com/banodoco/astrid-dev/pull/662), is not merged and has seven owner decisions open, so nothing here authorizes work yet. ## Highlight

On a creator's own computer with the model already loaded, a generation comes back in about the time the model takes.

## Intent

**Release 14 is a local-first speed release.** Hannah, Sun 15 Nov 10:45 UTC: "we need the next release to get it very fast, runpod is unimportant. Let's do a proper speed release after this one, focused on getting this as fast as possible. think through it from first principles."

Today a warm job on a person's own ComfyUI spends about 30 seconds in Astrid around a few seconds of the model's own time. Nothing in that path is slow because the work is hard: every job repeats work whose answer has not changed (workflow emission, registry and pack scans, source identity, the entry lookup), in new processes, with polling between them. This release removes that repeated work from the warm local path, designed from what a warm job fundamentally needs rather than by trimming today's path.

**RunPod speed is out of scope.** Rented machines stay in [Plan 54](../plans/54-warm-latency/plan.md), which is proposed (D7) to become the rented-machine plan and queue behind this release.

**Done:** the targets Hannah sets in D1 are met live on a GPU machine where Astrid and ComfyUI run together, for the default image workflow and reported for the default video workflow, on Linux and Windows; a standing budget test fails any pull request that adds a process start, a wait or a forced disk write to the warm local path; and every way of leaving the fast lane (ComfyUI restarted, a model or node pack removed, the workflow edited, Astrid updated, the worker killed, two callers, a cancel) ends in the same typed result as today.

## Approach

### The plan

The plan is [Plan 55, Local speed](https://github.com/banodoco/astrid-dev/pull/662) (`plans/55-local-speed`, astrid-dev PR #662, head `79c228a1` at the time of writing). It is **not merged**: seven owner decisions, D1 to D7, are open, and the PR is not set to merge automatically. It was written by the advisor from first principles with an independent review of the starting hypothesis.

In short: a fast lane entered by a key (workflow identity, input shape, target ComfyUI, Astrid installation); a workflow compiled once by VibeComfy into a template and filled per job, with ComfyUI as the authority on what a node accepts; one held connection to ComfyUI, woken at completion instead of polling; the output read and hashed once; resident pack sessions as a core capability, used first by the VibeComfy pack; every caller still through the Runtime, with its three once-a-second polls removed; a thin command line and an in-process agent tool server; cancel only what is ours. Critical path: LS-1 → LS-3 → RS1 → LS-8 → LS-15 → LS-9 → LS-14 → R. LS-1 measures the floor before anything is built.

[Plan 54](../plans/54-warm-latency/plan.md) (`plans/54-warm-latency`) is proposed to become RunPod-only and queue behind Plan 55 (D7). Its local tasks move into Plan 55; any rented-machine speed work between Release 13 and this release is dropped unless it is also a donor here.

### Targets (pending D1)

The staged targets from #662: median Astrid overhead for a one-megapixel image on an idle queue, measured as caller wall time minus ComfyUI's own start-to-success span. Queue wait is reported separately and never subtracted silently.

| Stage | Target |
|---|---|
| **First stage** | under **2 s** for every caller on every system |
| **Second stage** | under **0.5 s** |
| **Stretch, measured** | under **0.1 s** for an already-connected caller (SDK, App, agent tool server); under 0.25 s from the command line on Linux and macOS, Windows' set after LS-1 |
| Throughout | under 3 s (5 s on Windows) for the first job after a start, update or change |

All of these wait on Hannah's D1. The 0.1 s stage is a measured stretch: two independent estimates put an already-connected caller at 15–70 ms on Linux and 25–120 ms on Windows, but nothing is promised until LS-1 measures it. #662's own text runs from under 2 s straight to under 0.1 s; D1 also settles whether the 0.5 s stage is a separate commitment.

### Scope
