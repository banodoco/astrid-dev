# Release 14 — Local speed

**Release:** 14
**State:** Draft

## Highlight

On your own computer with the model already loaded, a generation comes back in about the time the model takes.

## Intent

Release 13 made generation work through one path; on a person's own ComfyUI it adds about 30 seconds to every job. This release removes that. A good outcome: under 2 seconds of Astrid's own time for every caller, and under a tenth of a second for a caller that is already connected, measured by a standing test on every build.

Proposed by the advisor and agreed by Hannah on 15 November 2026 (version 0.1 is "focused on hardening, updates, stability and speed"), with fixes and plans added on the fly from actual usage and user reports. See [Strategy](../strategy.md#decisions).

The slowness is the roughest edge Release 13 ships with, and it rewrites the path every job takes, so it comes before stabilising that path.

## Approach

Designed from the work a warm local job fundamentally needs, not by trimming today's path: a resident session, a workflow prepared once, completion by push, checks only when the installation changes, and a default-delete list of everything else ([Plan 55](../plans/55-local-speed/plan.md)). Rented-machine speed is out of scope. Riding along because they are small and users hit them: a stored record of test results per commit, so new failures are told from old ones without re-running; the last tasks of issue intake, which is the route for user reports; the seed in every receipt; and whatever the Windows testers report. The first fix after Release 13, looking up a model's fingerprint and size from Hugging Face instead of refusing, ships before this release as an update.

From the Windows tester run of 15 November 2026, where a tester got image, edit and music generating on Windows for the first time, the follow-ups in the standing lane are: a watchdog that writes thread stacks to the log when a task makes no progress ([#669](https://github.com/banodoco/astrid-dev/issues/669)); the short generation folder left behind for kept or crashed attempts ([#670](https://github.com/banodoco/astrid-dev/issues/670)); a result file path too long for user names over 36 characters ([#671](https://github.com/banodoco/astrid-dev/issues/671)); shorter install paths ([#672](https://github.com/banodoco/astrid-dev/issues/672)); a path-length test ([#673](https://github.com/banodoco/astrid-dev/issues/673)); the Runtime permission check that misfires on Windows ([#674](https://github.com/banodoco/astrid-dev/issues/674)); the folder-permission message during install ([#675](https://github.com/banodoco/astrid-dev/issues/675)); VibeComfy loading its node library and numpy to read one constant ([#676](https://github.com/banodoco/astrid-dev/issues/676)); and the unverified leads from the code hunt ([#677](https://github.com/banodoco/astrid-dev/issues/677)).

Each release has one theme and a [standing lane](../skills/astrid-dev-shared/glossary.md).
