# Release 14 — stability and reliable creative work (DRAFT)

**Status: NOT PUBLISHED.** This draft is conditional on the frozen tuple, Release 14 qualification and the owner's explicit publication approval. Do not present these as shipped features until the Lead has verified the exact resulting product commits. Release 14 is a **required update** under the [owner decision](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7065093369).

Release 14 focuses on making ordinary creative work dependable: installs and updates that preserve existing projects, edits that save or refuse clearly, and generation that retains usable evidence when something fails. The release also incorporates the approved Plans 59, 64 and 65 creative work **only to the extent it lands and passes the combined Release 14 gates**.

## Intended changes since Release 13

- **Windows paths and installation:** shorter result/manifest names and installation paths, tested path-length budgets, and the Windows Runtime permissions behavior ([#671](https://github.com/banodoco/astrid-dev/issues/671), [#672](https://github.com/banodoco/astrid-dev/issues/672), [#673](https://github.com/banodoco/astrid-dev/issues/673), [#674](https://github.com/banodoco/astrid-dev/issues/674)).
- **Startup and dependencies:** VibeComfy workflow/node-loading cleanup, verified certificate handling without disabling TLS, restartable model downloads and clearer installer browser control ([#676](https://github.com/banodoco/astrid-dev/issues/676), [#721](https://github.com/banodoco/astrid-dev/issues/721), [#722](https://github.com/banodoco/astrid-dev/issues/722), [#723](https://github.com/banodoco/astrid-dev/issues/723)). Do not describe the TLS change as accepting unverified certificates.
- **Editing and save behavior:** targeted repairs for long-lived timelines that previously refused simple edits or duplicated validation against untouched historical content ([#839](https://github.com/banodoco/astrid-dev/issues/839), [#842](https://github.com/banodoco/astrid-dev/issues/842)); FIX-16 makes saves stable snapshots, and a rejected save must stop and explain, offering **“Copy my change out”** or an explicit **“Discard and reload the saved version”** rather than silently overwriting work. The conflict **Keep** action and FIX-33's typed-rename fix make recovery clearer. These are shipped claims only after landing and passing the saved/reopened journeys.
- **Failure handling and recovery:** work on durable retry/failure evidence ([#926](https://github.com/banodoco/astrid-dev/issues/926)), the host activation/abort race tracked in [#905](https://github.com/banodoco/astrid-dev/issues/905), and the too-early “Saved” state tracked in [#966](https://github.com/banodoco/astrid-dev/issues/966). **#905 and #966 remain open at draft time**; do not call them fixed unless the Lead links a landed commit and passing reproducer.
- **Error envelope:** CLI and MCP errors include the literal JSON field `"code": null` where no code is available. Consumers must not treat absent `code` and an explicit null as the same wire representation.
- **Creative work:** Plan 59 adds still-image starts and continuation from a clip's last frames; Plan 64 adds speaker references to make a character say a new line in that voice; Plan 65 lets output size guide masks and composition. Whisper transcription removes its temporary recording after each run. R13 transitions remain supported, including crossfade, wipe, slide-push and zoom-through. These capabilities are included only to the extent their reviewed changes land and pass the combined Release 14 gates.

## Updating an existing installation

Release 14 is a **required update**. Update an existing installation with Astrid's native installer. Use Pinokio for a fresh install. An already-open tab may not learn about the update until it reloads; it then shows **“Editor updated · Reload”**. Reload into R14; if you had an unsaved edit, R14 offers **Restore**. Keep the existing project/realm and verify an edit survives save, reload and reopen.

The completed FIX-17 update matrix must test fresh installs on Windows, macOS and Linux, update-over-R13, a killed Windows update, the required-update prompt with draft preservation, and reopening R13-written realms with timelines, history and save queue. The owner personally runs the final Windows update on a real Release 13 installation, including one local generation, cancel and retry. There is no instruction here to delete user data, recreate a project, reset an installation, or take a test-only shortcut around a refused save.

## Known limitations and explicit non-claims

- The **known red tests remain visible**. The owner accepted the reviewed R14-known ledger and specified remaining publication blockers in the [override](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7076969522). A green summary total alone does not establish qualification.
- **Speed work moves to Release 15.** Release 14 makes no performance, warm-start or under-one-second claim ([decision](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7061778603)).
- **Scene-by-reference moves to Release 15**; Release 14's save-refusal card does not implement scene-by-reference ([decision](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7061951208)).
- The four Release 13→14 test differences (two Hyperframes public-service renders, a middle-shot duration check, and external process adoption) require FIX-18 causal disposition. No test is skipped, deleted, or relaxed simply to announce the release.
- A change to the Runtime timeline save contract is not automatically backward compatible. Mixed R13/R14 product versions are unsupported. FIX-17 must prove that the R13 App shows the required-update prompt without losing drafts and that an R14 install reopens R13-written realms with timelines, history and save queue.
- The final rented RunPod generation, teardown receipt and owner-run real Windows checks are pending in [the publication checklist](evidence/publication-checklist.md).
- **SDK compatibility:** authored extension fields on clips, tracks or config are refused, and exact rational FPS values are refused; existing R13 data with extension fields reopens and edits normally ([FIX-31, #510](https://github.com/banodoco/astrid-dev/issues/510)). These SDK cases are targeted for R15.
- **Save and reload:** a reload-after-save recovery race remains ([#1347](https://github.com/banodoco/astrid-dev/issues/1347)); very large timelines take longer to save, with large batches around 100 clips taking about a minute ([#1268](https://github.com/banodoco/astrid-dev/issues/1268)).
- **Publication and recovery wording:** the publication-only poll remains ([#1355](https://github.com/banodoco/astrid-dev/issues/1355)), as does the refused-undo dialog wording issue ([#1364](https://github.com/banodoco/astrid-dev/issues/1364)).
- **Test and legacy compatibility:** VibeComfy CI coverage is limited ([#1311](https://github.com/banodoco/astrid-dev/issues/1311)); raw SDK edits using legacy crossfade spellings inherit a timing limit ([#1312](https://github.com/banodoco/astrid-dev/issues/1312)).
- **Other existing limits:** disk-full interruption during save and seeding multiple realms have not been tested. The FFmpeg protocol whitelist currently covers `ffprobe` only ([#1247](https://github.com/banodoco/astrid-dev/issues/1247)). Windows has an intermittent Runtime discovery failure (WinError 32); its cause is unknown. The ledger also records unproven or test-only R15 fix-forward items, including incomplete legacy output settings, transcription inputs, H3 media/profile setup and graph expectations, generation target selection, dependency direction, track metadata, capture/filmstrip projections, dry-run recovery guidance, duplicate-operation test doubles, inventory/bootstrap witnesses, hosted-render/process-ownership evidence, and comparator parsing. The ledger distinguishes observed user impacts from unproven impacts and test-only findings.
- **Rollback:** fix-forward is the preferred response to a publication problem. Restoring the old R13 deployment is a last resort and can strand installations already updated to R14. The rollback reference is R13 App `de7dd1e6` and the served hashes recorded in [astrid-app#338, comment 7074514395](https://github.com/banodoco/astrid-app/issues/338#issuecomment-7074514395).
