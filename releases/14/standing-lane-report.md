# Release 14 standing-lane status

**Status date:** 16 November 2026

**Source:** Release 14 standing lane, sourced from the Windows tester follow-ups and issue decisions.

**Scope:** Issues #674, #721, #722, #670, #671, #672, #673, #669, #676, #736, and #723.

## Summary

Seven issues are complete within their assigned scope: #721, #722, #671, #672, #673, #669, and #723. Each has focused proof and an open, published Agent pull request. Three issues remain blocked: #674, #670, and #676. Issue #736 was already fixed on the App release branch and needs no new change.

“Complete” here means the scoped change was implemented, focused-tested, and published to an open pull request. It does not mean merged, released, or fully accepted on Windows. The publication audit on this date verified that all seven Agent PR heads and the #722 documentation PR are live, open, unmerged, and have the same tree hashes as their tested trees. The seven Agent PRs target [`release/14/main` at `ab95803`](https://github.com/banodoco/astrid-agent/commit/ab95803ce28fa51eec937b4074f5ec0f0439b98a); the documentation PR targets astrid-dev at [`f49111e`](https://github.com/banodoco/astrid-dev/commit/f49111e279742f23d99fe70ef40b6be46a3de9c6).

All completed Agent code is available on GitHub for review, with no unpublished product edits left in the corresponding local worktrees. The lane made no new Runtime, App, or VibeComfy changes and no dependency re-pins. Two earlier merged changes matter to the status: the Runtime DACL fix for #674 is already on the Runtime release branch, but Agent still pins the older Runtime; and #736’s App fix is already on the App release branch. No claim is made that every open PR’s full CI is green or that Release 14 has passed final Windows acceptance.

## Windows acceptance still needed

Focused tests and one bounded CI guard are useful evidence, but do not replace a real Windows pass for these platform-specific cases. After the open PRs are reviewed and integrated, acceptance should verify:

- [ ] **#674, after a separately authorized Runtime re-pin:** confirm a private Windows DACL permits safe timeline-memo reuse and a shared/unsafe store still requires full verification.
- [ ] **#721:** HTTPS through an inspection root trusted by Windows succeeds with certificate and hostname verification intact. An untrusted certificate produces the structured TLS explanation. Download progress and remaining counts stay truthful.
- [ ] **#722:** interrupt and rerun the same confirmed plan; valid completed files are verified and partial transfers resume where the server supports Range. A fully complete rerun reports “All requested model files are present and verified. Nothing needed downloading.” In disposable test files, check missing, unreadable, size-mismatched and same-size corrupted Comfy-listed files refuse before further writes or downloads; valid symlinks stay intact.
- [ ] **#670, after its lifecycle prerequisite:** eligible attempts and their helper-derived `vr` folders are deleted together; live, kept, caller-owned and pending-recovery attempts remain protected. No age-only `vr` sweep is acceptable.
- [ ] **#671:** with a 40-character profile and long paths disabled, generate and read back `outputs/outputs/result-<full SHA-256>.json` through the actual receipt/capture flow; full digest identity survives.
- [ ] **#672:** new install IDs have 12 hexadecimal characters, older installed IDs still work, remote archive and local Git installs retain the required JSON/package inputs, and normal generation succeeds. Excluded docs must not trigger path-budget failure; unsafe archive entries must still be rejected.
- [ ] **#673:** with #671 and #672 included, exercise default roots for a 40-character profile across all five families. Count UTF-16 code units, including staging: files stay strictly below 260 and directories below 248. This does not qualify arbitrary custom roots or #670 cleanup.
- [ ] **#669:** induce a controlled stall in the Windows service. Its phase must be published before blocking; after about 90 seconds without semantic progress, all-thread stacks reach `service-pack-host.log`. Other activity cannot reset the stalled owner's timer, and a continuing stall does not spam repeated dumps. Overlapping attempts may coalesce into one dump.
- [ ] **#676, after an authorized build contains the upstream fix:** reading the constant does not import the node/NumPy chain; after removing the workaround, normal Windows generation and heartbeat behavior still work.
- [ ] **#736:** close Updates through every supported dismissal path. Only `settings=updates` is removed; project/timeline queries, path, hash and history state survive, and reloading keeps the dialog closed.
- [ ] **#723:** independently check `--no-browser`, `ASTRID_NO_BROWSER=1`, and absent/non-TTY stdin suppress browser launch while still printing the URL; an ordinary interactive run opens it. With skills and command registration off, copy `.\run-astrid.cmd generate scan` from the install folder and run it in PowerShell. Verify the headline names the release and manifest Agent SHA. Consent policy remains undecided.
