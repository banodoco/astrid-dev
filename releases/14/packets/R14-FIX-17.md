# R14-FIX-17 — A Release 13 user updates to Release 14 and keeps their work

**Source tasks:** the red-team review of 21 Nov ([mailbox](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7061693469)). Release 13 shipped on a 14-row installed lifecycle matrix: Agent `journey.yml` on branch `harness/33-win-r12-update` at `ea5c0bff`, green in [run 43757304537](https://github.com/banodoco/astrid-agent/actions/runs/43757304537). It includes an update-over-the-previous-release row on Windows, macOS and Linux. That branch is in neither `main` nor `release/14/main`, and it has never run against a Release 14 tuple.
**Estimate:** 1–1.5 engineering days.
**Outcome:** The matrix runs from Agent `release/14/main`, and its "previous release" is the published Release 13 (App `de7dd1e6`, Agent `9814193a`, Runtime `6855dfa8`, VibeComfy `dba38f86`, schema `sha256:9628bb5f…`). Against the Release 14 candidate, every row passes:
- update over Release 13 on Windows, macOS and Linux, each with a seeded project, a marker and one saved timeline reopened afterwards;
- fresh install on all three systems;
- one update killed midway, **on Windows**, which must come back on Release 13 with the data intact;
- after each update, a **save leg**: edit a timeline, save, reload and reopen it, with the edit present;
- the **required-update rows** (owner, 21 Nov, [mailbox](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7065093369)), which replace the mixed-version rows:
  - the shipped Release 13 App, in an open tab and on a fresh visit, against the Release 14 required manifest, shows clear update instructions before any incompatible handshake or write; drafts in progress survive the update;
  - a Release 14 install reopens every Release 13-written realm, with timelines, history and the save queue;
  - the Pinokio route (Stop, Update, Start) keeps the realm and data roots, if any user installed that way;
  - a disk-full or interrupted download leaves the data intact and can be retried from outside the editor.

Port only these rows, not all 14.
**Dependencies:** [R14-FIX-15](R14-FIX-15.md) provides the App commit whose manifest declares Release 14 and its pins. The harness work can start now.
**Proof:** the matrix's own evidence gate (`scripts/check_journey_evidence.py`) passes on every row. Each receipt records 13 → 14 and the installed identities, which must match the candidate. A failure is reported with its row and step; do not weaken a row or its check to pass.
**PR destination:** astrid-agent. Cut `release/14/fix17-r13-update-matrix` from `release/14/main`, and bring the harness from `ea5c0bff` onto it. Target `release/14/main`. The smallest baseline change, located by the Lead's preparation:
