# R14-FIX-16 — A rejected save never loses the creator's change

**Source tasks:** [astrid-dev #720](https://github.com/banodoco/astrid-dev/issues/720) and [#732](https://github.com/banodoco/astrid-dev/issues/732); owner decision of 21 Nov ([mailbox](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7061493963), item 2); found by the red-team review ([mailbox](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-7061693469)).
**Estimate:** 2–3 engineering days.
**Outcome:** When the Runtime permanently rejects a timeline save, whether too large, invalid, or a missing route (400, 404, 405, 413 or 422), the editor:
- stops retrying;
- tells the creator, in plain words, that the change could not be saved and why;
- offers exactly two ways forward. **Copy my change out** keeps the change as a file the creator can save, and leaves the editor usable. **Discard and reload the saved version** is taken only by the creator's own choice.

Nothing is ever removed without that choice. Today App `release/14/main` silently removes the change, and every edit on top of it, on a `too_large` rejection (`localSaveSession.ts`, `discardOversized`, near line 160). Release 13 has no such path, so this is a Release 14 regression in user data safety. It blocks any tester build. Separately, a live-scene (Three.js) clip is saved by reference, not as inline content, so placing a world no longer produces a too-large save (#720's trigger).
**Dependencies:** none. App only, unless the by-reference change needs a Runtime or extension contract; if it does, report that before changing a contract.
**Proof:**
- Failing-before cases on App `release/14/main`, then passing after, for each permanent rejection kind (413 or too_large, 422, 404 or 405):
  - the retained change survives a reload;
  - no retry loop runs;
  - **Copy my change out** yields the exact rejected change;
  - **Discard and reload** restores the saved version only after the creator chooses it.
- #720's live-scene placement saves successfully.
- App Vitest and the affected installed save journey, by ID against App `release/14/main`.
**PR destination:** astrid-app. Cut `release/14/fix16-rejected-saves` from `release/14/main` and target `release/14/main`. Name `banodoco/astrid-dev#720` and `#732`. [Release skill](../../../agent/shared/workstreams/release.md#how-a-release-runs)
**Authority:** [run board](../run.md#authority). Changing existing editor assertions for the new behaviour is a narrow assertion change under the owner's delegation: list each one in the PR body.

One fresh packet session submits the PR and its proof. The Lead reviews (an Astra review with Luna helpers) and merges it, squashing into `release/14/main`.
