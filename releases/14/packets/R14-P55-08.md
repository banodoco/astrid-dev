# R14-P55-08 — Resident sessions in Astrid core, for packs

**Source tasks:** [`plans/55-local-speed/tasks.md`](../../../plans/55-local-speed/tasks.md) — LS-8
**Estimate:** 3 days
**Outcome:** A pack's manifest can declare that an action runs in a long-lived session. Core starts the session beside the host, with the pinned source and restricted environment a per-job process gets today, hands it jobs with a per-job fence, and ends it when the source or installation changes, on a crash or on a broken fence. Core knows nothing about ComfyUI.
**Dependencies:** none to wait for.
- Read `design.md` §4 on astrid-dev `release/14/plan-55`. Its ownership table says what is reused (`ManagedToolSession`, `persistent_supervisor`, `warm_hold`, `task_scope`, `custody_broker`, `process_group`); build on those, with no second fencing system.
- Read Plan 13's map, `plans/13-execution-host-refactor/map.md` on astrid-dev `release/14/plan-13`, slices H01–H16. The new code is a module beside `generic_host.py`, not more lines in it.
**Proof:** the card's, with a test pack: two jobs run in one session with no process start between them; a source change, an installation change and a kill each end the session, and the next job starts a fresh one; a job's fence cannot settle another job; a pack without the declaration still gets a process per job.
**PR destination:** astrid-agent, `p55/ls-8` → `release/14/plan-55` (`561950d08`).
**Authority:** [run board](../run.md#authority).

One packet starts **one fresh ChatGPT session**. The session opens task PRs and submits proof, **but does not merge or edit `tasks.md`**. The Lead reviews, integrates and reconciles tasks; the Orchestrator reports the handoff in its hourly STATUS.

Built for its first user, VibeComfy (LS-15, next), and nothing speculative.
