# R14-P61-02 — The one real run, on a hosted Mac instead of the owner's

**Source tasks:** [`plans/61-run-a-release-branch-locally/tasks.md`](../../../plans/61-run-a-release-branch-locally/tasks.md) — RB-6, RB-9
**Estimate:** 2 days
**Outcome:** Every item in Plan 61's [Completion](../../../plans/61-run-a-release-branch-locally/plan.md#completion) is shown on a GitHub-hosted macOS runner, which plays the owner's Mac:
- Release 13 is installed there as the "live" install, and given a long-lived timeline.
- `astrid-release` then runs `release/14/plan-61`'s tool for a release or plan branch beside it, on a copy of that live realm.
The first-start failure (RB-9) is either explained or recorded with its retry count and log tails.
**Dependencies:** R14-P61-01 merged, so the tool's no-stop fixes are in. Read the plan's [handover](../../../plans/61-run-a-release-branch-locally/handover.md): the commands, the live-install hash list and the negative cases are all there.
**Proof:**
- **The checklist:** every Completion box, in order, each command and its output pasted into the plan's run record from the runner's log. That includes the live install's `shasum -a 256` set and its read-only database facts, before and after.
- **Playback:** the stack's editor at `?entry=editor`, driven by Playwright on the runner, opens the copied timeline and plays it.
- **RB-9:** run several fresh first starts on fresh copies; a runner can be reset freely.
- **The negative cases:** each one listed in Completion.
- **Disk:** if the runner runs out of disk (the stack needs about 10 GB beside the live install), report the free-space numbers and what was cut. Do not skip a Completion item to fit.
**PR destination:** astrid-app, a `workflow_dispatch` workflow on `p61/rb-6` → `release/14/plan-61`, dispatched on that branch, never on `main`. Fixes the run finds go on `p61/<task id>` too.
**Authority:** [run board](../run.md#authority).

One packet starts **one fresh ChatGPT session**. The session opens task PRs and submits proof, **but does not merge or edit `tasks.md`**. The Lead reviews, integrates and reconciles tasks; the Orchestrator reports the handoff in its hourly STATUS.

The owner's own Mac and running stack are never touched by this packet. A run on her real data is optional, afterwards, at her convenience.
