# R14-P39-14 — Three repositories enforce the sealed failure ceiling

**Source tasks:** Plan 39 K2, K3

**Estimate:** 3–5 engineering days across the three repositories (RS1 §4).

**Outcome:** Each repository runs its trusted per-ID comparator on PRs and nightly. Only IDs failing on both measurements outside decision A–D may enter the initial sealed list. Listed tests still run and report their real outcomes.

**Dependencies:** [G1](https://github.com/banodoco/astrid-dev/blob/77a95b4b/plans/39-green-mains/evidence/release-14-phase1-measurement-20261116/baseline-g1/final-report-data.json.gz), [G2](https://github.com/banodoco/astrid-dev/blob/7290367c/plans/39-green-mains/evidence/release-14-phase1-measurement-20261116/remeasure-g2/final-report-data.json.gz), K0/K1 and SF3a(.1) supply the identities and results. Use the [R15 owner rows](../../../plans/39-green-mains/tasks.md#release-15-ceiling) and the expected jobs for each tier. Keep absent baseline evidence unknown.

**Proof:** In each repository show a complete covered run, an actual retirement with a passing receipt, and rejection of a new red, lost ID or job (including a missing nightly), incomplete results, an added or swapped entry, and a retired ID that fails again. See [K2](../../../plans/39-green-mains/tasks.md#k2) and [K3](../../../plans/39-green-mains/tasks.md#k3).

**PR destination:** One PR each in astrid-agent, astrid-runtime and astrid-app, `p39/k2-k3` → `release/14/plan-39`.

**Authority:** [run authority](../run.md#authority) and [RS1 decision](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-6995664680).

**Gate review.** Use the merge-base gate and removal-only ledger to catch ordinary skips, xfails, deselection, self-approved changes and missing or truncated evidence. At most two review rounds. Round two verifies the round-one fixes. [Standing rulings](../run.md#standing-rulings).

**Know before you start.** RS1.3/.5/.9 identify recovered G1 shards, pytest subtests and incomplete Playwright identities. Seal only supported ID matches. The Lead deferred causal fingerprints. [RS1 decision](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-6995664680).

One fresh packet session opens the task PRs and submits proof. The Lead reviews, merges and updates the task board.

Keep unknown failures that touch custody, persistence, retry or publication out of the ceiling. Add one injection: a same-ID, different-cause case on a sensitive test must be rejected. Before a covered run counts as green, reconcile the nine literal missing IDs, the 33 subtest failures and the missing job evidence (RS1.3, RS1.5).
