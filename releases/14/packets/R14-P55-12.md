# R14-P55-12 — Output handled once: Runtime and VibeComfy

**Source tasks:** [Plan 55 LS-6](../../../plans/55-local-speed/tasks.md), the remainder assigned by the [Lead's scope decision](https://github.com/banodoco/astrid-dev/issues/796#issuecomment-6982812408).
**Estimate:** 3 human engineering days for the streaming contract and generated client, receipt propagation, and settlement/restart proof across three repositories.
**Outcome:** Each attributed output is fetched once. VibeComfy carries its digest, length and prompt attribution through the Agent manifest to settlement. A transforming hook produces a fresh receipt. The caller receives a verified independent file and can use the settled result before thumbnail extraction finishes. Follow [design §5](https://github.com/banodoco/astrid-dev/blob/release/14/plan-55/plans/55-local-speed/design.md#5-runtime-hand-off-output-and-write-budget), D11 and D14.
**Dependencies:** [R14-P55-06](R14-P55-06.md) merged ([Agent #407](https://github.com/banodoco/astrid-agent/pull/407)).
**Proof:** LS-6, with the transfer, retry and hash-count evidence below.
**PR destination:** One PR each in astrid-runtime, VibeComfy and astrid-agent, from `p55/ls-6-remainder` into that repository's `release/14/plan-55`. Put any Agent re-pin in its own commit for the Lead's approval.
**Authority:** [run board](../run.md#authority).

1. Implement negotiated streamed `get_object` in the Runtime server and client generator. Regenerate the Agent client from the template. Runtime hashes the chunks it transmits and sends the successful completion marker only after digest and length match. The caller independently hashes received bytes against the authorized result identity and atomically installs its temporary file only after both checks and the marker. Preserve caller verification on legacy and range transfers. Prove that equal-length corruption, mutation during transfer, and loss of the marker after the last byte each preserve the prior destination and yield no verified receipt.
2. Preserve output custody, lease, fence, epoch and declared-output checks. Commit a durable thumbnail intent atomically with the main effect, bound to source digest, project and attempt. Reply after durable settlement. The trusted host reconciles pending intents on restart and admits the ordinary thumbnail task with a deterministic idempotency key. Hold thumbnail work pending and show the reply completes, then interrupt between settlement and admission and show the preview appears once after recovery. A failed thumbnail remains visibly retryable without repeating generation.
3. Use LS-2's before/after counters on the full path, including a large output. Show one fetch and one producer hash per attributed output, with Runtime verification and the caller's D14 hash counted separately. Change only the hash-count assertions in `test_output_hash_passes_across_download_host_runtime_and_delivery`, together with the de-duplication they measure. Verify delivery leaves the store's file inaccessible for writing through the caller's copy.

One packet starts **one fresh ChatGPT session**. The session opens task PRs and submits proof, **but does not merge or edit `tasks.md`**. The Lead reviews, integrates and reconciles tasks; the Orchestrator reports the handoff in its hourly STATUS.
