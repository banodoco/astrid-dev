# Release 14 standby Lead

The owner keeps a standby Lead in a Codex session (Astra), so that Release 14 keeps moving if the Claude Lead session stops. The standby waits, and takes over only after 3 hours without a Lead heartbeat. The general rule is in the [Lead workstream](../../../skills/roles/astrid-dev-lead/workstreams/multi-manager-release.md#standby-lead).

## Heartbeat

The Claude Lead posts on [mailbox #796](https://github.com/banodoco/astrid-dev/issues/796) at least every 90 minutes, a `STATUS` when nothing else is due. A **Claude Lead message** is a comment whose `text` block says `from_session: r14-lead` and whose body ends with the footer `_Generated by [Claude Code](https://claude.ai/code)_`.

## Wait mode (every hour)

1. Read the last 30 mailbox comments:
   - `gh api "repos/banodoco/astrid-dev/issues/796/comments?per_page=100&page=<last>"`, where the last page is ⌈comments ÷ 100⌉ from `gh api repos/banodoco/astrid-dev/issues/796 --jq .comments`;
   - or, without `gh`, the same through your GitHub connection.
2. Find the newest Claude Lead message and its `created_at`.
3. **If it is less than 3 hours old, do nothing and post nothing.** Wait for the next hour.
4. **If it is 3 hours old or more**, rule out a quiet Lead. Look for any of these in the same 3 hours:
   - a commit or pushed branch named `claude/*` in banodoco/astrid-dev;
   - a pull request opened or merged by the Lead in astrid-dev, astrid-agent, astrid-runtime or astrid-app;
   - a newer "Now" time in [run.md](../run.md).

   If you find one, wait another hour. If you find none, take over.
5. **If the newest `r14-lead` message is a takeover by you**, you are the Lead: run check-ins, not wait mode.

## Taking over

1. Read, in order:
   - the [Lead role skill](../../../skills/roles/astrid-dev-lead/SKILL.md) and its [workstream](../../../skills/roles/astrid-dev-lead/workstreams/multi-manager-release.md);
   - the [run board](../run.md): Authority, Standing rulings, Dispatch queue and Waiting on the owner;
   - this folder: [README](README.md), [notes](lead-notes.md), [review tiers](review-tiers.md) and [gate review notes](gate-common.md);
   - the mailbox from the board's Lead cursor onwards.
2. Post one message on the mailbox: `type: DECISION`, `to: all`, `from_session: r14-lead`, beginning *"Lead continuity: the standby Lead session is now r14-lead. The previous Lead session has been silent since <time>. Nothing else changes."* Then keep the mailbox name `r14-lead` for everything.
3. Run a first check-in at once, then every 30 minutes while anything is in Review, else every 60. Use whatever scheduler outlives your machine, and say in your first STATUS which one it is.
4. **Capability check**, in the first STATUS. List which of these you can do, and for each one you cannot, the owner's manual step:
   - comment on the mailbox;
   - read pull requests, runs and job logs in the four repositories;
   - merge a pull request;
   - mark a draft ready;
   - dispatch or rerun a workflow;
   - push to an astrid-dev branch and open a PR with auto-merge;
   - start a reviewer sub-agent.

   If you cannot start sub-agents, review yourself at high reasoning effort with the same briefs.
5. You hold the Lead's Authority on the board, including any delegation in force. You inherit nothing more.

## If the Claude Lead comes back

After a takeover, the Claude Lead stands down. It posts nothing and acts on nothing until the owner hands the role back. The standby stays Lead until then.

## Start message

The owner pastes this into a fresh Codex session on the Astra model, with the highest reasoning effort it offers:

```text
You are the STANDBY Lead for Release 14 of Astrid (GitHub org banodoco). You are not the Lead yet.
Read releases/14/lead/standby.md on banodoco/astrid-dev main, and follow it exactly.

Set yourself a reminder that fires every hour and resumes this same session. If you cannot set one, tell me now, before anything else.
Then confirm, in one short reply to me (not on GitHub), that you can read banodoco/astrid-dev issue #796 comments.

Every hour, run "Wait mode" from that file:
- find the newest mailbox comment from the Claude Lead: from_session r14-lead, ending with the Claude Code footer;
- if it is under 3 hours old, do nothing and post nothing;
- if it is 3 hours old or more, and the Lead also left no commits, PRs or board edits in those 3 hours, take over as "Taking over" describes.

Until you take over, post nothing on GitHub and change nothing. After you take over, you are r14-lead, with the Lead's Authority from releases/14/run.md and nothing more.
Keep each waiting check short, so this conversation lasts. If this chat nears its length limit while still waiting, tell me, so I can start a fresh standby with this same message.
```
