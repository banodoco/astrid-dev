# Release 17 — Continuous hardening

**Release:** 17
**State:** Draft
**Release manager:** not yet named

## Highlight

The Agent, Runtime and App have trustworthy green test suites, execution failures are reproducible without paid machines, and the execution host is simpler to maintain.

## Intent

After [Release 16](16.md), make reliability sustainable: eliminate inherited CI failures by cause, keep checks green and reduce the execution host's structural risk. Owner direction, 25 November 2026. This is the second release in the sequence; do not defer harm on supported Release 16 journeys merely because it appears in this hardening backlog.

## Approach

Preserve Plan 91's existing branch, evidence, mailbox and standing rulings; the Lead must coordinate its move from the old Release 16 target before any landing or new target-dependent dispatch. Run 39 and 91 with explicit per-test baselines and root-cause repair; never weaken current-behavior assertions. Reconcile 50 against RunPod's experimental status, with money safety required already. Start the host extraction with 13, use its measured result to bound 83, and coordinate with the process-identity work in 16 and test owners so proof is not invalidated. Include VibeComfy/launcher required checks where they affect the shipping tuple, without inventing a new independent programme. Ship the integrated set once the promised green and hardening outcomes are proven. [Release 18](18.md) follows.

Each release has one theme and a [standing lane](../skills/shared/glossary.md).
