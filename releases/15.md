# Release 15 — Every platform and rented machines

**Release:** 15
**State:** Draft
**Release manager:** the Release 15 [Lead](../skills/roles/astrid-dev-lead/SKILL.md), session `session_011EzfW1gtAhRQwk8pgJMzhG` (named by the owner on 21 November 2026; it takes over from the setup session, `session_011EzfVzwqZJRctZ5jAQnQc9`)

**Run board:** [`15/run.md`](15/run.md). First lane: Plans 69 then 77, one manager ([brief](15/briefs/plans-69-77.md)).

## Highlight

Generation is tested for real on Windows, macOS and Linux on every build, and a rented machine can never keep billing unnoticed.

## Intent

[Release 14](14.md) makes the tests that exist run and pass. This release adds the tests that do not exist yet, and closes what can cost a user money. A good outcome: a real generation on CPU in CI on the three systems, a Windows update from the previous release, the money-safety items for rented machines closed, the reliability items deferred from Release 13 closed or deliberately dropped, and the execution host split into modules on tests that are green.

Proposed by the advisor and agreed by Hannah on 15 November 2026 (version 0.1 is "focused on hardening, updates, stability and speed"), with fixes and plans added on the fly from actual usage and user reports. See [Strategy](../strategy.md#decisions).

The Windows tester runs found failures no automated test had ever executed; doing this after the speed release avoids testing a generation path that is about to be replaced. Getting to green moved to Release 14 on 16 November 2026 (Hannah), because its release branch could not be trusted until it was.

## Approach

After Release 14, because that release rewrites the path every job takes and about ten deferred items change or disappear with it, and because it leaves the tests green. Start by re-measuring on the published Release 14 code; fix by cause, never by loosening a test. Carries the rest of [Plan 39](../plans/39-green-mains/plan.md): the structural fixes that kept the mains hard to read, and the release rule that every required check is green on each pinned commit. Carries the extraction of the execution host ([Plan 13](../plans/13-execution-host-refactor/plan.md)), which Release 14 mapped. Includes the money-safety items for rented machines, because they can cost a user money: a rented machine that cannot stop itself when the person's computer sleeps, and a failed clean-up that leaves one billing. Offline tests of the rented-machine boundaries so those failures are found without renting.

The Windows tester run of 15 November 2026 found six generation failures in one afternoon that no automated test had ever executed, because Windows checks covered installing and starting only. So this release also adds: a generation against a real ComfyUI on CPU in CI on Linux, macOS and Windows ([#678](https://github.com/banodoco/astrid-dev/issues/678)); a Windows update from the previous release ([#679](https://github.com/banodoco/astrid-dev/issues/679)); the unit tests run on Windows itself, not on Linux with the platform name faked ([#680](https://github.com/banodoco/astrid-dev/issues/680)); a first run on macOS with a person's own ComfyUI ([#681](https://github.com/banodoco/astrid-dev/issues/681)); a check of whether the network guard is enforced on Windows ([#682](https://github.com/banodoco/astrid-dev/issues/682)); and errors that name the real cause ([#683](https://github.com/banodoco/astrid-dev/issues/683)).

Each release has one theme and a [standing lane](../skills/shared/glossary.md).

## Included plans

- [Plan 39](../plans/39-green-mains/plan.md) — the structural fixes from Release 12, and the release rule that every required check is green on each pinned commit.
- [Plan 13](../plans/13-execution-host-refactor/plan.md) — the execution host split into modules, one responsibility at a time.
- [Plan 50](../plans/50-recorded-boundaries/plan.md) — rented-machine failures found on a CPU.
- [Plan 40](../plans/40-machine-lifetime-controls/plan.md) — the remaining cost and lifetime controls.
- [Plan 69](../plans/69-project-elements/plan.md) — editing a real clip: project elements (a project's own effects and components, loaded in every editor and rendered the same in preview and final render) and the practical editor and timeline fixes found while doing it. The work is done, on `release/15/plan-69`; it needs an inventory and landing. Plans 77 and 78 build on it (moved here on 21 November 2026; scope pending the owner).
- [Plan 77](../plans/77-saving-holds-on-a-heavy-timeline/plan.md) — a loop plan, first among the saving plans: on a heavy generated timeline every ordinary edit saves in about 2 s or is refused only for a real clash, found and fixed by live rounds whose evidence rewrites Plans 63, 75, 76 and 18 (about 4 days; moved from Release 14 by the owner on 21 November 2026). Its branches were cut from Release 14's integration of Plans 59, 64 and 65, then took in Plan 69 and the forwarded `release/15/main`, because Release 14's integration has not yet landed in `release/14/main`.
- [Plan 63](../plans/63-dependable-saving/plan.md) — dependable saving, first: nothing is refused or undone however fast the owner edits, every change from the editor or an agent ends in one of four outcomes the server names, and a refusal or clash parks and never blocks (about 39.5 days; the owner decided Release 15 on 18 November 2026, and it starts on her go).
- [Plan 76](../plans/76-editing-together/plan.md) — editing together, after Plan 63: an agent edits beside a person without blocking or overwriting them (about 12 days).
- [Plan 18](../plans/18-timeline-editing/plan.md) — phase A only, agents and packs (about 18 days, Agent and Runtime, no App code), after Plan 63's server track; phase B, the editor's gestures as commands (about 44 days), is not in this release's scope until its D4 is answered.
- [Plan 78](../plans/78-live-custom-element-editing/plan.md) — live custom-element editing: one mixed edit in one commit, with pack refresh and the editor's live proof (4–6 engineering days; the owner approved the scope, including the fresh-install motion-pack pin and 2-round review cap, and added it to Release 15 on 21 November 2026).
- [Plan 79](../plans/79-local-media-any-size/plan.md) — local media of any size: a clip from the creator's own computer is placed at any size the Runtime accepts, with one limit, streaming instead of loading the file into memory, and the original never touched (about 8 engineering days across the Runtime's client, the Agent and the App; the owner asked for the project and this release on 21 November 2026; she decided D1, D2, D4 and D5 the same day; it starts after Plan 77 lands, with an interim 1 GiB limit meanwhile).
- [Plan 81](../plans/81-under-a-second-to-start/plan.md) — under a second to start: on a warm local machine a generation is queued and a timeline edit is accepted within a second of running the command, by timing every stage, working each thing out once and holding the result with a test; a slow command says what it is waiting for (about 22 engineering days, re-stated after its first real measurements; the owner asked for it and for this release on 22 November 2026, and decided D1 to D5 the same day). It replaces Plans 55 and 75 in this release: she asked for those, the tenth-of-a-second redesigns, to wait in no release.
- [Plan 52](../plans/52-issue-intake/plan.md) — issue intake: its last tasks, one place for user and tester reports (about 2.5 days, mostly waiting on the owner; moved from Release 14 by the owner on 21 November 2026).
- [Plan 53](../plans/53-vision-aspirations/plan.md) — vision aspirations: one short reference under the vision for each part of Astrid, and every gap measured against it (about 4.5 days, waiting on the owner's mark-up; moved from Release 14 by the owner on 21 November 2026).

- [Plan 72](../plans/72-composable-project-delivery/plan.md) — consolidate canonical delivery relationships into reusable typed links, with a small read-only issue-to-release reuse proof (internal only; no publication change).
