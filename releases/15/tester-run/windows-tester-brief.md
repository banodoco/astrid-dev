# Test Astrid Release 15 on Windows

**For testers:** Give this page to your coding agent. Try Astrid, make something, and tell us what worked, what was awkward and what broke. You have agreed to give detailed feedback; the agent should handle the engineering and reporting rather than make you follow a long terminal checklist.

**The result:** one GitHub issue telling the whole story of your session, plus separate linked issues for actionable problems (or links to existing ones). A fix PR is a bonus, **not** a requirement. A blocked or unsuccessful test is still useful when reported accurately.

This tests the **unpublished Release 15 Agent and Runtime**, not the currently served web editor. The usual astrid.haus installer selects the published release, so it **does not** count as a Release 15 test.

## Agent workflow

1. **Start the session issue.** Ask permission to post feedback to public GitHub and show the tester the redacted draft, as the setup skill requires. Search [astrid-dev issues](https://github.com/banodoco/astrid-dev/issues) for this tester's existing run and reuse it if resuming. Otherwise open one [observation issue](https://github.com/banodoco/astrid-dev/issues/new?template=observation.yml): `observation: Release 15 Windows test — tester/date`. Record **Session started**, the planned scope, Windows/GPU/VRAM, existing ComfyUI, fresh install vs update, and the tester's permissions. Update this issue as you go. If you cannot create it, prepare a link for the tester and do not install until its URL exists.
2. **Verify the build and isolate code changes.** Obtain the Release Lead's **approved, green, frozen** Release 15 `install.ps1` and `install-manifest.json` from the [tester-build workflow](../../../skills/shared/workstreams/astrid-dev-release/SKILL.md#tester-builds). Record exact Agent/Runtime/VibeComfy SHAs, manifest hash, and **active** installed identities. Detect the current install's ownership first; do not overwrite a Pinokio-managed install or attempt an unapproved migration. Never assume an old `windows/tester-*` artifact is Release 15. If no approved build exists, report **BLOCKED**. The [manual source route](windows-test-matrix.md#part-2-install-or-update-to-frozen-release-15-main) is maintainer-only with explicit Lead authorization. For investigation, create a separate scratch checkout and local `tester/r15-<session>-<topic>` branch from the **tested Release 15 commit**, but keep the initial test unmodified.
3. **Set up and test.** Read the [Astrid setup skill](https://github.com/banodoco/astrid-agent/blob/release/15/main/astrid/packs/setup/docs/SKILL.md) **at the exact frozen Agent SHA** (replace `release/15/main` in the navigation link with the full commit from the approved manifest). Reuse its installation detection, choices, consent, ComfyUI connection, first image and troubleshooting. **Do not run its normal published installer or preinstall helper**: only the approved tester bundle installs this test build. Use the [generation skill](https://github.com/banodoco/astrid-agent/blob/release/15/main/astrid/packs/generation/docs/SKILL.md) for creative commands and the [technical matrix](windows-test-matrix.md) for exact Release 15 tests, timings, output checks and optional GPU work. Core: install/update, verify build, connect the tester's ComfyUI, make an image and immediately repeat it where possible. Try additional image editing, audio, video or a tester-chosen project when feasible. Mark each cell **passed / failed / refused / skipped / blocked**; a RunPod result is not Windows-local proof.
4. **Record the actual experience.** Keep a live timeline in the session issue: what the tester tried and expected, what happened, what delighted them, confusing terminology, unnecessary steps, waits and workarounds. Preserve the tester's words separately from your interpretation; quote only with permission. Ask a short feedback question **after setup, after the first creation and at the end**, not after every click.
5. **File distinct problems separately.** When there is a concrete independently actionable problem, search existing [astrid-dev issues](https://github.com/banodoco/astrid-dev/issues). If found, get the tester's permission to add redacted evidence there; otherwise show the redacted draft and get consent before posting with the existing [intake forms](../../../docs/contribution-workflow.md#issues): `bug:` for failures, `observation:` for specific UX friction, `idea:` for missing capabilities. Add expected/actual behaviour, steps, active version/SHA, redacted evidence and a link to the testing session; link the finding from the session too. **Do not create a new issue for every hesitation or passing test.** Maintainers, not testers, decide Release 15 scope.
6. **Offer a focused fix, optionally.** With the tester's consent, investigate on a branch from the frozen Release 15 source, add regression proof, and submit an issue-linked patch or PR. Follow the [contributor skill](../../../skills/astrid-dev/SKILL.md) and ask the Lead for the authorized `release/15/<topic>` fix-branch destination. **Never push or merge straight into `main` or `release/15/main`.** Do not patch the installed candidate or misreport patched results as baseline results.
7. **Finish and clean up.** Post a short final comment on the session issue: overall verdict, positives, frustrations, most important frictions, test outcomes/skips, exact source and environment, issue/PR links, diagnostics and unanswered questions. Complete the [cleanup procedure](windows-test-matrix.md#part-6-clean-up-and-report), ask whether to keep or restore the prior installation, and record what was removed or retained. If RunPod was used, record approved/actual cost and independently verified termination.

**Safety:** Ask before installing/updating, changing saved settings, downloading models, starting a generation or spending on RunPod. Back up existing projects, never alter the tester's ComfyUI node packs or remove their pre-existing models, and redact tokens, private paths and personal data before posting. Follow the [RunPod skill](https://github.com/banodoco/astrid-agent/blob/release/15/main/astrid/packs/runpod/docs/SKILL.md) for paid machines. Record any failure to obtain consent as a skip or blocker.

**Done means meaningful feedback and honest evidence, not a perfect pass rate.** The [technical matrix](windows-test-matrix.md) is the detailed reference; this page is the only entrypoint for the tester.
