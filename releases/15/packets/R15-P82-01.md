# R15-P82-01 — A task whose approval receipt does not match its admitted bytes is refused (RA-6)

**Source tasks:** [`plans/82-reuse-across-commands/tasks.md`](../../../plans/82-reuse-across-commands/tasks.md) — RA-6
**Route:** X (ChatGPT mode: Extra High; [run contract](../../../agent/shared/run-contract.md#chatgpt-session-modes)). The orchestrator reviews it on the high-judgment route (integrity check).
**Estimate:** 1.5 days (inferred); aim for one design STATUS inside the first hour and the PR within about three hours of it
**Outcome:** The worker or pack host, before it compiles and runs a ComfyUI task, recomputes `revision_id`, `workflow_content_digest` and `api_digest` from the exact admitted `workflow.py` and companion bytes and refuses the task, naming which field differs, if any differs from the task's `invocation_preflight` receipt (or if the companion's own `generation_id` disagrees with the one the receipt names). A matching task is admitted and runs unchanged. This must land before any cache ships: Plan 82's caches reuse results, and this is the check that a reused result cannot silently carry a stale receipt.
**Dependencies:** none (Plan 81 is landed on `release/15/main`).

## Why, and what the code looks like (read first)

The [floor experiment](../../../plans/82-reuse-across-commands/evidence/2026-11-24-thin-client-floor/README.md#surprises) (surprise 1) admitted and ran 10 tasks whose receipt held a stale `api_digest` and `revision_id` and whose companion held a stale `generation_id`. Nothing downstream compared them with the bytes. The scouting read, on `release/15/plan-82`:

- The Runtime (`runtime_protocol/service.py:6764 create_task`, `store.py:2840`) stores the spec opaquely and has **no VibeComfy dependency and no knowledge of `invocation_preflight`**. It cannot recompute `api_digest`. **The seam is on the Agent side.** A Runtime-side validator seam is a Release 16 item (Plan 92) and is **not** part of this packet. **Release 15 Lead ruling, 24 November 2026:** the binding check goes on the **host** side, in the worker or pack host before `_approve_live` (the boundary is caller versus host). Because every task that runs passes through that worker, it also stops a task a direct client POSTed to `/v1/tasks`; the packet proves that. A command-side check is allowed only as an **earlier, friendlier error**; it is not the guarantee.
- The receipt (`astrid/packs/vibecomfy/invocation_preflight.py`, the dict built in `preflight_invocation`, about lines 495 to 505) holds `schema_version`, `phase`, `workflow_identity`, `revision_id`, `semantic_digest`, `workflow_content_digest`, `api_digest`, `run_inputs`, `reachable_nodes`, optional `expected_prompt` and `source_av`. It has no `generation_id`; that is in the companion (`workflow.vibe.json`). The capability digest travels in the admission envelope as `capability_digest`.
- It is attached at `astrid/sdk/remote.py:2236-2254` (create-task path) and `:3001-3019` (invoke path), also `astrid/sdk/workspace_client.py:1057-1072` and `astrid/sdk/invocation.py:2692-2708`. `_vibecomfy_invocation_preflight` (`remote.py:34`) re-reads the python, companion and source objects by digest and checks sha256 before calling `preflight_invocation`.
- The worker side is `astrid/packs/vibecomfy/local_server_engine.py`: `run_local_server` (about line 400) calls `_approve_live` (about line 215), which runs `bundle.compile(...)` on the staged bytes. Nothing in this file reads `invocation_preflight`.
- Precedent for the exact comparison: `astrid/sdk/transcript_run.py` (about lines 88 and 150-160) compares `receipt.workflow_content_digest` with `_expected_workflow_digest` and `_admitted_workflow_digest`. Follow that pattern.

Line numbers were read on 24 November 2026; re-check them.

## Contract

- A task whose receipt's `revision_id`, `workflow_content_digest` or `api_digest`, or whose companion `generation_id`, does not match what the admitted bytes recompute to is **refused before the compile and before the target is touched**, with a message naming the differing field and both values' short digests.
- A matching task, and every task today's tests admit, still admits and runs unchanged. No wire, schema or store change; no new Runtime or VibeComfy dependency; no pin.
- No check is removed or moved later. The new refusal is added before `_approve_live`, and `_approve_live` itself, `require_canonical_authority` and the live schema preflight keep their place and order.
- Refusals are not retried and not downgraded to a warning. No broad `except`, no silent fallback, no flag that skips the check.

## Proof (new tests; change no existing assertion)

New tests, with the receipt and companion built through the real `preflight_invocation` path, not hand-written dicts:
1. A task whose receipt `api_digest` differs from the admitted bytes is refused, naming `api_digest`.
2. The same for `revision_id`, for `workflow_content_digest`, and for a companion `generation_id` that differs.
3. A matching receipt and companion are admitted (the worker proceeds to the compile).
4. Prompt, seed and size changed in the bytes without the receipt being re-derived (the stale-cache case from the floor experiment) is refused; the same change with a re-derived receipt is admitted.
5. The refusal happens before the target is contacted (assert no request reached a fake target).
6. **Direct POST:** a task with a mismatched receipt is admitted through the plain Runtime path (the Runtime's `/v1/tasks`, using the real Runtime fixture and the Runtime client, no `astrid generate` and no SDK preflight) and the worker refuses it, naming the field.
