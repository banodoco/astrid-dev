# R15-P87-07 — `clip.move` and `placement.move` write integer `at_ms`

**Source:** Release 15 Lead DECISION `r15-lead-p87-0004` ([#1776 comment 7140838944](https://github.com/banodoco/astrid-dev/issues/1776#issuecomment-7140838944)); it extends Plan 87's integer-millisecond fix (`occurrence.create`, Agent `2efd174a`). No `tasks.md` row yet: the orchestrator adds it.
**Route:** S (ChatGPT mode: Pro; [run contract](../../../skills/shared/run-contract.md#chatgpt-session-modes)). It touches the stored timeline format, so it gets a high-judgment review.
**Status:** Ready (route confirmed by `r15-lead-p87-0006`; manager `r15-p87-manager-2`; the orchestrator names the head at dispatch)
**Estimate:** 1 day (inferred)
**Outcome:** The Agent commands `clip.move` and `placement.move` write a non-negative integer `at_ms`, never a fractional one. A project saved under Release 14 with a fractional clip or placement `at_ms` opens in the editor, because the App rounds it on read.
**Dependencies:** the fix worker's branch `p87/ci-fixes2` is merged into astrid-agent `release/15/plan-87` first. Branch from the head the orchestrator names at dispatch (at writing the ref was `0ca8c77c`; do not use that if a later head is named). New branches: `p87/clip-move-int-ms` in astrid-agent; `p87/clip-move-int-ms-app` in astrid-app (from App `release/15/plan-87`, head `c091d432` at writing, or the head named at dispatch).

**The defect:** `move()` in `astrid/sdk/timeline/capture.py` ends with `ctx.write(ref, ['at_ms'] ..., local * 1000)` where `local = float(quantized) - origin` is a float of seconds, so a frame-snapped start such as frame 128 at 30 fps stores `4266.666666666667`. `placement_move` in `native_placement_commands.py` calls the same `move()`, so one fix covers both writers. The editor requires an integer `at_ms` (`src/tools/video-editor/data/shotComposition.ts` lines about 53 to 54 and 201 to 203).

**Rounding rule (the same as `occurrence.create`; do not invent another):** `start_ms = round_half_even(frame * 1000 / fps)` on the parent frame grid, using Python `round()` on an exact `Fraction` (ties go to the even integer). `duration_ms = int(round(duration * 1000))`, not frame-snapped. A whole-millisecond input keeps its exact value. For a clip inside an occurrence, take the global integer start and subtract the occurrence's start (`occurrence_start`, in ms); round that difference to an integer if a legacy occurrence start is still fractional.

**Scope:**
1. Reuse the helper from `native_occurrence_create.py` (`frame_snapped_start_ms`) by import; do not copy or edit it. In `move()`, compute the integer millisecond start from `frame` and `fps` and write it to `at_ms`.
2. Keep the codecs agreeing. `_duration()` in `capture.py` raises `contradictory at/at_ms timing codecs` when `at` and `at_ms/1000` differ by more than 1e-9. So when a clip carries both `at` and `at_ms`, write `at` as the same integer value divided by 1000 (so a later move or trim does not refuse), and when it carries only `at`, leave the `at` seconds write as it is. Check this against the existing at/at_ms tests and say in the PR how you handled it.
3. Keep the boundary check (`moved interval crosses the next occurrence`, `placed interval exceeds occurrence duration`) on the exact quantised seconds so that a 1 ms rounding change cannot flip an accepted or refused move. If a rounded value would cross a boundary the exact value did not, say so in the PR instead of changing the check.
4. App, read time only: apply the Release 14 normalisation to fractional stored `at_ms` on clips and placements, as `normalizedStoredStartMs` in `src/integrations/runtime/dataProvider.ts` (about lines 2376 to 2400) already does for an occurrence's `placement.start_ms` (use of it at about lines 2455 to 2474 and 2636 to 2661). Reuse that function; do not change its rule. Find where the App reads a clip's or placement's stored `at_ms` and make the copy used by the editor integer; the canonical stored document and the save diff base keep the stored value, as for occurrences.
5. Do not change the command schema, the recorded capture fields or the `move.quantization` dependency (`rounding: half-toward-positive-infinity` stays; it describes the frame choice, not the millisecond rounding).
