# R15-Q-03 — Agent timeline writes keep every `_ms` field a whole number the editor accepts

**Source tasks:** `releases/15/qualification.md` row 5 (Lead DECISION r15-lead-qual-0004); issue packet. Plan 87 found and fixed one instance (Agent `2efd174a`, App `4ab5da56`, on `release/15/plan-87`, not on `release/15/main`); this packet checks the whole class.
**Route:** X (Extra High): an invariant over every write path, proved by driving each.
**Estimate:** about 1 engineering day.
**Repro:** On `release/15/main` (Agent `514499de`), `occurrence.create` stores `start_ms = float(Fraction(frame, 1) / fps) * 1000` (`astrid/sdk/timeline/native_occurrence_create.py`, about line 39): a fractional value (1 frame at 30 fps is 33.333… ms). The App derives `at_ms` from `placement.start_ms` (`src/integrations/runtime/dataProvider.ts:2436`) and its composition validators require whole numbers (`src/tools/video-editor/data/shotComposition.ts:53-55`, `nonNegativeInteger`, message shape `occurrences[1].at_ms: must be a non-negative integer`; `shotCompositionAdapter.ts:158-164`). So the editor cannot open the project (Plan 87's board, astrid-dev #1776).
**Outcome:** An Agent-side test that drives each timeline-writing command in-process on a fixture and asserts every `*_ms` field it writes on a placement, occurrence or shot is an `int` on the frame grid (`type(value) is int`, never a float, never a `Fraction`), failing with the command name and field path; plus, where the App's validators can be called from node with no network, the same composition passed through `parseShotComposition`.
**Dependencies:** R15-Q-01's harness files (`tests/editing_conformance/app_open/open-bundle.mjs`, the sibling App checkout) if present on `release/15/q-agent-writes`; otherwise the packet adds its own small node call. Facts: the App loader `loadTimelineJsonFromProvider` has no `start_ms` check itself, so the invariant is best proved Agent-side.
**Proof:** the new test fails on `release/15/main` for `occurrence.create` (the known case) and passes once `2efd174a` is merged into `release/15/q-agent-writes` (the Qualifier does that merge to prove it); the selectors below pass unchanged.
**PR destination:** astrid-agent `p15q/R15-Q-03` → `release/15/q-agent-writes`, then to `release/15/main` through the Lead's gate.
**Authority:** [qualification dispatch](../run.md#qualification-dispatch); Lead DECISIONs r15-lead-qual-0004, -0005, -0007.

## Contract

1. New test file `tests/editing_conformance/test_agent_ms_fields_are_whole_numbers.py`. Reuse the in-process pattern of `tests/editing_conformance/test_commit_runtime_occurrence_create.py` (`execute(original, [birth(original, on=4.25, duration=4)]).bundle`, `State(born).occurrence(OWNER)`) and `tests/editing_conformance/test_recipe_occurrence_create.py` (`capture_*`, `commands.execute`). Offline; the test blocks outbound network itself.
2. Walk the commands in `astrid/sdk/timeline/commands.py` (`occurrence.create`, `occurrence.duplicate`, `occurrence.fork`, `occurrence.place-shared`, `clip.move`, `placement.move`, `placement.create`, `clip.trim`, `clip.split`, `occurrence.add-media`, `clip.add-media`, `shot.set`, `shot.pool`, and any other that writes a time) with times chosen to be off the millisecond grid (for example `on=4.25`, a 29.97 and a 30000/1001 fps, durations such as 10.01). For each, assert every `*_ms` field in the resulting bundle is an `int` and equals the frame-snapped rounding of the exact rational (half-to-even, as `2efd174a` does). The PR body carries a coverage table: writes found, writes covered, writes not covered and why.
3. **`duration_ms`:** Plan 87 deliberately left `duration_ms` as before because `test_recipe_occurrence_create.py:67` expects 10000 for 30000/1001; changing that assertion is the owner's call and not this packet's. Assert only "is an int", not the value, for `duration_ms`, and list in the PR any `duration_ms` that is not an int.
4. A failing assertion is a **finding for the owning plan**, never a test to loosen; list each (command, field, value) in the PR body for the Qualifier to relay. No product code changes. No existing assertion changes.
