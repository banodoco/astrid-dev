## Contract (phase 1)

1. New files only: `tests/editing_conformance/test_agent_writes_open_in_app.py` and `tests/editing_conformance/app_open/open-bundle.mjs` (from `parse_bundle.mts`: reads a bundle JSON path, imports the App's `parseTimelineBundle` from `$ASTRID_APP_ROOT`, prints `{"ok": bool, "name": ..., "message": ...}`, exits 0 on accept and 1 on reject). The test skips with a loud, named reason if `ASTRID_APP_ROOT` or Node is absent, and fails instead of skipping when `ASTRID_REQUIRE_APP_PARSER=1` (how the gate runs it). The test blocks outbound network itself (the suite has no global socket block).
2. **Cases that produce a saved draft with no runtime, in this order:** (a) `transcripts refresh` (the worked example, with the fixture seeded the way a real project is: `config.bundle` has `schema_version` and `itemsBySchemaRef`); (b) `edit --add-media` through `tests/packs/timeline/test_cli_media.py`'s fixture with a real `Checkout.save` instead of the stub; (c) every other timeline-writing verb whose command is driven in-process by the existing tests (`occurrence.create`, `clip.move`, `clip.trim`, `clip.anchor`, `occurrence.add-media`, `clip.add-media` and the rest in `astrid/sdk/timeline/commands.py`) **only where it yields a draft or a bundle with `parent.config.bundle`**. Where a verb yields only a commit request or a document, say so in a coverage table in the PR body (one row per write in `commands.py` and the CLI verb table: covered, or not and why: for example "needs the integration runtime, red on `release/15/main`"). The sweep carries its count: writes found, writes covered, writes not covered.
3. **Mutation check, in the test:** for each covered write, the same bundle with one required field removed (for `transcriptReferences`, rows lacking `assetId`) must be rejected by the harness, so the harness can fail.
4. **Expected state on `release/15/main`:** the transcripts-refresh case **fails** (the finding above) until Plan 88's #624 is on the branch. Do not skip, xfail or loosen it. The PR states which cases fail on `release/15/main` and with which parser message; the Qualifier merges #624's head into `release/15/q-agent-writes` to prove the case turns green.
5. Reuse fixtures: `tests/sdk/test_timeline_sync.py` (`initial_bundle`, `connected`), `tests/sdk/test_timeline_transcript_refresh.py`, `tests/packs/timeline/test_cli_media.py`, `tests/fixtures/timeline_editing/tiny.json`. No new fixtures that copy these.
6. A rejected bundle is a **finding for the owning plan**, never a test to loosen; the PR body lists each (command, parser message). No product code changes.
