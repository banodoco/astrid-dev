## Synthesis

1. **A brief changes defaults, and says so.** Kind: precedence. General documents stated defaults as absolutes, such as "only when the owner asks", "every 20 minutes", "a Lead gate before a release branch" and "the orchestrator never writes Run start"; the H3 brief changed them, and nothing said which wins. Settles: h3-orchestrator-start E8, X2, X4, X5; h3-codex-manager-start E6, X3, X4; h3-orchestrator-proof-and-hold (release gate); h3-orchestrator-silent-manager (cadence); improve-changes-workstream E2. Fix: one sentence in the run contract's Who answers for a run, and the three absolutes softened to defaults.
2. **One start message per edge, and one way back.** Kind: missing parent. Each session invented how it returns: draft or ready, push or return the tree, which base, which sign-off, BLOCKED with or without lines, which template to send. Settles: h3-codex-manager-start E6; h3-chat-unit E1–E7; h3-claude-worker-fallback E4, X4; manager-starts-worker E6, E8; h3-orchestrator-start E5, E7, X1; h3-orchestrator-proof-and-hold E1. Fix: start-session step 7 gains "the way back"; the dispatch template defers to a brief's chat message; chatgpt-packet's base follows the pin; the brief orders LAUNCH before STATUS 1, allows READY early and defines the CI check.
3. **Long-running roles check in, one-shot roles report, on one clock.** Kind: precedence plus structural. Settles: h3-claude-worker-fallback X2; improve-changes-workstream E2, X1; h3-orchestrator-silent-manager E3, E4; h3-orchestrator-start X4. Fix: run contract items 5, 7 and 8: who checks in, one 2-hour/3-hour clock, never two writers on a branch, keep-awake only where a brief asks.
4. **What a host can do decides where tests run.** Kind: wording. "A chat can't build" was read by a worker that can. Settles: h3-claude-worker-fallback E3, X3. Fix: the brief's Proof bullet says fallback workers build with `scripts/worker-env/`; Plan 66's test inventory names that command.
5. **Test a role on the cheapest route allowed to hold it.** Kind: case design. The Lead and reviewer misses were judgment failures on `N` in roles that run on `X` or `S`. Settles: lead-divides-lanes E1–E4; h3-reviewer-s-unit E1. Fix: the README's `actor` rule; lead-divides-lanes runs on `X`, the reviewer on `S`.

Left as actor-errors, with no document change: h3-codex-worker-fallback (the guide is linked and clear), contributor-start E5, improve E3 and E7. A contract line now says a community pack joins through the extension contract, which removes the cause of contributor-start E2 and E3.

### Rounds 2 and 3: what the synthesis added

6. **A rule a role needs must be on that role's own reading path.** Kind: structural. The way back lived only in start-session, which the creator reads; the worker's page never linked it. The same held for the manager's proof re-run and improve's skill build. Fix: each role page links its side of the hand-off (`worker.md`, `whole-project.md`, `improve.md`, `chatgpt-packet.md`).
7. **Every worker commits its own work.** Kind: precedence, introduced by this run's own golden path. The golden path said a subagent "returns its tree and its creator commits", against the run contract and the Codex guide, which have workers commit and return the SHA. The owner confirmed that workers run their narrow tests and commit. Fix: every worker commits; a worker session also pushes and opens the draft PR; a subagent returns the SHA and its creator pushes. Written in start-session, `worker.md`, `whole-project.md`, the H3 brief and the golden path.

8. **A worker's start message says which kind of worker it is.** Kind: missing parent, a corollary of 2. A subagent told the rule still pushed until its message said, in words, "You are a subagent: commit, return the SHA, and do not push." Fix: start-session step 7 lists that line among what every worker's start message carries.

**Harness findings.** Actors made six stray calls (`send_message`, `interrupt_session`, `create_session`), all denied by the permission classifier. Run actors where session tools are unavailable or denied. The actor checkout withholds the cases, so a case about running agent tests can't list them; its fixture states what `status` would show.
