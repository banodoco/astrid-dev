# Strategy

Astrid's execution strategy is a ladder of **versions** toward our [vision](vision/README.md), climbed in **releases**. A major version (1.0) states where we are going; the minor versions under it (0.1 to 0.9) each state one aim and the plans that deliver it. Each release document holds the living rationale, intended outcome, approach and included plans; this page is their short, ordered map.

Each plan's own `plan.md` holds its status, owner and estimate, `plans/priority.md` holds the order, and the [plan catalog](plans/index.md) is generated from them. [Vision gaps](vision/README.md) and their routes still define what needs to improve and how success will be assessed. A plan may be worked on before it is assigned to a release; an unassigned plan is not a release commitment.

**Last reviewed:** 2026-11-15, when Hannah set version 0.1's focus (hardening, updates, stability and speed), left version 0.2 open, and asked for this page to be a checked map of versions up to 1.0. Future assignments are provisional until explicitly finalized.

## Versions

Each major version holds every minor version that leads to it, in order and without gaps. A minor version has one sentence saying what it aims to achieve and the plans included in it; one that is not yet decided says `Open`. A plan belongs to one version. CI checks this structure.

### Candidates, not yet in a version

Version 0.2 is open. These are the candidates so far, from Release 13's deferred list, the owner's requests and the plan catalog; none is assigned:

Its small corrections can ship earlier in the standing lane.

- **Finish a video:** generate onto the timeline, agent edits that never overwrite the creator's, export ([Plan 37](plans/37-generate-time-destination/plan.md), [Plan 04](plans/04-concurrent-edits/plan.md), [Plan 18](plans/18-timeline-editing/plan.md), [Plan 27](plans/27-video-render-options/plan.md)). Three of these are goals without tasks; walk one real video end to end before scoping.
- **Rented machines:** speed and the slow first job ([Plan 54](plans/54-warm-latency/plan.md)).
- **Packs extend the database:** a pack adds its own tables and rows, with Astrid's own fields protected, updates accommodated and destructive actions refused; features such as references then become default-installed packs ([Plan 57](plans/57-pack-database-extensions/plan.md), a draft; the owner asked for it on 15 November 2026 as one for after version 0.1).

## Not now

Work beyond a single creator's path is not yet placed in a version: hosted workspaces, the sandbox, Hivemind, agent learning, contribution discovery, the portable workspace and editors beyond video. Open owner decisions for version 0.1: whether rented machines are fully supported or labelled experimental, and whether Pinokio is a supported install route. Rows after Release 14 are provisional: their scope is set from actual usage when each brief is taken up.

Past releases are documented in the [existing release log](plans/releases.md) and actual receipts. Plan 31 migrates that history into canonical release records only where it can be grounded in publication evidence; Release 11's publication race is recorded in the [ledger](docs/ledger/2026-11-09-two-projects-published-release-11.md).

## Keeping this page current

**Versions.** To fill an open version, replace `Open` with one sentence and `None yet` with its plan links; a plan may appear in one version only. When a release is assigned to a version, add it to that version's `Releases` line: every plan the release carries must be one of the version's plans. Keep all nine minor versions under a major version, in order; add the next major version, with its own sentence and nine minor versions, when one is defined.

**Releases.** When a draft release is added or changes its headline or included plans, update the matching sequence row in the same PR. When a release is published, keep its final document immutable and retain its summary in release history. CI checks the version map, the draft's basic structure and consistency with the overview; the Plan 31 release gate separately protects publication. Keep this page short: deeper reasoning belongs in the release document, gap route or plan.
